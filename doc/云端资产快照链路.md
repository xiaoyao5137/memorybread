# 云端资产快照链路

本文记录 MemoryBread 客户端记忆包的云端备份/恢复链路。该链路用于时间线、知识、文档、操作、数据与本地 Skill 等记忆资产，不上传原始采集正文、截图路径、输入文本或音频文本。

## 数据范围

快照包含：

- 时间线：`timelines`
- 知识：`bake_knowledge`
- 文档：`bake_documents`、`bake_document_sections`
- 操作：`bake_sops`
- 数据：`data_sources`、`data_snapshots`、`data_source_links`
- 本地 Skill：`creation_skills`

快照不包含：

- `captures` 原始记录正文
- `ax_text`、`ocr_text`、`input_text`、`audio_text`
- `screenshot_path`、`url`、`webpage_title`、`screenshot_source`
- 配置、隐私规则、动作日志、咨询历史、任务调度、创作历史
- `vector_index`、FTS shadow tables、系统监控与清理日志

个人资料、工作投入、工作心情和标签卡片属于账户数据，不写入记忆包。登录后客户端通过账户接口单独同步这些聚合结果；工作投入同步只包含日期、分钟数、记录数量、应用级汇总，工作心情只包含推断结果，不上传截图、窗口标题或 IM 原文。

`timelines.capture_id` 仍需要外键，因此快照会导出 redacted capture refs。恢复时这些 refs 会写成 `event_type='snapshot_ref'` 且 `is_sensitive=1` 的占位行，只保留 id/时间/应用窗口元数据，不恢复采集正文或截图。

## 客户端本地 API

- `POST /api/snapshots/assets/export`
  - 导出明文记忆包 JSON 到本机备份目录。
  - 返回 `file_sha256`、文件大小与 manifest。
- `POST /api/snapshots/assets/import`
  - 默认 `dry_run=true`，不会写库。
  - 可传 `path`，也可传前端读取出的 `content`。
  - 显式传 `dry_run:false` 时追加/合并导入，不清表。
- `POST /api/snapshots/cloud/backup`
  - 在客户端用 AES-256-GCM 加密记忆包。
  - 调用 admin 上传 URL，PUT 到 OSS，再提交快照元数据。
  - 加密材料由已登录账户的快照服务按对象派生，仅在本次备份请求中临时返回给客户端；用户无需设置或保管恢复密钥。
- `POST /api/snapshots/cloud/restore`
  - 下载 OSS 对象，核对数据库登记的 size/checksum。
  - 已登录客户端临时取得对应快照的解密材料，在本机解密并写出明文快照文件。
  - 默认不导入；传 `import_to_local:true` 后仍默认 dry-run。

## 服务端 API

以下接口均只要求账号已登录；每个账号默认拥有 50MB 云端备份空间：

- `POST /v1/snapshots/upload-url`
  - 校验登录用户与设备归属。
  - 检查 50MB 总配额，生成 scoped OSS object key、临时加密材料和 15 分钟 PUT 签名 URL。
- `POST /v1/snapshots`
  - 上传完成后登记快照元数据。
  - 在用户行锁内再次检查实际密文大小，避免并发上传突破配额。
  - 同一用户同一 `oss_object_key` 重复提交时，如果 size/version/checksum 完全一致，直接返回已有快照。
  - 若元数据不一致，返回 `SNAPSHOT_OBJECT_CONFLICT`。
- `GET /v1/snapshots`
  - 返回快照版本、对象 key、checksum 与提交状态，用于核对 RDS 元数据。
- `GET /v1/snapshots/:snapshot_id/download-url`
  - 返回 10 分钟 GET 签名 URL、临时解密材料和登记的 size/checksum，并写入恢复请求流水。

官网个人控制台的“云存储”页展示已用/50MB 总额度、备份列表，以及最近 100 条备份与恢复流水。

## 重复判断

本地导入：

- 记忆资产表按主键 `INSERT OR IGNORE`，同一快照重复导入不会重复插入。
- 数据源按 `canonical_key` 合并，并将快照、来源关系的 `source_id` 重映射到本机真实 ID；因此目标数据库已经占用相同数值主键时，不会静默丢失导入数据。
- 数据快照按重映射后的 `source_id` 更新，来源关系按 `source_ref_key` 合并；备份记录旧于本机现有记录时保持本机新值，不用旧快照倒灌覆盖。
- `capture_refs` 使用 capture id 去重，不覆盖真实 capture。

云端登记：

- OSS object key 由服务端按用户、设备和 UUIDv7 生成。
- `snapshots(user_id, oss_object_key)` 有唯一索引。
- 完成登记先查已有对象；一致则幂等返回，不再重复写 outbox。
