# 脑暴从问题推进到方案与落地

2026-09-08。

## 问题与原因

原实现把背景维度覆盖作为主要收敛条件。Core 只强制展开选中至少两个选项的回答或继续方向，并使用广度优先顺序；一个选项有过一道子题即视为已展开。单选、自定义答案和子题回答容易回到横向换题，不能保证已发现的问题进入解决方案讨论。

Sidecar 在用户已经选定方向后若收到模型 `ready`，还会把继续方向列表包装为“接下来深入哪个方向”的问题，形成没有实际深入的循环。界面同时只对多选叶标记待展开，且遗漏没有 `parent_option_id` 的自定义后续节点。

## 最终行为

- 新题保留讨论阶段：明确问题/方向、探索解法、细化落地、验证效果。Core 沿用户已选路径深度优先推进，单选、多选、自定义都可继续；验证方式讨论结束后回到其他分支，避免无限分叉所有执行细节。
- 方案候选由模型主动给出具体做法和收益/代价；落地承接已选方案，验证承接执行安排。用户选择候选项即可继续，自定义提示不要求用户自己补方案。阶段不代替内容质量，不声称已执行或验证通过。
- 分支有指定阶段时禁止提前 `ready`、错误阶段和纯泛化选项，使用现有有界重试与总截止时间纠正。全局背景覆盖不再压过当前分支；指定阶段仍允许按用户权限检索和校验证据，但不做无关的全局背景继承核对。
- 父子关系由 Core 维护，深层上下文保留祖先的有效用户选择；明确排除与跳过不自动扩展。用户仍可随时结束、换方向和回改答案。旧题缺少阶段时按问题/方向处理，不重写已保存答案。
- 子题记录生成时的父答案版本，人工重改父摘要后，旧后代和迟到回答不能影响有效简报或模型输入；下一次成功推进时归档供回看。自定义继续方向也经过同一分支调度。
- 思路树展示自然中文阶段、单选与自定义分支；讨论了验证方式的叶节点显示“已讨论”。深树节点保持可读宽度，滚动限制在树容器内，避免窄卡片把文字挤成竖列。

契约见 [`shared/creation-brainstorm/README.md`](../shared/creation-brainstorm/README.md)。实现涉及 Sidecar 协调器与请求模型、Core 脑暴状态机、前端思路树和摘要，不需要数据库列迁移。

## 当前验证边界

这次证明的是分支调度和生成行为能从问题进入方案、执行方式与验证，不是证明模型提出的技术路线已经实施成功。真实候选仍有质量限制：一项“无需额外付费”没有当前输入依据，另一个执行候选转回提示词优化，未持续细化原选解法。提示已要求条件化表述与承接当前路径，但不能仅凭阶段标签声称所有候选成本、能力和可行性都已核实。这两项已在私有真实验收报告中记录。

已通过项目启动锁与受管函数加载 Core / Creation Service，核对实际新进程、请求阶段字段和服务健康；UI 使用当前源码。原会话 state、完整历史记录与会话行均保持一致：revision=5，4 轮已保存回答，正文仍为空。未自动选择继续方向或为用户生成正文。

原用户会话的完整快照及哈希、真实输入输出、模型阶段日志、回归日志保存在本机 `/tmp/brainstorm-depth-20260908/`。原需求、来源正文和模型原始输出不写入本说明。真实回放与合成选择只在独立进程中进行，不向用户原会话提交答案或生成正文。
