# 知识与数据记忆门槛提升方案

- 状态：已完成首期实现与近期样本回放
- 更新日期：2026-08-21
- 决策阶段：change approval
- 适用范围：MemoryBread 本地自动提炼的“知识”和“数据”资产

## 1. 结论

不建议只调高一个统一的模型分数阈值。应把当前“候选通过后直接成为资产”改成四段式链路：

1. **事实保全**：原始 capture、timeline、逐字证据和系统观测时间继续保留，不因资产门槛提高而删除。
2. **类型路由**：先判断内容应进入知识、数据、文档、操作，还是只保留在时间线；禁止同一价值点同时生成知识和数据。
3. **分层晋级**：候选分为 `published`、`shadow`、`timeline_only` 三态。只有高质量候选进入用户可见资产；边界候选进入本地影子池等待复现、补证或用户确认。
4. **稳定身份合并**：数据按“规范来源范围 + 开放语义关系 + 业务对象 + 上下文 + 时间语义”合并；知识按“对象 + 谓词/结论 + 时间语义”去重，避免一次浏览产生多条流水账资产。

建议知识自动发布阈值先设为 `0.78`，`0.62–0.77` 进入影子池；数据不使用同一套“重要性分数”，而采用“开放语义事实门槛 + 不确定候选影子保全 + 稳定身份合并”。生产判定不得依赖预先列全的保护类型、噪声类型、指标允许列表或事实类型枚举；文中的具体类型和案例只用于解释与回放测试，不构成穷举规则。

## 2. 问题与证据

### 2.1 当前知识门槛事实上未生效

候选预筛只要 importance 较高、用户验证、历史查看，或具备中高证据并命中特定活动/来源即可进入提炼。更关键的是，落库阶段的 `resolve_review_status` 当前忽略 `review_status`、`match_score` 和 `match_level`，固定返回 `auto_created`。Sidecar 即使把类型错配候选降到 `0.49 / low`，仍标成 `auto_created`。因此当前模型分数只被记录，没有成为发布门槛。

近期知识样本中出现了三类典型低价值资产：

- “用户查看/查询/复制了某页面”的活动流水账；
- 浏览器 JavaScript 提示、页面未加载等瞬时界面状态，被扩写成长期知识；
- 资产配置、成本、IP、CPU 等结构化事实同时进入知识和数据，形成跨类型重复。

### 2.2 当前数据更大的问题是“噪声行 + 来源碎片化”

数据侧已经要求对象、指标、数值和逐字证据，这是正确的可靠性底线。但现有校验允许“对象、场景、指标任一锚点命中证据”后继续降级修补，模型的 `high` confidence 也没有业务语义约束。结果是：数值真实存在，但可能只是待办数、已选数、消息时间戳、在线编辑人数等界面噪声。

同时，当前稳定身份仍容易被时间线切分影响。近期 60 条数据源全部只关联一个 timeline，平均每条关联 4.45 个 capture；其中 24 条来自同一规范文档 URL 且标题完全相同，却被拆成 24 个来源。

### 2.3 提高门槛时不能牺牲的内容

不能用有限枚举定义“重要事实”。只要一段信息同时满足以下开放语义条件，即使只出现一次、模型主观分数不高，也必须至少进入影子池：

1. 能形成一个可独立回答的未来事实问题，而不只是描述用户做过什么操作；
2. 丢失这段信息会让后续决策、执行、验证、追责或事实核对缺少不可替代的依据；
3. 对象、关系或属性、时态/适用范围和证据足以让系统在不补写、不猜测的情况下复述；
4. 当前没有另一条语义等价、证据质量不低于它的正式资产。

决策、状态、成本、配置、标识符、目标值等只是可能满足上述条件的示例，不是保护枚举。相反，某个看似普通的编号、时间或文本值，如果是恢复具体工作结果所不可替代的依据，也可能需要保留。

## 3. 用户与场景（Users and scenarios）

- **日常使用者**：希望“知识”和“数据”页只展示未来值得找回的资产，同时仍能从时间线追溯未晋级内容。
- **咨询/创作使用者**：需要精确事实、决策和约束能够被可靠召回，且目标值、阈值和实测值不会混淆。
- **本地质量维护者**：需要只在本机查看候选、证据、规则版本与原因码，回放新规则并安全回滚。

核心场景包括：从会议或聊天保留一次出现的关键决策；从报表保留成本与容量但过滤界面计数；把同一文档多次浏览聚合为一个数据源；把边界候选暂存在影子池并在补证后晋级。

## 4. 目标与非目标

### 3.1 目标

- G-001：知识有用率达到 AC-010 的 85% 以上，并降低活动流水账、界面瞬态和跨类型重复。
- G-002：不能形成可复用领域关系的偶发值进入数据正式视图的比例降至 AC-010 的 1% 以下，顶层重复率降至 5% 以下。
- G-003：对满足 2.3 开放语义条件的 grounded fact 达到 100% 保全；“未发布为资产”不等于“删除证据”。
- G-004：所有门槛决策可回放、可解释、可灰度、可回滚。

### 3.2 非目标

- 不删除原始 capture 或 timeline。
- 不在本方案中自动清理历史知识/数据；历史治理应先影子标注，再单独审批迁移。
- 不以“出现次数多”作为事实真假的判断。
- 不把供应商模型信息或私有内容写入外部遥测。

## 5. 功能需求（Requirements）：统一状态模型

每个候选先进入本地审计记录，得到以下状态之一：

| 状态 | 用户可见 | 用途 | 后续动作 |
| --- | --- | --- | --- |
| `published` | 是 | 高质量正式资产 | 正常检索、创作与刷新 |
| `shadow` | 否 | 可能重要但证据、语义或去重尚不足 | 30 天内等待复现、补证、关联任务或用户确认 |
| `timeline_only` | 否 | 活动轨迹、界面瞬态或无复用价值 | 仍可通过时间线与原始检索找回 |
| `rejected_invalid` | 否 | 无法回证、字段矛盾或明显幻觉 | 保留审计原因，不生成结构化资产 |

影子记录只保存本地结构化候选、证据引用 ID、规则版本与原因码；不复制无关正文，不上传服务端。

## 6. 功能需求：知识门槛

### 5.1 硬门槛

- **FR-001** — 知识候选必须表达至少一个可独立复述的“对象 + 谓词 + 状态/结论/约束”，并关联可回查的来源证据；“用户查看了/尝试了/点击了/复制了”本身不构成知识。
- **FR-002** — 系统必须先执行类型路由。若主要价值是“对象 + 指标 + 数值/配置”，则只进入数据；若主要价值是完整正文或步骤，则分别进入文档或操作。
- **FR-003** — 瞬时 UI 状态只有在明确造成持续业务影响、形成可复用排障结论，或被重复观测后，才可成为知识。单次 JavaScript 提示、加载失败、空输入警告默认 `timeline_only`。
- **FR-004** — 多主题活动汇总必须拆成独立事实；无法拆出具体对象和结论时不得发布知识。
- **FR-005** — 模型生成的事件时间必须逐字回证；否则只使用系统 `observed_at`，不得在详情中生成来源没有明确写出的日期。

### 5.2 评分与事实保全通道

通过硬门槛后计算 `knowledge_quality_score`：

| 维度 | 权重 | 评分要点 |
| --- | ---: | --- |
| 未来复用价值 | 0.30 | 能否支持后续决策、执行、排障或避免重复确认 |
| 对象与结论具体性 | 0.25 | 对象、状态、原因、约束是否明确 |
| 证据与归因 | 0.20 | 来源、说话人/系统状态、时间语义是否可回查 |
| 持久性 | 0.15 | 是否超越一次点击或短暂 UI 状态 |
| 新颖性 | 0.10 | 是否补充或更新现有知识，而非同义重复 |

- **FR-006** — 分数 `>= 0.78` 才可自动发布；`0.62–0.77` 进入影子池；`< 0.62` 保留为时间线。
- **FR-007** — `match_score` 或 `match_level=low` 不得被解析为 `auto_created`；Core Engine 必须成为最终确定性门禁，不能只信任 Sidecar 输出的状态字符串。
- **FR-008** — 候选未达到发布阈值、但满足 2.3 的开放语义条件时，系统必须进入 `shadow`，不得通过某个有限类型列表决定保留或丢弃，也不得使用更低的“特殊类型发布阈值”绕过统一发布门槛。
- **FR-009** — 用户手动确认、编辑、收藏或在创作中实际引用的影子候选必须可晋级；用户明确忽略的候选不得自动恢复。

### 5.3 知识原因码

门槛结果必须记录机器可读 `reason_code` 和人可读 `reason_summary`。`reason_code` 是允许后续新增值的命名空间字符串，读取方必须接受未知值；不得把一组固定原因码当作判定分支的完整枚举。`ACTIVITY_ONLY`、`ROUTE_TO_DATA`、`TIME_UNGROUNDED` 等只作为首批观测示例。

## 7. 功能需求：数据门槛

### 6.1 行级事实门槛

- **FR-010** — 每个数据事实必须能独立回答“什么业务对象，在什么事实类型/维度/时期下，什么指标或属性，值是什么”。对象、值和关键维度必须在同一段连续证据中回查。
- **FR-011** — 数据事实必须保留来源表达的事实语气、时态和适用范围，使读者能区分“已经观测到的值”与“被要求、预计、假设或计划的值”；可以使用开放文本或结构化关系表示，但不得依赖一组封闭 `fact_kind` 枚举决定是否保留。
- **FR-012** — 一个值只有在其语义角色是某个明确对象的可复用属性、度量或关系时，才可发布为数据；如果该值只是在描述一次界面状态、交互位置或活动顺序，且脱离当次操作后不能回答具体领域问题，则不得发布为数据。实现不得依赖待办数、时间戳等词面黑名单，也不得依赖领域指标允许列表。
- **FR-013** — 只要候选满足 FR-010、其语义关系可回证、且没有等价正式资产，系统不得因低频、低主观重要性或值的形态不在预设列表中而丢弃；仍无法确定语义角色时进入 `shadow`。
- **FR-014** — 校验必须按行执行。一个来源中出现不满足 FR-012 的值时，只处理对应行，不得连带丢弃同批满足事实门槛的行。
- **FR-015** — `confidence=high` 只能作为模型自报信息，不能绕过确定性事实门槛。

### 6.2 数据身份与合并

- **FR-016** — `report_url` / 文档来源的稳定范围使用去 fragment、去非语义 query 后的规范 URL；同一文档不同 section 不得天然生成不同数据源。
- **FR-017** — 数据行的语义身份必须由规范来源范围、对象、关系/属性、适用上下文和时间语义共同生成；字段取值允许扩展，不得把事实类型写成封闭枚举。同一自然周内同一语义身份的新值更新同一快照，跨周保留阶段历史。
- **FR-018** — 同一规范来源下的多个指标应聚合为一个可浏览的数据集，数据行保持各自证据与来源 timeline；不得为每个时间线片段创建一个顶层数据源。
- **FR-019** — 无稳定 URL 的聊天/桌面来源仍按明确对象与指标隔离，禁止把不同话题仅因值或泛化标题相似而合并。

### 6.3 数据原因码

数据原因同样使用允许新增值的 `reason_code + reason_summary`，未知原因必须可存储、展示和统计。`INCIDENTAL_VALUE`、`MISSING_RELATION`、`UNGROUNDED_VALUE`、`MERGED_STABLE_SCOPE` 等只作为示例，不能反向成为封闭分类器。

## 8. 功能需求：重要事实不丢失机制

- **FR-020** — 任何资产门槛失败不得删除或改写原始 timeline/capture；审计记录必须保留来源 ID、规则版本、候选类型和原因码。
- **FR-021** — 影子候选出现新的语义证据、使用证据或用户反馈时必须重新评估；触发条件由“是否补足发布判断所缺信息”决定，不由一组固定事件枚举决定。
- **FR-022** — 任何已逐字回证、能形成独立事实问题、但分类或价值判断仍不确定的候选必须进入 `shadow`，而不是静默丢弃；后台可在空闲时补提炼一次。
- **FR-023** — 删除或降级历史资产前必须先验证其来源仍可回查；没有来源证据的历史资产只允许标记待审，不得批量硬删除。

## 9. 近期样本离线回放

### 8.1 样本与方法

本次只读抽取截至 2026-08-21 02:41 的最近 60 条知识，以及按创建时间倒序的最近 60 条有效数据源。首期实现完成后再次以只读方式确认样本集合和代表案例仍存在；历史记录没有新契约字段，因此分类数量沿用同一批人工语义标注，代码边界另由自动化测试验证，不把回放结果写回用户数据库。

知识样本按以下顺序判定：独立事实问题 → 类型路由 → 证据与不可替代性 → 统一评分分层。数据样本逐行判断“该值在语境中承担可复用领域关系，还是只描述当次界面/活动”，再按规范 URL 和稳定标题做保守合并模拟。回放没有使用类型允许列表、词面黑名单或特殊保护阈值。

### 8.4 回放结论

近期样本支持“分类型门槛”而非“统一提高 importance”：

- 知识问题主要是发布门槛未执行和类型路由不足；
- 数据问题主要是 UI 数字没有业务语义门禁，以及同一来源被时间线切碎；
- 事实不应依赖模型的主观重要性或有限保护枚举，而应由独立事实问题、逐字证据、不可替代性和影子池共同保证召回。

## 10. 可观测性

- **OBS-001** — 本地按规则版本统计每类候选的 `published/shadow/timeline_only/rejected_invalid` 数量和原因码分布，不记录正文。
- **OBS-002** — 分别统计知识发布率、路由到数据率、影子晋级率、用户忽略率、重复合并率。
- **OBS-003** — 数据统计候选行数、有效行数、语义不成立数、不确定候选数、稳定范围合并数和跨周快照数；原因维度必须支持新增未知值。
- **OBS-004** — 抽样面板必须能从资产追溯到证据 ID、规则版本和每一条门槛结果；敏感正文只在本机查看。

## 11. 验收标准与追踪

- **AC-001** — 给定 `match_score=0.49`、`match_level=low` 的知识候选，执行发布决策后不得成为 `published`。覆盖 FR-006、FR-007。
- **AC-002** — 给定只描述“查看、查询、复制成功”的候选，且没有独立结论，结果必须是 `timeline_only/ACTIVITY_ONLY`。覆盖 FR-001。
- **AC-003** — 给定一次性页面 JS 提示，结果必须是 `timeline_only/TRANSIENT_UI`；给定同一提示造成明确持续业务阻塞且有排障结论时，允许进入 `shadow` 或发布。覆盖 FR-003。
- **AC-004** — 给定任意未预先定义类型的候选，只要它能形成独立事实问题、对未来任务不可替代、证据完整且没有等价资产，即使只出现一次也必须至少进入 `shadow`；删除所有类型特定保护分支后结果仍一致。覆盖 FR-008、FR-020、FR-022。
- **AC-005** — 给定若干值形态不同、领域不同的完整事实，以及词面相似但缺少语义关系的反例，系统必须基于对象—关系—值—证据判断，不得基于类型允许列表或值格式决定保留。覆盖 FR-010、FR-013。
- **AC-006** — 给定同一来源中一个可独立回答领域问题的值和两个只描述当次界面状态的值，系统必须逐行保留前者、将后两者移出数据正式视图；替换具体界面词后结果应保持一致。覆盖 FR-012、FR-014。
- **AC-007** — 给定来源分别表达“已观测、被要求、预计、假设”的多个值，保存和检索结果必须保留原语气与适用范围，不得把非观测值写成实测；加入一种实现未见过的新语气后仍可保存到影子池或正确展示。覆盖 FR-011。
- **AC-008** — 给定同一规范文档 URL 的 20 个时间线片段和不同 section fragment，系统只创建一个顶层数据源，同时保留全部合法指标行和来源 timeline。覆盖 FR-016、FR-017、FR-018。
- **AC-009** — 给定门槛失败候选，原始 timeline/capture 仍可按来源 ID 读回，审计记录包含规则版本和原因码。覆盖 FR-020。
- **AC-010** — 在人工标注的 grounded fact 集上，满足 2.3 条件的事实保全率必须为 100%；知识有用率不低于 85%，数据事实准确率不低于 95%，顶层重复率不高于 5%，非领域偶发值进入数据正式视图的比例不高于 1%。覆盖 FR-001–FR-023。
- **AC-011** — 给定以数值指标为主要价值的候选，系统只路由到数据；给定包含三个互不相关活动但没有独立结论的汇总，系统不得发布知识。覆盖 FR-002、FR-004。
- **AC-012** — 给定模型生成但来源未明确写出的事件日期，详情只展示系统观测时间；给定来源逐字写明的事件日期，允许保存为事件时间。覆盖 FR-005。
- **AC-013** — 给定影子候选，用户确认、编辑、收藏或在创作中实际引用后应重新评估并可晋级；用户明确忽略后不得自动恢复。覆盖 FR-009、FR-021。
- **AC-014** — 给定 `confidence=high`、逐字数值真实存在，但该值不能建立可复用对象关系的数据候选，结果不得发布；修改候选词面但保持相同语义角色后结果应一致。覆盖 FR-015。
- **AC-015** — 给定无稳定 URL 的两个不同聊天话题，即使标题或数值相似也不得合并；同一对象指标再次观测时允许触发影子重评。覆盖 FR-019、FR-021。

## 12. 发布与回滚

- **ROLL-001** — 第一阶段只运行影子判定，不改变现有用户可见资产；连续回放至少 7 天，完成人工 grounded fact 漏失审查，并专门加入训练/开发样本未出现过的新类型。
- **ROLL-002** — 第二阶段只对新知识启用三态发布，对新数据启用 FR-010–FR-014 的开放语义行门禁；旧资产不动。
- **ROLL-003** — 第三阶段启用稳定来源合并。先生成合并预览和 ID 映射，不删除旧来源；检索层读新身份，旧 ID 保持可解析。
- **ROLL-004** — 第四阶段才评估历史资产降级。只做软状态变更，保留来源与恢复映射。
- **ROLL-005** — 任一阶段若满足 2.3 条件的事实保全率低于 100%、用户确认资产被降级，或错误合并率超过 1%，立即关闭新门槛开关并恢复旧读取路径。

## 13. 风险与待决策

- **风险：重要但低频或新类型的事实被模型低估。** 通过开放语义保全条件、影子池和原始证据保全规避，不维护保护类型列表。
- **风险：模型把示例当成枚举边界。** 提示词和测试必须明确“示例非穷举”，并使用同义改写、陌生领域和新值形态做变形测试。
- **风险：规范 URL 合并过度。** 只去 fragment 和明确非语义 query；不同业务对象仍按 subject/metric/dimension 分行，不跨无 URL 聊天合并。
- **风险：规则变多后难以解释。** 原因码、规则版本和本地回放必须成为发布条件。
- **待决策 D-001**：影子池保留 30 天还是 90 天；建议先 30 天，满足 2.3 条件但仍待补证的 grounded fact 不自动过期。
- **待决策 D-002**：影子候选重新评分时是否复用原模型，还是使用独立判定提示；建议使用独立判定提示，避免同一盲点重复出现。
- **待决策 D-003**：历史数据源合并是否在本期实施；建议本期只处理新数据，历史仅生成预览。
