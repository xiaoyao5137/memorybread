# 脑暴启动失败：根因修复与验收

日期：2026-09-08。

## 原始现场

最新创作记录为 `creation_history.id=147`，会话 `creation-1788800464979-35478c74aa0268`，创建时间 01:01:42，创作模式为脑暴。用户需求是快手灵机面向非 L0 商家的增长方案。故障时正文为空，尚未创建 `creation_brainstorm_sessions` 状态，页面提示「脑暴启动失败，请重试」。

原始 `creation.log` 的调用栈为：`next_step → _assess_memory → _complete → _stream_direct_completion → _stream_qwen35_raw → require_complete_generation`，抛出 `CREATION_DOCUMENT_TRUNCATED`，`POST /creation/brainstorm/next` 返回 503。错误发生在历史决定核对，尚未生成首题。

## 根因

1. 历史决定核对仅有 1200 个输出 token。通用传输层正确拒绝长度截断，但脑暴协调器只重试 JSON/质量校验异常，未接住截断的 `OperationError`。可选的记忆核对因此变成启动的致命依赖。首题生成也有相同异常漏接。
2. 核对只要求普通 JSON，没有约束字段和本轮维度、来源枚举。模型抄录大量资料或输出不合契约时，恢复成本高。已有非思考模板实际已开启，不把本故障归因于思考模式。
3. Core 将所有非成功返回压成通用脑暴错误，且记录原始上游响应；页面无法展示真实失败类别。
4. 传输层单次允许等待 300 秒，Core 整请求只等待 180 秒；新增重试若没有共享截止时间，会形成超时后后台仍继续生成的问题。

## 修复

- 用专属 `BrainstormOutputTruncated` 接住长度截断。截断候选整份丢弃，即使收到的前缀已经能解析为 JSON，也不能提交或与下一次拼接；其他操作错误继续原样传播。
- 记忆核对最多两次，问题生成最多三次，仅长度耗尽时增加预算，总上限为 4800。记忆字段和维度/来源枚举由紧凑 schema 约束；引用长度、数量和逐字原文继续后置校验。限制复述，只核对已确定维度的最短充分原文。
- 记忆核对共享 40 秒。核对耗尽后继续提问，所有未经核对的维度仍待确认；保留已召回资料作为参考，明确显示「历史决定未能可靠核对」。不会伪造沿用的历史结论。
- API 自入队起共享 150 秒。排队超时撤销未运行任务；执行中的任务只能使用剩余时间，超时取消模型流。Core 保持 180 秒上限，返回稳定的超时类别。
- Core 白名单映射截断、格式无效、权限、繁忙、不可用与超时；使用固定中文原因，日志仅保留安全类别。前端无需放宽敏感内容过滤。失败不改变已保存的问题、答案和版本。
