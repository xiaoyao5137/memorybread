# 文档正文采集与提炼质量优化方案

状态：2026-09-11 原始方案基线，保留原需求及当时的排查结论。用户随后已授权实施修复；当前处于整体验收阶段，最新完成情况见 [验收清单](document-source-quality-acceptance-2026-09-12.md)，实施证据见 [实施记录](document-source-quality-implementation-2026-09-12.md)。以下“本次只读排查”“当前”等表述指方案形成时的状态，不代表实时状态。

## 问题与证据

用户发现文档 953 的内容与来源 URL 中的业务文档不符，主要是页面外围文字。受影响的是浏览文档、检索记忆及基于来源创作的用户；他们当前只能打开原文自行核对，难以信任“文档”这一产物。

本次只读排查确认：

- 953 的 full_content 是 74782、74783、74784、74785、74786、74788、74790 共 7 条早期采集的拼接，包含未命名文档、知识库目录、编辑器工具栏和空内容提示。
- 关联 48 条采集记录，均无 OCR 文本，43 条 AX 文本含脱敏占位符。部分业务内容在标题后终止。
- 证据说明匹配 deterministic_document_recovery 的“由已采集的文档标题与可见正文恢复，未生成额外内容”。该逻辑直接使用聚合文本或 AX/OCR 文字。
- 无来源快照，刷新状态 historical_only，完整性 unverified。增加关联采集不代表当前正文已更新。
- 当前入库已有 document_evidence 和 is_document_shell；前者依赖正文字符数及后者的启发式判断。现有空壳检测主要组合导航、控件和句子长度，不能证明正文区域已取得。
- 当前隐私过滤将部分配置转为关键词查找，collect_keyword_value_range 可在无冒号时匹配“账号”，并吞到换行结束。扁平 AX 文本无换行时存在大段误过滤风险。该缺陷是否解释 953 的每次截断尚未实证。

边界：原 URL 当前全文未成功读取，不能判定本地内容与当前全文的差异比例；仅凭 JavaScript 提示不能认定页面未加载，因为隐藏提示也可能进入采集。

实现依据：core-engine/src/services/bake_service.rs、core-engine/src/services/document_refresh.rs、core-engine/src/capture/content_filter.rs、ai-sidecar/embedding/document_quality.py、core-engine/src/storage/migrations/101_bake_document_source_snapshots.sql。

## 目标与非目标

目标：每份文档的正文来自可定位的内容区域，完整性有证据；部分正文仍可使用但必须限定范围；采集失败明确可见，旧的可靠内容得到保护；相同规则用于提炼、索引、咨询和创作。

非目标：本方案不实施代码或生产数据修复，不批量重新请求所有 URL，不绕过登录或隐私设置，不让模型补写缺失原文，不默认打包 DMG。

## 用户场景与方案选择

用户浏览在线文档时系统被动采集；有正文后生成可用记忆；用户详情页查看完整性并按需重新获取原文；检索与创作只使用满足用途的来源；维护者可审计并恢复历史错误记录。

| 方向 | 收益 | 局限 | 选择 |
| --- | --- | --- | --- |
| 仅修改提炼提示词 | 改动小 | 模型无法恢复没有取得的正文 | 不作为根治方案 |
| 对每次采集都整页抓取 | 有机会补齐原文 | 频繁请求、登录失败、打扰用户，仍可能误抓外壳 | 不采用 |
| 结构化采集、共享质量契约、按需补全 | 从输入到引用保持同一证据约束 | 涉及采集、存储和消费方协调 | 推荐 |

## 核心设计与契约

复用已有文档身份、来源快照、刷新策略和质量模块。新增一份版本化共享质量契约与跨语言夹具，扩展已有数据模型，避免另外建立同义的刷新系统。以下字段为拟议语义，最终命名随契约评审确定。

### 分开表达四类状态

| 维度 | 拟议值 | 含义 |
| --- | --- | --- |
| 正文质量 body_quality | unknown / shell / substantive | 是否取得实质内容，不表达全文覆盖 |
| 覆盖 coverage | unverified / partial / complete | 是否取得整篇原文，与更新时间独立 |
| 采集任务 collection_state | observed / queued / collecting / retry_wait / blocked / succeeded | 调度状态，不能当作内容质量 |
| 提炼产物 artifact_state | pending / ready / stale / quarantined | 提炼版本是否可用及是否需要重建 |

沿用 existing refresh_status 表达新鲜度，沿用 completeness_status 承载覆盖语义；不得将新的 coverage 与已有字段作为两个可独立修改的事实源。登录失效时，任务 blocked，但上次完整快照仍是 complete，只是新鲜度下降。

正文质量评估基于去除非正文后的内容，不能依据整页字数或单一总分放行。正文块可以是段落、表格、代码、列表、图注；短文可以完整，长页面也可能只有导航。

### 来源与版本

每份候选快照记录 document_id、实际来源身份、采集方式、采集时间、正文块引用、内容哈希、质量规则版本、提取器版本、覆盖证据和脱敏统计。模型产物必须记录准确的 source_snapshot_id 及生成规则版本。

正文块保留类型、原有顺序、可用的稳定块标识、来源定位和脱敏后文本。不得为了诊断增加未脱敏原文持久化；原始页面只在内存处理，既有采集历史继续遵守现行隐私策略。

身份校验使用稳定文档标识和重定向结果；不能只按标题合并，也不能盲目去除所有 query、降低大小写而合并实际不同的资源。复用现有 document_identity 时先补充身份碰撞回归，必要时版本化迁移并保留旧 ID 别名。

### 正文获取顺序

1. 优先使用已授权且可用的结构化文档正文接口或页面内容模型；没有这种能力时继续下一步。
2. 通用 DOM 正文定位结合 main/article、编辑器语义、块结构；明确排除导航、工具栏、评论、隐藏提示。站点适配器只提供正文根节点、虚拟滚动策略和身份规则，不包含业务关键词。
3. 语义 AX 正文子树保留块边界，不将整页扁平文本直接充当完整正文。
4. 允许截图时，OCR 补充可见正文区域；无截图、权限不足或仅覆盖一屏时必须保留限制，不自动判为全文。

正常被动观察不主动翻页或抢焦点。补全优先后台受控会话；需要操作用户当前页面时由显式“重新获取原文”触发，并恢复滚动位置。

页面就绪需要身份匹配、正文根存在、正文块出现及变化趋稳。complete 还需要正文内容源或滚动遍历的覆盖证据、无未解析懒加载内容、无截断；“滚到底”和“两次不变化”单独都不够。虚拟列表须累计跨屏块并验证重叠衔接；无法证明覆盖时保持 partial。

### 隐私过滤

区分“普通关键词敏感片段”和“凭据字段值”。凭据字段要求字段语义及分隔符或结构化 label/value 关系，“商家账号运营”不得匹配为凭据。值范围按字段/文本块、类型及配置上限约束；非结构化长值无法确定结束位置时标记不确定，不把可疑敏感内容交给模型。

过滤前后保持块边界，输出规则 ID、命中类型、删除字符数和比例，禁止在日志中输出匹配原文。大量过滤时继续保护隐私，但将正文标记 partial 或 unusable，不能把剩余侧栏发布为文档。高过滤比例仅为诊断信号，不能单独断言误过滤。

### 更新及消费

同一来源的新快照先独立评估，再切换当前来源指针。新的 partial 不能覆盖已有完整正文；它可记录为“发现更新但覆盖不足”。较短的新 complete 可能是作者删除内容，允许在身份和覆盖验证通过后替换，不用字数单调增长判断质量。

部分快照合并仅限有同一修订版本或可靠块连续性证据的片段；否则保持独立快照，避免把不同日期互相冲突的正文拼成一篇。完整新版本按版本替换，历史用于追溯。

摘要及标签从合格正文生成，原文和提炼结果分开显示。确定性恢复仅能复制已通过质量判定的正文块，不能直接复制原始聚合 capture。无实质正文只保留待采集来源，不发布正式文档。

共享判定用于全文、向量、混合检索、咨询和创作：shell/quarantined 不得通过旧向量或历史 URL 别名重新进入证据；partial 只允许支持已取得块，并显示“仅获取部分正文”，不能回答全文完整性或未读取章节的问题。

## 功能需求

- FR-001 — 采集器必须把正文块与导航、控件、评论及加载提示分开输出。
- FR-002 — 质量判定必须分别输出实质性和覆盖证据，不得以页面长度或静止状态单独判定完整。
- FR-003 — 隐私过滤必须限定凭据值边界，并保留可审计的脱敏统计。
- FR-004 — 入库必须拒绝将空壳或缺失正文作为可用文档，包括确定性恢复路径。
- FR-005 — 文档更新必须通过版本化快照原子切换，保护可靠旧版本，禁止无依据跨版本拼接。
- FR-006 — 补全任务必须按来源身份去重，并在浏览器不可用、登录不足或重试耗尽时给出明确状态。
- FR-007 — 详情页必须展示正文覆盖、采集时间、失败原因及重新获取入口，并将原文与摘要分开展示。
- FR-008 — 检索、咨询和创作必须遵守统一的来源可用范围判定。
- FR-009 — 历史修复必须保留原 ID、原采集和引用历史，并提供修复前版本的恢复能力。
- FR-010 — 提炼产物必须绑定本次实际使用的快照，来源切换后标记旧产物及其索引过期。

## 调度、异常与兼容要求

首次已有正文但覆盖不足、实质正文变化、显式重新获取原文可触发补全。首次补全不受“已完整来源”的常规 TTL 限制；refresh_policy=never 继续阻止自动补全。显式重新获取只创建一次任务，不隐式修改用户长期策略。

拟议默认预算：同一来源至多 1 个任务，后台全局并发 1，单次最多 60 秒、最多 20 次滚动步骤，触达任一预算即停止并保存部分覆盖。短暂错误最多额外重试 2 次，建议间隔 30 秒、2 分钟；值均可配置，需真实采样后定稿。前台交互推理优先，后台 OCR/提炼复用已有队列抢占能力。

| 错误或结果 | 行为 |
| --- | --- |
| BODY_NOT_READY | 有预算则等待或延迟重试，耗尽后保留待采集 |
| BODY_NOT_FOUND / COVERAGE_UNVERIFIED | 保存诊断或部分正文，不生成完整文档 |
| IDENTITY_MISMATCH | 禁止合并或索引该候选，不将重定向登录页判为原文 |
| AUTH_REQUIRED / PERMISSION_DENIED | 阻塞到用户恢复访问或显式重试，不循环请求 |
| BROWSER_UNAVAILABLE | 等待能力恢复或用户重试，不阻塞提炼队列 |
| REDACTION_DOMINATES | 保留过滤、降低可用性，不关闭隐私规则 |
| TIMEOUT / RESOURCE_BUDGET_EXCEEDED | 保存已取得的有效片段，按预算结束 |
| PAGE_GONE | 仅有明确文档删除证据时确认；临时网络失败不得推断删除 |

- NFR-001 — 客户端 Python 必须兼容 Python 3.9；Rust/Python 使用同一质量夹具验证行为一致。
- NFR-002 — 日志不得包含正文、凭据或完整敏感 URL；诊断只记录内部标识、规则与统计。
- NFR-003 — 后台采集必须可取消，并遵守上述可配置资源预算及现有隐私授权。
- NFR-004 — API 采用可选字段增量兼容；缺失质量证据默认为 unknown/unverified，不能提升为完整。

先发布共享契约和错误码，再发布 Rust 存储与兼容接口、Python 消费、前端、文档。保留旧字段读兼容；旧客户端不能理解质量状态时，服务端仍须阻止不合格正文进入其可用文档与检索响应。

## 可观察性与衡量

- OBS-001 — 每次评估记录 capture/snapshot/document ID、规则版本、实质块数、正文字符数、排除块数、脱敏比例、覆盖证据及拒绝原因，不写正文。
- OBS-002 — 记录任务排队/执行耗时、重试次数、成功/部分/阻塞比例、受预算限制比例与每来源重复任务数。
- OBS-003 — 记录来源版本、摘要版本和索引版本不一致次数；消费路径发现不一致时拒绝作为当前版本返回。

首阶段目标：验收夹具中空壳误入库为零、凭据泄漏为零、合法短文等负向回归误拒为零；953 通过真实原文核对才算个案修复。真实总体误拒率与耗时尚无基线，先影子采样，不虚设已达成的数值。人工抽样标注用于评估，不上传私有正文。

## 发布、历史迁移与回滚

- ROLL-001 — 第一阶段补齐共享质量契约及夹具，修复隐私字段边界；对当前已脱敏历史数据影子评估，不尝试恢复被过滤的内容。
- ROLL-002 — 第二阶段在确定性恢复、入库、更新和检索入口强制执行质量约束。规则版本和灰度开关可配置，先使用 953 及多类型代表样本验证。
- ROLL-003 — 第三阶段接通结构化采集、有限补全、快照切换和详情状态，执行真实页面验收。
- ROLL-004 — 第四阶段历史扫描默认只生成候选清单和原因，优先处理明确空壳。实际修复先备份正文、元数据、索引关联和收藏状态，再将来源隔离、获取合格快照并在原 ID 上重建摘要与索引。无法补全的记录保持待采集，不用其他文档填补。
- ROLL-005 — 回滚可停止新任务与新规则写入，恢复修复前的版本指针和兼容读取；已确认空壳的消费隔离独立保留，不能因功能回滚重新泄漏到检索。每次修复保存清单、校验和及反向操作记录。

建议实施顺序为“先停止错误产出，再提升正文获取能力，再治理存量”；首个切片也必须配套前端可理解的缺失状态，不能静默吞掉用户文档。

## 风险与待决策

1. 当前原文访问：953 仍需通过有效登录会话取得内容。缺少访问不会阻止通用代码验证，但阻止个案端到端验收。
2. 历史脱敏不可逆：已删除文字不能从现有 capture 恢复，必须重新采集；不能关闭隐私策略来追求完整率。
3. 虚拟编辑器覆盖：部分站点不暴露块标识或修订版本，默认保持 partial。站点适配器按结构能力注册，通用路径仍保留。
4. 资源预算：本方案默认值是建议，需要实际页面样本和运行时间数据校准；不得自动无限提高重试预算。
5. 产品默认：建议 partial 正文允许进入检索并显式限定证据范围，shell 不进入检索；该默认是本方案建议，尚未视为用户批准。
