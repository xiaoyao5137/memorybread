日期：2026-09-08。测试本机当前开发版本，不打包 DMG。

## 范围与方法

本次按主要用户路径和风险等价类测试，不将有限用例描述为穷举所有自然语言。保留工作区已有修改，先将相关代码基线保存到 `/tmp/mb-creation-qa-20260908/baseline.tar.gz`。新增缺陷回归先在相应修复前基线上复现，再验证修复。模型脚本使用合成材料和隔离存储；页面测试新建专用验收会话，不修改原有用户会话。

## 本次修复

1. **会话之间的迟到结果串写。** 切换会话先停止并保存原运行；主生成、建档、终态保存、选区修改和撤销均核验请求归属。旧请求的清理不能释放新请求状态。取消与提交竞争时，收到已提交的结果仍会恢复正确正文；不再把恢复失败误报为“文档未修改”。前端最初新增 12 项回归在基线均失败，修复后均通过。最终复审再补上旧接口兼容生成的迟到结果隔离，以及脑暴失败重试在首个事件之前中止的持久化，两项均先复现后修复。
2. **正文操作识别错误。** 在规范化前校验嵌套操作对象，避免畸形输出跳过有界修复。识别重叠重复片段，禁止把有歧义的选择器当唯一匹配。Markdown 节点覆盖完整多行 Setext 标题，排除代码、HTML、注释、列表和引用中的伪章节。包含增删改移的 24 种排列回归，并与桌面解析器的根标题和字符偏移对照。
3. **脑暴人工修改后旧答案复活。** 清空决定重新变为待确认，不能被历史记忆或根需求补回；手改后不再沿旧多选 ID 下钻。重答时撤销过期的手改覆盖及其下游覆盖。清空上下文显式保留字段 ID 和维度，有手改时从结构化字段重建，避免旧 Markdown 摘要重复注入。归档的子分支保持可回看。
4. **运行状态被旧进度覆盖。** 缺省 epoch 只兼容尚未开始运行的旧记录，不能穿透已启动运行的 epoch。进度接口保护终态与正文，同一终态仍可补充元数据；正常正文保存接口不受阻。
5. **断点缺少会话、正文和简报绑定。** 外部模型回传和普通恢复均校验会话、当前正文以及本次提供的简报。用户失败后修改简报再重试时，Core 跳过旧断点，基于当前输入开始新运行；侧车也独立拒绝旧简报的恢复，防止继续使用旧来源和写作计划。相同简报正常续作，旧快照缺省简报与显式空简报兼容，真正清空已有简报仍视为变更。保留原底稿、已保存分步结果的兼容路径；拒绝跨会话和被后来编辑替换的文档。完成的补丁恢复后不重复应用。跨会话缺陷已通过实际侧车 ASGI HTTP 入口复现。
6. **输入判断、写作和验收看到的材料不一致。** 三者共用带版本的上下文快照，保留角色、用户更正、根需求和有效简报。统一入口的截断规则，先裁剪助手解释，避免中段用户更正被上游首尾截断提前丢弃；在原有 40 条上限内保留根需求锚点和最近用户消息，助手最多 4 条。超过总容量的历史仍是有界上下文，不能宣称无限保留全部旧约束。助手消息不进入可选事实行。验收继续提供原 `supplied_lines` ID 和完整候选 Markdown，补齐简报行号和全文结构，分行通知样本复测通过。旧断点的简报缓存按结构化内容重建。
7. **擅自补充日期及验收遗漏。** 检索时间范围不作为事实写入正文；资料齐备的写作不注入执行时钟。占位符守卫不改写已有数字，且本周/上周标签必须对应。新增日期、周次和相对时间限定单独验收，不能仅凭其他数字正确便通过；查询时间、采集元信息及不可用来源不能替代事实依据。此前新增的 16 项回归覆盖来源视图的可用性与容量边界，不是日期换算测试；验收规则允许有依据的换算、等价表达、待确认建议和用户允许的虚构。

    后续真实调用还暴露了正文写“本周”、审计释义却省去该限定的问题。代码核对实际正文与所选来源的日历标签，不用模型释义替代原文；仅拦截可识别范围内的无日期来源和裸星期新增周锚点。常用同值格式做等精度规范化，遇到未解析的日期线索采取保守处理。复杂换算继续由原日期条件核验，不把这项有限词法守卫描述为完整日期推导。正确日期选错来源时需要修正引用，不能据此要求删除正确正文事实。
8. **脑暴结构化边界。** 换方向返回问题的异常进入内部有界修复；字符串 `"false"` 不再被解释为必答。
9. **成品夹带验收说明，篇幅判断失真。** 写作和检查提示统一要求结构通过作品实现，不能将“困难”“解决办法”“结尾”等自评标签混入正文。代码提供正文实测汉字数、非空白字符数和拉丁词数，避免模型凭行数估算字数；保留用户原计数口径和“约”的合理浮动，不任意加严。

10. **失败条件或前置问答替代成文目标。** 真实检索已命中资料，却因“取不到就失败”的条件把撰写小结分成只读回答，最终正文为空；“先回答、再写通知”也曾遗漏成文。单一目标引用和字段顺序调整的实测仍不稳定，因此改为一次模型调用中逐项标记实际任务、约束和失败回退，再由代码聚合正文动作。引用范围、角色及动作组合有界核验，格式异常沿用两次上限；不靠项目名或业务关键词分类。数组仅用于意图核验，不作为执行计划、事实或工具收据，原始指令仍完整进入独立需求和检索流程。分类及完整输出分别验收。

11. **验收检查项被合并或漏报。** 不能把“无依据数字”和“无依据日期”的两项要求合并在同一个 reason 中。首次明确必检 ID；格式重试精确反馈缺失、重复和未知 ID，保留两次上限。真实不可用来源样本复测返回两项完整的拒绝理由，而不是漏项错误；这组证据包含四项真实模型验收及一项缺检索回执的代码拦截。后续修正控制又出现重复检查 ID，内部解码进一步改为实际必检 ID 的固定对象，并把“通过”与实际非空正文行证据绑定，严格校验后按原顺序还原公开数组；原条件、旧保存报告和两次格式修复额度保留。最终结构仍需结合真实正文逐项验收。

12. **普通脑暴被业务关键词带偏。** 真实读书会需求因包含“设计”“创作功能验收样例”而被强制套入技术架构、实现机制等章节。默认改为五个中性创作维度，专业覆盖由用户所选 Skill 的实际决策步骤补充；不能从需求中偶然出现的词推断必须写技术方案。

13. **脑暴资料限制缺少统一输入时序与清理。** 真实需求明确不检索个人资料，仍进入查询分析与检索。后续复核确认不同禁止措辞、条件性许可、旧选项引文、人工修改及自定义方向均需要统一处理。资料限制在分析和检索前判断，按用户输入修订顺序处理变更；禁用后从用户确认内容和人工编辑重建上下文，避免旧参考说明重新进入下一题或成文。当前实现与页面复验状态见最终验收证据。

14. **受众默认值和模型预检草稿污染正文。** “周三下午、二楼会议室”的材料被扩写成“各位同事”，预检拟出的草稿也曾被当成交付目标。未提供受众时不从主题关键词推断群体；交付目标绑定原始指令，预检的需求理由和草稿不作为写作事实。显式创作设置单独进入输入、写作及验收，兼容旧快照时只更新该设置，不重建已冻结的其他上下文。真实对照进一步发现，一个宽泛通过判定会用正确时间或未增加流程抵消已承认的无依据身份；还会漏掉“例会”性质和报备义务。现在由共用构造器向写作、修复和验收提供身份关系、属性存在、流程义务三项独立必检条件，代码要求全部通过；保留授权方案设计和虚构故事，不擅自要求逐个虚构设定另行许可。原始混合指令的完整成稿已在一次修正后通过，原六项来源对照均达到预期，已通过样本用最终请求回放验证，受影响负例另做真实复测。

    仅拆分三项检查仍可能漏掉句中隐含含义，因此同一验收调用增加逐片段来源审计：候选片段绑定实际原文，来源 ID 由代码从真实可用目录取回材料；已识别为无依据或推断的内容由代码强制退回。片段覆盖全部本轮改动，长文合并而不截断；以最多 32 组实际 ID 的必填对象限制返回结构，避免本地解码器去除数组长度约束后发生重复扩写。重复键、漏片段和错误引用仍进入有界格式修复。来源可用标记在共用证据压缩中保留，不可用资料不能成为事实依据。没有按样本词汇删除正文或放宽用户的“不补充新事实”要求。

    授权童话对照还出现过逐片段均认可虚构授权、独立检查却反称无授权的矛盾。现在仅在审计全部正面却有独立来源失败时，使用原两次核验额度重新核对。已有真实负面时保留独立失败，不因某一引用定位欠准确而再生成一份报告、撤销已检出的“例会”等错误。独立条件仍保留，因为真实样本曾由它补获片段审计漏掉的含义；这项一致性约束不等于代码证明所有语义都正确。

15. **完整生成修正反复保留错误底稿。** 真实控制反复复制“同事”“本周”和额外流程，复杂的段落补丁与逐问题处置也未解决。完整生成修正改为从原可信材料和原目标重新成文，只将失败问题及旧稿标题、章节结构作为参考，不要求照存失败正文；已撤除未发布且实测无效的生成补丁处置实验。局部变换继续绑定原选区并使用原子补丁，回答仍只更新回答。修正与审查共用材料，保留 Skill 的有效约束；代码从原失败检查与来源审计派生完整问题，同 ID 多问题及超过 12 条的要求不会丢失。历史问题绑定同一修正链，原材料可以纠正旧误报；新链不继承，旧断点仅在原有输入绑定成功后迁移，后处理修正前保存恢复状态。仍使用原两次修正额度，实际写入正文要再次独立验收。

    共享模型入口现在按真实输出形式附加标题要求，避免补丁、回答或 Skill 单章节收到全文指令；24 个本地及外部调用分支覆盖该边界。重新成文使用整稿替换预览，防止页面临时拼接旧稿与新稿；旧局部修改意图和 Skill 最终组装也不能覆盖已修正的新稿。从原始失败材料重新成文的诊断及生产修正入口控制均已通过：生产入口一次修正、两次模型调用，实际替换正文与独立验收正文一致。独立保存的完整混合指令也以一次内容修正、七次模型调用完成，最终正文事实准确、语句通顺，以 `run.completed` 结束。

## 内容样本与人工复核

首轮自动检查曾将收入更正样本判为通过，但人工逐字检查发现新增了错误周次和日期，因此该样本被判不通过并触发修复。修复后的正文为：

> 本周实际收入为96万元，相比上周的80万元增长20%。

脑暴通知首次生成的时间、地点、人员实际完整，验收却把 Markdown 分行标签误判为缺失；据此补齐同源行 ID 和全文结构。复测还检查“周三”不能无依据改成“本周三”。表格按项目、状态、负责人逐行核对，不能只检查关键词是否出现。童话检查完整情节、篇幅和行动结果关系，不以虚构世界不符合现实物理作为错误。只读回答同时核对原文完全不变。

旧验收脚本的正反对照使用了不符合当前数据来源契约的 `content` 字段，导致有效数字不可见。脚本已改为生产使用的 `can_use`、`content_excerpt`，并将“若陈述因果就需依据”与“必须额外写因果”区分。旧报告保留为失败证据，不算当前通过证据。
