# 脑暴横向推进与后台预生成

2026-09-09。

## 用户可见行为

用户多选 A、B、C 后，先分别讨论 A、B、C 的解法，再按同样顺序进入执行与验证。每题保留真实父题和父选项关联；最近回答的兄弟题不会变成下一题的父题。单选、自定义方向、继续脑暴新方向仍能进入后续阶段，验证方式讨论结束后不无限分叉。

A 的题目返回后，后台即可准备 B、C；B 已准备而 C 仍在生成时，提交 A 会直接发布 B，并保留 C 已进行的计算。只为用户已经确认的分支准备题目，不预测当前尚未提交的答案。前端显示当前方向路径，回看历史保留原答案与路径。

## 调度与有效性

Core 使用同一广度优先队列进行前台取题和后台准备，默认每会话最多准备 4 个候选，可用 `MEMORYBREAD_BRAINSTORM_PREFETCH_LIMIT=0..16` 配置。缓存只驻留进程内，最多 8 个会话、有效期 10 分钟；不改数据库表结构，不后台推进 revision、写答案或生成正文。

缓存依据根需求、Skill、人工修订、祖先答案版本、分支身份和模型配置区分。只有程序确认不改变资料权限的普通选项回答允许沿用同层快照；自定义文本、跳过、排除、回改、换方向、编辑简报、结束与放弃会撤销旧缓存及在途调用。调度在存储锁内核对持久化版本，并保留被撤销版本的标记，防止并发旧恢复请求重新启动预生成。迟到结果再次核对缓存代次和会话终态，不能复活已终止会话。

预生成命中时仍检查最新有效历史中的重复题干；相同题干忽略标点与空白后判重，拒绝候选并转前台生成。候选发布时分配 Core 题目 ID，避免同一回答计数下独立模型生成相同 ID。人工编辑清除旧派生资料段；同许可兄弟题保留已核验引用，明确等于已答题的待决定项会清除，跳过产生的待核验假设与人工待决定事项不会被当作已解决。

Sidecar 的 `prefetch=true` 进入现有 P2 可抢占通道，当前用户所需题目仍用 P0；前台需求可中断预生成，未完成的下一题转前台执行。HTTP 断开会取消排队与实际模型协程；后台记忆检索使用单线程、有界进入的独立执行器，慢检索不会拖住取消后的模型槽，也不会累积已取消工作。原总截止和有界质量重试保持有效。

## 验证边界

预生成利用用户阅读和作答的时间隐藏模型延迟，不保证所有题目都零等待。首题、未准备完成、被前台抢占、候选重复或上下文失效时仍会调用模型。同层普通选择沿用准备时的共同上下文，不声称已核对之后新增的所有跨方向预算或资源约束；提示要求对未知兄弟决定保留条件，后续生成继续消费全部有效用户回答。

真实验收使用独立 Sidecar、真实本地模型和临时 SQLite 中的合成会话；用户原有会话不作为自动作答对象。浏览器验收采用独立页面和模拟接口，用来确认方向切换、回看与窄屏布局；实际模型耗时单独记录。
