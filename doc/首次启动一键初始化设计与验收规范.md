# MemoryBread 首次启动一键初始化设计与验收规范

**状态：** 已实现，待发布验证
**Owner：** 未指定
**决策人：** 待指定
**最后更新：** 2026-07-27

## 1. 摘要

MemoryBread 的采集、提炼、咨询和创作能力依赖本地推理引擎、采集提炼模型、向量模型、本地数据库以及内置 Skill/Tool。当前首次配置允许跳过，且组件安装分散，用户可能在核心能力不可用时进入主界面。

本方案把首次启动改为一个不可跳过的一键初始化门禁。用户只需点击一次“初始化”，应用在后台按阶段执行判重、安装、启动、迁移、质检和功能冒烟测试；窗口可以最小化，重新打开后继续显示同一任务的百分比和阶段。只有所有阻塞项和最终质检通过后才进入主界面。失败时可以重试，也可以在用户主动确认后把经过脱敏的诊断包上报到云端，供运营台分页查看。

## 2. 问题、证据与边界

### 2.1 问题

- 没有采集提炼模型时，产品核心闭环不可用，但旧引导允许跳过。
- Ollama、模型、数据库和 Skill/Tool 分别由不同模块管理，用户无法判断“已经可以使用”还是“只完成了部分安装”。
- 使用 Homebrew 或 `Ollama.app` 会引入额外依赖或菜单栏图标，降低首次成功率并暴露底层工具。
- 初始化失败缺少可运营的、隐私安全的环境信息和阶段错误。
- 开发者缺少与真实用户目录隔离的首次初始化回归模式。

### 2.2 已知事实

- 桌面端已经有本地模型列表、Ollama 安装/启动接口、SQLite 自动迁移、首次引导和调试面板。
- 客户端本地 API 分为 core-engine `127.0.0.1:7070` 与 AI sidecar `127.0.0.1:7071`。
- MemoryBread 坚持本地优先；截图、知识内容、prompt、回答和本地数据库明文不得包含在初始化上报中。
- MemoryBread 客户端不得消费供应商模型名、供应商密钥或购买成本。

### 2.3 非目标

- 不把本地数据库、截图、知识库、prompt 或模型回答上传云端。
- 不在首次初始化中安装系统级 Homebrew、LaunchAgent 或 `Ollama.app`。
- 不在本次能力中实现模型市场、供应商路由或模型计费。
- 不承诺在系统版本、磁盘空间或网络条件不满足时绕过平台限制。
- 测试模式不复用、移动或删除用户真实模型和真实数据库。

## 3. 用户与核心场景

### 3.1 首次安装用户

打开应用后只看到初始化门禁。点击“初始化”后可以最小化窗口去做其他事情；再次打开时看到同一个运行任务、总进度和当前阶段。完成后收到操作系统通知并进入主界面。

### 3.2 已有部分组件的用户

初始化逐项探测。已安装且校验通过的组件显示“已就绪”，不重复下载或覆盖；缺失项才执行安装。最终仍统一执行质检和功能冒烟测试。

### 3.3 初始化失败用户

看到失败阶段、可执行建议和“重试”按钮。点击“上报诊断”前可以看到将上传的信息范围；确认后生成幂等上报，不包含内容数据或秘密。

### 3.4 测试账号/开发者

在调试面板开启“初始化测试模式”，二次确认后进入隔离沙箱。应用把真实环境视为不可见，每轮分配随机空闲回环端口和唯一沙箱身份，在独立 HOME/XDG、运行时目录、模型目录和临时数据库内走完整初始化和质检。冷启动轮次的运行时、两个模型、数据库、技能工具阶段不得判重跳过。关闭模式后，只停止并清理本次沙箱资源，恢复原状态。

## 4. 决策

### 4.1 采用应用托管的 Ollama CLI 运行时

MemoryBread 下载并校验官方发布的 macOS CLI 压缩包，把可执行文件放在应用数据目录的版本化运行时目录，由 sidecar 以子进程执行 `ollama serve`。不安装 `Ollama.app`，因此不会出现 Ollama 菜单栏工具；不调用 Homebrew，因此不依赖用户预装包管理器。

托管进程必须：

- 只绑定回环地址；
- 使用 MemoryBread 专属模型目录；
- 禁用 Ollama 云能力；
- stdout/stderr 写入受控日志且执行脱敏、滚动和大小限制；
- 由 MemoryBread 记录 PID、运行时版本和健康状态；
- 如果 `127.0.0.1:11434` 已有兼容的无界面 CLI 服务，则复用并判定推理引擎阶段完成，不接管或终止该外部进程；如果服务由 `Ollama.app` GUI 主程序托管，则先安装并校验 MemoryBread 托管 CLI，平滑退出 GUI 后接管为无界面后台服务，避免菜单栏图标继续出现；
- 正式模式使用固定稳定端口；测试模式每轮使用随机空闲回环端口、唯一沙箱身份和独立目录，不接受仅凭端口健康的未知进程。

运行时版本、下载地址和 SHA-256 必须由随安装包发布的清单固定。清单升级属于客户端版本发布，不在运行时静默漂移到 `latest`。

### 4.2 初始化由 sidecar 单任务状态机统一编排

sidecar 负责持久化任务状态并在后台线程执行。前端只负责启动、轮询和展示，不把多步骤工作流串在 React 生命周期里。一个环境同一时刻最多有一个初始化任务；重复启动返回同一任务。

### 4.3 完成标记必须晚于质检

客户端完成标记使用新的版本化键，只有 `completed` 且 `quality_gate.passed=true` 时写入。旧“已完成/已跳过”标记不能直接绕过新版门禁。被用户手动删除的阻塞组件在下次健康检查后会重新触发门禁。

## 5. 生命周期与状态

### 5.1 任务状态

`not_started -> running -> completed`

失败路径：`running -> failed -> running`（重试）
测试路径：开启 `mode=sandbox` 时必须先停止有身份标记的遗留沙箱进程，再删除旧沙箱并生成新身份；随后执行 `not_started -> running -> completed|failed`。关闭时再次校验 PID、创建时间、可执行文件和沙箱身份，停止沙箱进程并删除沙箱，再恢复正式模式状态。

应用或 sidecar 异常退出时，持久化为 `interrupted`。重新打开后显示“继续初始化”；继续执行时逐阶段判重，不依赖上一次内存状态。

### 5.2 阶段

| 顺序 | 稳定阶段 ID | 用户文案 | 建议进度区间 | 判重依据 |
| --- | --- | --- | --- | --- |
| 1 | `preflight` | 检查运行环境 | 0–8% | 系统、架构、内存、磁盘、网络与端口 |
| 2 | `inference_engine` | 准备本地 AI 引擎 | 8–25% | 受信二进制存在、哈希正确、健康接口可用 |
| 3 | `capture_model` | 准备采集提炼能力 | 25–52% | 品牌组件映射对应的模型摘要存在并可推理 |
| 4 | `vector_model` | 准备语义检索能力 | 52–68% | 品牌组件映射对应的向量模型存在并可生成向量 |
| 5 | `database` | 准备本地记忆库 | 68–78% | core-engine 健康、迁移版本完整、读写探针通过 |
| 6 | `skills_tools` | 准备技能与工具 | 78–86% | 必需内置清单存在、结构合法、版本兼容 |
| 7 | `quality_gate` | 执行完整质检 | 86–93% | 组件健康、权限、磁盘、端口、数据库完整性 |
| 8 | `feature_smoke_tests` | 验证核心功能 | 93–100% | 采集、提炼、咨询、创作四类测试全部通过 |

阶段状态为 `pending | running | skipped | succeeded | failed`。`skipped` 仅表示“已有内容通过校验，无需重复安装”，在最终判定中等价于成功。百分比必须单调不降；真实下载阶段根据字节或模型拉取进度映射到对应区间。

## 6. 功能需求

- **FR-001** — 首次启动或新版完成标记缺失时，应用必须只展示初始化门禁，不得渲染或通过快捷键、托盘、深链进入主界面。
- **FR-002** — 门禁必须提供唯一主操作“初始化”，一次点击启动完整后台任务，不要求用户选择模型或安装工具。
- **FR-003** — 初始化任务必须在窗口最小化或隐藏后继续执行，并在窗口恢复后展示同一 `run_id` 的最新进度。
- **FR-004** — 初始化必须展示 0–100 的单调总进度、当前阶段、每阶段状态和用户可理解的说明。
- **FR-005** — 每个阶段执行前必须判重；已存在且验证通过的内容不得重复下载、覆盖或迁移。
- **FR-006** — 初始化必须覆盖推理引擎、采集提炼模型、向量模型、数据库、Skill/Tool、质检和核心功能冒烟测试。
- **FR-007** — 只有阻塞阶段全部成功且最终质检通过时，应用才能写入版本化完成标记并开放主界面。
- **FR-008** — 完成时应用必须发送操作系统通知；通知失败不得把已经通过的初始化改判为失败。
- **FR-009** — 失败界面必须展示失败阶段、稳定错误码、可执行建议、重试和上报诊断操作。
- **FR-010** — 用户确认上报后，客户端必须先幂等提交结构化白名单到 `/v1/initialization-reports`，再通过客户日志接口上传脱敏、限量日志并关联 `initialization_report_id`；不得自动上报。
- **FR-011** — 运营台必须提供“上报信息”分页页面，覆盖 loading、empty、error、forbidden 状态，并展示阶段错误、应用版本和运行环境；有关联日志时，仅向具有客户日志权限的运营人员提供短时下载地址。
- **FR-012** — 调试面板必须允许测试账号/调试模式用户在二次确认后开启初始化测试模式。
- **FR-013** — 测试模式必须使用独立 HOME/XDG、运行时目录、模型目录、数据库、随机回环端口和唯一沙箱身份，不移动、改名、删除、读取或写入真实用户环境；冷启动轮次的五个安装阶段不得返回 `skipped`。
- **FR-014** — 关闭测试模式必须停止仅由本次沙箱启动的进程、清理沙箱目录、恢复正式环境可见性和原完成标记。
- **FR-015** — 同一环境重复提交启动请求时必须返回已有运行任务，不得并行安装同一组件。
- **FR-016** — sidecar 重启后必须从持久状态恢复；中断任务可继续，并重新验证已经完成的阶段。
- **FR-017** — 应用启动后的健康校验发现阻塞组件被删除或不可用时，必须重新启用初始化门禁。
- **FR-018** — 阶段失败后必须先执行有界自动修复：可续传下载和合成探针最多额外重试一次；Core 异常必须先等待启动宽限，然后仅重启 Tauri 持有的内置子进程。自动修复用尽后才允许用户重试或上报。

## 7. 非功能需求

- **NFR-001** — （隐私）诊断包不得包含截图、窗口标题、应用内容、知识库、prompt、回答、凭据、主机名、用户名、完整文件路径或供应商密钥。
- **NFR-002** — （安全）下载运行时必须使用 HTTPS、固定版本和 SHA-256 校验；校验失败不得执行文件。
- **NFR-003** — （隔离）托管推理服务必须仅监听 loopback，正式和测试环境的数据目录不得重叠。
- **NFR-004** — （可恢复）所有阶段必须幂等；断网、进程退出或应用重启后可从判重重新开始。
- **NFR-005** — （可访问性）初始化界面必须支持键盘操作、可见焦点、ARIA 进度语义和减少动态效果偏好。
- **NFR-006** — （可观测）日志使用 `run_id`、`stage_id`、稳定错误码和耗时，不记录用户内容。
- **NFR-007** — （兼容）云端 API 采用 expand -> deploy -> consume 顺序；旧客户端不调用新接口时不受影响。
- **NFR-008** — （成功率）必须记录首次运行完成率、各阶段失败率、重试成功率和耗时分位数；正式发布阈值由产品负责人批准，不在本文虚构。
- **NFR-009** — （可取证）诊断日志必须来自固定文件白名单，单文件只取末尾 128 KiB；core 不可用时必须能通过 loopback sidecar 读取同一日志目录。
- **NFR-010** — （修复安全）自动修复不得结束身份不可验证的外部进程，不得删除或重建现有数据库，不得放宽下载校验或沙箱隔离。

## 8. 功能冒烟测试

所有测试使用固定、非用户内容的探针，结果只保存通过/失败、耗时和错误码。

| 测试 ID | 能力 | 验证方式 |
| --- | --- | --- |
| `capture_probe` | 采集 | 在当前隔离目标数据库写入一条固定合成采集记录，通过 core API 读回后立即删除，验证真实采集表、触发器、持久层和查询接口 |
| `extraction_probe` | 提炼 | 对固定短文本执行一次本地推理，验证输出非空且满足最小结构 |
| `consultation_probe` | 咨询 | 对固定文本生成向量并执行一次固定问答，验证向量维度和回答非空 |
| `creation_probe` | 创作 | 使用内置默认 Skill/Tool 清单执行固定短内容生成，验证工具清单可加载且输出非空 |

模型生成探针必须关闭长思考，并限制为 2048 上下文、最多 64 个输出 token；
探针只验证基础生成链路，不允许因为模型默认的长思考策略把健康组件误判为超时。

真实截图采集权限由进入主界面后的系统权限流程管理。初始化不得为了测试而静默申请屏幕录制权限。

## 9. 本地接口契约

### 9.1 `GET /api/initialization/status`

返回当前环境的状态。模型和引擎只返回品牌化组件 ID，不返回供应商模型名。

```json
{
  "status": "ok",
  "initialization": {
    "schema_version": "initialization.v1",
    "run_id": "UUIDv7/UUID",
    "mode": "normal",
    "state": "running",
    "progress": 43,
    "current_stage": "capture_model",
    "stages": [
      {
        "id": "capture_model",
        "label": "准备采集提炼能力",
        "status": "running",
        "progress": 61,
        "detail": "正在下载必要组件",
        "error_code": null
      }
    ],
    "quality_gate": {
      "passed": false,
      "checks": []
    },
    "can_retry": false,
    "can_report": false
  }
}
```

### 9.2 `POST /api/initialization/start`

请求：

```json
{ "mode": "normal" }
```

若已有任务运行，返回 HTTP 200 和原任务；不得创建第二任务。参数或环境不满足时使用：

- `INITIALIZATION_ALREADY_RUNNING`
- `UNSUPPORTED_PLATFORM`
- `UNSUPPORTED_ARCHITECTURE`
- `INSUFFICIENT_DISK_SPACE`
- `RUNTIME_DOWNLOAD_FAILED`
- `RUNTIME_CHECKSUM_MISMATCH`
- `RUNTIME_START_FAILED`
- `MODEL_DOWNLOAD_FAILED`
- `DATABASE_INITIALIZATION_FAILED`
- `SKILLS_TOOLS_INITIALIZATION_FAILED`
- `QUALITY_GATE_FAILED`
- `FEATURE_SMOKE_TEST_FAILED`
- `INITIALIZATION_COMPONENT_MISSING`
- `SANDBOX_CONFLICT`
- `SANDBOX_ISOLATION_FAILED`

### 9.3 测试模式

- `POST /api/initialization/test-mode`：创建并启用隔离环境。
- `DELETE /api/initialization/test-mode`：停止本次沙箱进程并清理沙箱。

测试模式接口只在桌面调试模式显式开启时由 UI 调用；服务端仍必须验证确认字段和当前任务状态。开启响应通过 `sandbox_isolation` 明确表示正式运行时、模型和数据库均不可见，以及本轮是否为强制冷启动。

## 10. 云端上报契约

### 10.1 `POST /v1/initialization-reports`

允许未登录的首次启动用户调用；如果请求携带有效用户 Bearer token，服务端在可信边界内关联 `user_id`。请求使用 `Idempotency-Key`，同一 `installation_id_hash + run_id` 只创建一条记录。

允许字段：

- `schema_version`
- `run_id`
- `installation_id`（客户端随机 ID，服务端只保存 SHA-256）
- `client_version`
- `occurred_at`
- `failed_stage`
- `error_code`
- `summary`（长度受限、经过脱敏）
- `environment`：OS 名称/版本、架构、内存档位、可用磁盘档位
- `components`：品牌组件 ID、版本、状态
- `checks`：检查 ID、状态、耗时、稳定错误码

响应：

```json
{
  "data": {
    "report_id": "UUIDv7",
    "received_at": "2026-07-27T00:00:00Z",
    "duplicate": false
  },
  "request_id": "..."
}
```

错误码：

- `INVALID_INITIALIZATION_REPORT`
- `INITIALIZATION_REPORT_IDEMPOTENCY_MISMATCH`
- `INITIALIZATION_REPORT_THROTTLED`

请求体超过 256 KiB 时由 HTTP 层返回 413。相同 `installation_id_hash + run_id` 直接返回原回执并标记 `duplicate=true`；同一安装实例每小时最多接收 5 个新任务，已登录用户每小时最多接收 20 个新任务。

### 10.2 关联诊断日志

结构化上报成功后，客户端调用客户日志的 prepare / OSS PUT / complete 链路，prepare 和 complete 请求都必须携带相同的 `initialization_report_id`。服务端校验安装实例哈希一致，登录上报还必须校验用户归属；关联字段可选，因此旧版客户日志上报保持兼容。

### 10.3 `GET /ops/v1/initialization-reports`

要求 `ops.initialization_reports.read`，必须服务端分页，支持 `page`、`page_size`、`failed_stage` 和 `error_code`。响应不内嵌日志文本，只展示白名单结构化数据和可选的 `diagnostic_log_id`；日志下载仍要求 `ops.customer_logs.read`。

## 11. 验收标准与追踪

- **AC-001** — 验证 **FR-001、FR-007、FR-017**。给定新版完成标记不存在或健康检查确认阻塞组件缺失，当启动应用时，则只能看到初始化门禁；快捷键和托盘打开仍停留在门禁。
- **AC-002** — 验证 **FR-002、FR-006**。给定未开始的初始化，当点击一次“初始化”时，则无需第二个安装选择，任务按八个阶段执行到质检。

## 12. 可观测性

- **OBS-001** — `initialization_started`：模式、客户端版本、平台和架构；不含用户内容。
- **OBS-002** — `initialization_stage_finished`：`run_id`、阶段、结果、耗时、是否判重、错误码。
- **OBS-003** — `initialization_finished`：总耗时、首次完成/重试完成、质检结果。
- **OBS-004** — 云端按客户端版本、OS 主版本、架构和失败阶段聚合首次成功率；样本量不足时不下结论。
- **OBS-005** — 运营页面访问和日志下载进入独立运营审计；初始化报告仅返回关联 ID，下载继续复用客户日志的短时 OSS 地址和权限检查。

## 14. 风险与缓解

- 官方运行时体积较大：固定版本、断点临时文件、真实字节进度、充足磁盘预检。
- 模型下载受网络影响：幂等拉取、失败保留可复用缓存、明确重试，不从零覆盖有效 blob。
- 外部 Ollama 冲突：先探测 11434；兼容则复用，不兼容则返回明确端口错误，绝不 `pkill` 用户进程。
- 遗留沙箱进程伪装成新环境：每轮随机端口和唯一沙箱身份；复用前校验 PID、创建时间、可执行文件、模型目录与数据库路径，身份不符立即失败。
- App Store 沙箱限制：运行时下载/执行能力需单独经过签名、公证和商店审核评估；商店渠道可由发布清单选择随包资源或禁用不合规路径。
- 冒烟测试污染真实数据：采集探针只写入固定合成记录并在 API 读回后立即删除；模型探针使用固定合成文本，不读取用户内容。
- 上报泄露隐私：端侧固定文件白名单、末尾限量和脱敏；服务端校验大小、对象和报告归属；运营台按独立权限下载。

## 15. 待决策与开放问题

- App Store 渠道最终采用“随包签名运行时”还是“审核允许的下载运行时”，需要发布负责人和合规审核决定。
- 托管 Ollama 版本升级节奏及运行时清单签名机制需要发布负责人决定。
- 正式发布所需的首次初始化成功率阈值、采样窗口和最低样本量需要产品负责人决定。
- 当前数据库限流覆盖安装实例和已登录用户；如匿名随机实例滥用上升，再评估基于网关/Tair 的全局限流，不在客户端采集额外指纹。
