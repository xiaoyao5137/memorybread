## 已实施的契约

新建且没有已选 Skill 的三阶段会话使用准备契约 17。每阶段准备一批平面内容题，当前 Sidecar 一次最多生成一道高影响问题、恰好两个完整可选方案；Core 契约容许每阶段 0 至 4 题，后续可在有证据时扩展。问题需指向原需求、有效用户答案或人工修订中的逐字锚点，说明答案改变正文何处；每个选项要产生不同的内容结果。方向问本次成品的对象、主线或路线；细节承接已确认决定和周期，问指标口径、措施机制、执行约束或证据缺口；行文问具体材料的论证与缺证表述。风格和段落顺序不再代替内容问题。全部内容决定已足够时可返回 0 题，但必须给出经独立审查的原因并在页面显示。

Sidecar 的通用路径让本地模型先输出紧凑的 `content_seed`，程序将它编译成完整 `BrainstormQuestion`、选项和 `content_proofs`。能从有效原需求识别计算资源成本优化报告时，领域 profile 先编译针对账单、GPU 卡时、利用率、闲置时段、回收／调度记录和同口径对照的条件式候选；不匹配的任务仍走通用路径。编译候选也必须接受同一独立模型审查，拒绝后才有界尝试模型生成，不把编译成功伪称审查通过。程序校验题数、选项数、推荐项、重复题、来源锚点、逐项正文作用、未授权日期与数值、以及周报周期是否误入内容题。条件性“先核对，取得证据后再写；缺失则标待核”可以作为方案；没有来源的实际成本、节省额、利用率、发生过的措施不得变成事实。独立模型审查逐题、逐选项检查本次性、可答性、固定决定、正文作用和事实边界；`unknown` 或拒绝使候选失败，重试有界，失败时保留已保存状态。模型审查通过只代表候选可展示，不代表最终文档合格。

Core 使用持久化的 `content_mode` 和版本 17 区分新旧流程。细节阶段仍先执行周期/来源预检，确认周期与预检收据进入准备指纹；用户修订或清空已确认的周期、来源时，依赖它们的当前内容题、已答选择及证明归档，重新预检并准备后续阶段。历史答案、人工修订和已完成正文保留为历史，不会作为新周期的有效依据。用户真实选中的完整方案说明以条件做法进入有效简报及章节写作输入；人工简报修订优先，未选方案不进入。Core 验证 Sidecar 返回的逐题 proof、真实权威锚点、方案差异、输入身份与 CAS 后才保存题池；proof、哈希与归档不进入公开响应。版本 17 的候选文案不能经 `repair_candidate_copy` 单独修改，因为那会脱离已审查证明。行文阶段建立一个正文容器，问题按现有确认和交付流程推进。已选 Skill 的新会话暂沿用既有 v16 可信目录路径，避免新内容模式绕过 Skill 政策。

对能明确识别的计算资源成本优化报告，版本 17 的资料预检会分别核对账单费用、资源用量及利用率／措施记录的来源。每类资料独立保留 `matched`、候选、缺失或读取失败状态；一类命中不能代替其余类别，也不能证明其中的成本数值、措施效果或节省结论正确。资料缺失时按现有来源确认题询问准确定位或选择明确缺口。旧 v16 和其他题材没有新增强制资料项。

客户端沿用现有 MemoryBread 问题卡和三阶段布局；版本 17 平面题提示“逐题确认”，零内容题时显示 Core 保存的跳过原因。细节阶段即使保留已答的报告周期澄清题，仍能显示内容题跳过原因。没有改变页面的答题、版本锁或章节提交流程。
