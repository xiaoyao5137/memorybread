# OCR 用户优先、抢占与后台恢复

## 与上一轮修复的区别

上一轮将后台模型队列的同步等待移出 IPC 事件循环，解决 OCR 无法被及时调度的问题；没有建立 OCR 优先级。本轮增加用户咨询/创作优先级、原生取消、会话期间暂停及后台任务恢复。

## 契约与执行

- IPC OCR 增加 `priority: foreground | background`，旧请求默认 background。不能根据 capture_id 猜测来源，因为两类调用都可能传 0。
- 用户附件/主动截图显式 foreground，Core 后台补识别与自动扫描为 background。
- 咨询、悬浮球与创作 UI 在整个处理期间持有独立 activity_id；覆盖 OCR、检索、云端/本地生成和工具执行，不仅覆盖模型出 Token 的时段。每 5 秒续期；结束、失败、取消、卸载时释放；未续期 15 秒后过期。多个活动必须全部释放才允许后台继续。已有跨进程 P0 demand 同样阻止后台 OCR。
- 前台请求到来，排队中的后台任务直接返回 OCR_DEFERRED。执行中的 Apple Vision 请求调用取消接口，等待原生调用确实结束后再执行用户 OCR；全局单并发不变。
- OCR_DEFERRED 是调度让位，不是识别失败。Core 始终保留同一队列任务与原图，每 250ms 重试，直到前台结束；普通超时/真正错误仍按原有错误策略结束，不无限重试。
- 被中断图片从头识别，其他已完成图片不重做。取消的结果不会触发 fallback 或写入半截文字。
- 不支持原生取消的后端、或原生取消失败时，在当前原生调用结束的安全边界让出，不能宣称任意 OCR 引擎都能瞬时中断。Apple Vision 取消接口来源：https://developer.apple.com/documentation/vision/vnrequest/cancel()

## 验证

- Python OCR、IPC、后台处理和咨询回归 135 项通过，1 项平台相关跳过。
- 前端活动续期/结束、并发活动、晚到续期、悬浮球、咨询、创作/脑暴回归 110 项通过。
- Core 采集 36 项通过，包含两次 OCR_DEFERRED 后仍使用同一原图并成功恢复，以及真正超时只发送一次请求。
- 桌面 Rust 8 项通过；共享 IPC Rust 7 项与 1 项 doctest 通过。
- 前端构建、Python 3.9.25 编译检查、git diff --check 通过。
- 真正 Apple Vision 验收：先等待后台原图进入 VNRequest，再提交前台 OCR。后台取消、用户完成、同一背景图片恢复全部成功，用户与恢复结果各 111 字符，合计约 0.489 秒。使用独立 worker，仅隔离其他 P0 活动检测，不替换 Vision。
- 正在运行的 IPC 服务验收：建立两条用户活动；后台让位；用户识别成功；只释放一条时后台仍暂停；全部释放后原图识别恢复。两次结果均 111 字符。
- 保留用户原图，未把这些调用级验收称为原生窗口鼠标自动化；未打包 DMG。
