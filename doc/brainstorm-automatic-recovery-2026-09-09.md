# 脑暴重复问题与瞬时故障自动恢复

2026-09-09。

## 现场与原因

最新创作记录 `creation_history.id=155` 在 01:07:20、01:08:47 两次返回 `BRAINSTORM_MODEL_OUTPUT_INVALID`，对应约 69.6 秒、75.2 秒的请求。捕获时脑暴 revision=19，18 轮已保存回答、正文为空。两次请求均耗尽三次模型尝试，主要原因是重复已回答的题干，也出现指定探索阶段不匹配。

重复判定对应真实旧题，不应放宽。原生成只约束 JSON 语法，没有按当前任务约束状态、阶段和覆盖目标；历史参考位于提示末尾，容易压过当前分支。纠错只描述最后一次错误，没有提供被拒绝的题目，也没有保留此前尚需避免的错误。模型断流、限流与短暂不可用未完整纳入生成和历史核对的内部恢复。

## 修复行为

- 根据本轮任务生成紧凑 JSON Schema，约束 question/ready、题型、指定阶段和覆盖目标；继续保留内容长度、重复题、选项质量和引用校验，不以修改标签或预置题库冒充成功。
- 在历史资料和纠错数据之后重新明确当前分支、阶段目标与已答题目。质量重试携带被拒绝候选的最小问题字段和累计校验原因，完整重生成，不重复检索，不把失败候选当作用户决定。
- 短暂模型断流、超时、限流和不可用使用统一分类，在本次请求内退避恢复；问题生成仍最多三次尝试，与排队、检索共享 150 秒总截止。历史核对保留两次/40 秒预算，无法核实时继续有背景的提问，不承接未经核实的决定。鉴权、配置和取消不盲目重试。
- 中间失败不返回前端，SSE 保持等待，成功后仅交付经过校验的结果。持续故障耗尽预算后才返回固定中文错误，避免无限等待、重复提交或伪造成功。
- 脑暴路由耗尽错误按白名单映射状态和文案；日志只记录类型、受控错误码及结构枚举，不记录异常内的地址、密钥或模型正文。

契约更新于 `shared/creation-brainstorm/README.md`。Core/UI 无需叠加整轮重发，避免重复消耗队列和提交后断流的版本冲突。
