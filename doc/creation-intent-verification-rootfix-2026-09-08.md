# 创作动作核验与排版空白误拒绝修复

日期：2026-09-08。本机开发版本，不打包 DMG。

## 根因证据

最新用户记录为 `creation_history.id=154`，脑暴转成文时失败于操作解释之前。原运行日志的两次失败均为 `requests[0].request 必须逐字引用完整 instruction 中的原文`，P0 执行约 7.3 秒，并非排队超时或检索未取得资料。

使用该记录的真实原指令，以及失败断点中带完整简报的旧 `context_query`，分别重放旧实现。两种输入均连续两次失败；模型将中英文交界自动加空格，如 `非L0商家` 变为 `非 L0 商家`，`GMV` 和 `SOTA` 两侧加空格。其余原文保持一致，动作已正确判断为 `create`。重试返回了相同排版，因此仅增加重试不能消除故障。

另一个输入边界缺陷是：脑暴模式把本轮指令、历史简报与引用一起拼成 `context_query`，再全部作为动作分类的 instruction。历史上下文不应成为本轮新动作的证据。

## 修复范围

- 证据定位优先逐字匹配。仅在逐字匹配失败时，允许汉字与 ASCII 字母/数字交界的横向排版空白差异，建立原文字符偏移映射，并要求唯一连续原文位置。返回值来自原始文本，模型抄写内容不会替换用户输入。
- 英文词内部、数字内部、汉字之间的空白，以及换行、标点、大小写、非空白文字改动仍有意义；无法唯一定位仍失败关闭。不会把排版归一化结果用于文档补丁、数字修正或事实替换。
- 本地、外部模型及恢复路径统一只核验 `state.user_message`。脑暴简报作为独立的交付约束背景传给路由，写作和检索的上下文继续保留。旧断点的无绑定分类重新核验；缓存绑定本轮指令与正文是否存在，简报修订仍会刷新约束。
- 来源审计中的候选正文引用也使用相同的保守原文定位；后续语义、数字、日期与来源 ID 检查继续使用实际正文原文。
- 连续空白一次扫描，避免不符合排版容错条件的长空白段出现二次复杂度。
