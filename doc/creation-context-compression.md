# 创作上下文压缩方案

## 目标

创作写作、修订和交付验收共享一套有界上下文契约，在本地模型上下文窗口内同时满足：

1. 原始材料和断点不丢失；
2. 数字、日期、否定、适用范围和来源定位不经生成式改写；
3. 模型调用前为结构化输出保留明确预算；
4. 失败后从同一 session、operation 和正文断点继续，不重新检索或写作。

## 分层结构

### 原始层

完整参考资料、数据结果、工具回执和正文继续保存在 operation checkpoint。该层不因压缩而修改，也不直接整体进入 Prompt。

### 证据层

`CreationEvidencePrompts` 生成两种互补视图：

- `source_catalog`：保留精确事实文本、稳定来源 ID 和授权属性，供模型选择并由代码回查；
- `retrieved_evidence` inventory：仅保留来源身份、可用性、刷新状态和数量，不重复事实正文。

精确事实按当前正文片段和验收条件进行相关性排序，在字符预算内选择，不做生成式摘要。未装入本批的事实只表示当前上下文未展示，不能证明来源或事实不存在。

### 审计层

正文来源审计最多分成 32 个可定位片段。每批大小根据“正文 + 精确事实账本”的共享压力在 8、4、2 之间调整；每个片段仍须恰好检查一次，最终由代码合并结果。

### 传输层

结构化节点调用前估算 Prompt token，并以 `MEMORYBREAD_CREATION_CONTEXT_TOKENS` 为统一窗口契约。系统预留安全边界和节点声明的首轮输出预算（最低 1024 token）；空间不足时不发送请求，而是由调用方切换紧凑提示词。长度恢复只在剩余窗口内增加输出预算，不再以更大的 `num_predict` 重发超出上下文的输入。

## 安全边界

- 原始材料、正文和 operation checkpoint 不因压缩被覆盖。
- 精确事实只选择、不改写；模型返回的 `source_id`、正文行和审计片段均由代码重新绑定。
- `can_use=false` 的来源只出现在 inventory，不能作为事实证据。
- 压缩视图未命中不能转换为“事实不存在”。
- 截断候选整份丢弃，不能拼接残缺 JSON。
- 极端情况下仍无法完成时，错误保留 `retryable=true`，客户端可从已保存断点恢复。

## 验收

交付要求同时满足：压缩后输入和输出预留不超过实际上下文窗口；所有来源片段及验收条件无遗漏；最终出现 `delivery.checked` 和 `run.completed`；恢复前后的 session、operation 和已保存正文保持一致。
