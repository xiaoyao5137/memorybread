## 已发现并闭环的问题

- 长对话中新增的角色压缩器之前仍存在首 4 加末 36 的原始截断。42 条消息的最小样本会先丢掉用户“取消预算上限”，留下原预算。现已统一采用角色预算：保留首条用户锚点和近期用户输入，最多 4 条近期助手消息，维持时间顺序、40 条总上限及幂等。实际 `_new_state → _input_context` 链路已有回归。
- 私有资料禁令曾被常见否定语气、并列检索动作绕过；引用委托一度影响其他无关引用；否定或条件句中的许可也曾解除限制。现已使用完整直接授权、按具体引用区间识别委托及通用动作连接规则。独立纯函数检查覆盖 12 条否定、引用和许可表达。
- 人工修改根需求后的新禁令曾被较早回答中的许可覆盖。现由 Core 持久化 `user_input_revisions`，按真实先后比较；同版本限制优先，旧状态未知顺序的限制保守保留。迁移使用已有值优先，不在恢复时不断刷新旧编辑时间；重新打开或修订答案会移除失效下游版本信息。
- 停止检索后，旧题干、选项 tradeoff、模型假设、历史 Markdown 和来源不明的 focus 仍可能进入模型上下文。现按有效用户字段重建；分支 focus 仅携带用户确认的标签。用户明确排除的主题和人工清空的具体字段仍保留范围语义，不恢复旧答案或来源段落。
- 自定义继续方向原先没有持久化，也没有参与权限判断；同时勾选推荐方向与自定义时，自定义内容被忽略。现单独和混合继续均保留为用户输入，携带修订号；独立 `user_inputs` 保留完整的用户授权或限制，后续轮次不丢失。
- 同一指令失败后保存新简报再重试，旧 checkpoint 会恢复此前的简报和 `input_context v1`，忽略请求中的新资料范围。真实 sidecar 模拟服务测试证明两类恢复均曾接受旧状态。Core 现按规范化后的输入决定是否重用 checkpoint；变更时启动新尝试，不接旧模型结果。Sidecar 在缓存和文档身份恢复之前检查简报是否变化。
- 恢复输入比较一度误将原本为空的简报和显式 `{}` 判为变化。已规范化为空快照等价，同时保持“原非空简报变为 `{}`”属于真实清空。空与非空同输入的正对照均保留。

## 恢复模块 16 项覆盖

原有 8 项：跨会话恢复拒绝；插入人工文档修改或清空后恢复拒绝；重试 checkpoint 不得覆盖其他文档；原始基线及已保存结果可恢复且不重复应用；外部模型结果在未变基线上可正常接续；HTTP 拒绝跨会话状态且不发出另一会话事件。

新增 8 项：

| 输入情况 | resume_state | resume_checkpoint |
| --- | --- | --- |
| 保存新私有资料禁令后重试旧状态 | 拒绝旧状态 | 拒绝旧状态 |
| 原非空简报显式清空为 `{}` | 拒绝旧状态 | 拒绝旧状态 |
| 相同非空简报 | 正常完成 | 正常完成 |
| 原本为空，继续发送相同 `{}` | 正常完成 | 正常完成 |

修复前证据：新禁令两项均 `DID NOT RAISE OperationError`；增加严格比较后，空简报相同输入两项曾错误抛出 `CREATION_BASE_CHANGED`。最终既阻止过期输入恢复，也保留合法恢复。
