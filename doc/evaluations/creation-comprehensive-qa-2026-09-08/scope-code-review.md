# 三项来源检查的独立代码复核

本文件保留历次结构与兼容性试验的复核记录，各节机制并非全部同时存在于最终代码。完整生成曾尝试段落补丁及问题处置，实测未改善后已撤除；最终重新成文路径以主报告、共享契约和后续生产验收记录为准。固定检查 ID、来源审计、历史问题留存、局部原子操作与标题输出模式等通用修复继续保留。

独立前端 QA 代理只读复核了最终三项来源检查及已有测试源码，没有运行模型或修改文件。代码边界复核未发现阻断；真实模型输出的接受结论另见对应运行及人工复核记录。

- `SOURCE_SCOPE_CHECKS` 分别规定身份关系、属性与存在预设、现实读者的额外流程义务。`with_source_scope_check` 深拷贝原契约，逐项处理 ID 重名并保留用户条件的内容与顺序。
- 早期三项检查版本由 `_model_prompts` 的外层 `contract_attached` 包装向普通写作及修复递归附加同一组条件，保证只附加一次。后续专用修正输入替代了修复递归复用通用润色环境，当前结构见后文；三项条件与原契约继续共用。
- `review_delivery` 使用相同构造器生成验收条件及必检 ID。`validate_review` 继续验证精确覆盖与全部通过，任何独立项失败都不能被整体 `pass` 覆盖。
- 三项只检查本轮新增或修改的内容，不借此扩大局部编辑范围。虚构故事的角色类型、地点、事件和拟人无需逐项取得许可；故事内部的行为不当作对现实读者的流程义务。明确授权的方案设计和安排仍可创作。
- 相关现有测试核对了写作、修复和验收条件相等，原契约不变，ID 冲突，漏报，以及单项失败不能被总评通过掩盖。

代码复核不证明任意自然语言输出均正确。验收数据必须与候选全文、原材料、授权范围和实际执行记录交叉核对。

## 逐片段来源审计复核

后续独立只读复核覆盖固定对象结构的 `source_audit`、来源目录、校验及已有针对性用例，未发现代码阻断问题。该轮复核没有运行模型、测试或修改文件。

- 改动按真实片段分组，最多 32 组，长文合并保留内容；不连续改动保留为独立原文部分，不能将中间未改正文或跨部分拼接的文字当作本轮声明。
- 实际片段键作为解码结构的必填属性，重复 JSON 键在解析阶段拒绝，缺失和额外片段在代码中拒绝；格式修复保留两次上限。
- 候选引用绑定实际原文，来源引用绑定相应可用来源。助手消息、工具回执和不可用资料不进入事实来源目录；构造新内容还需要可提供用户授权的来源。
- 已标为合理推断或没有依据的含义会强制对应系统检查失败，即使模型的后续检查全部通过也不能覆盖。原用户验收条件和对外报告结构保留。
- 对应用例包括长文覆盖、80 处间隔改动、固定必填键、重复键拒绝、六类负面审计强制退回、来源绑定、虚构及中性表达，以及十种无效响应的有界重试。空值兼容结论仅限已验证的参考资料视图和来源目录入口。

该结构保证覆盖记录及已识别问题的执行约束，仍不独立证明模型找到了所有隐含事实。事件性质、流程义务与中性称呼的真实语义正反对照另行验收，不能仅因返回 `revise` 就认定定位正确。

## 来源 ID 版本复核

最新一轮独立只读复核覆盖来源 ID 协议及对应新增用例，未发现新增阻断，未运行测试或模型。

- 固定字段为 `text/source_id/meaning/kind/basis`；来源只能从实际目录中选择，原文由代码取回。未知非空 ID 在任何依据类型下均拒绝，有依据声明不能使用空来源；构造授权额外要求来源具备用户授权资格。旧 `source_quote/source_evidence` 字段不会意外通过。
- 含义类别与依据类型分别判断，`neutral` 类别没有自动通过分支。两种负面依据仍强制对应系统项失败；类别为中性却承认无依据时也会退回。原有逐项检查及全部通过要求保留。
- 审计对象从内部返回中移除后，仍校验原来的 `checks/status/corrections`；不会把模型解释或来源 ID 变成正文事实。真实可用来源目录、助手和不可用资料排除、简报与旧正文不能独立授权构造的边界未放宽。
- 该轮读过 `test_creation_delivery_contract.py` 中字段顺序、八类未知/空/禁授权输入、来源取回及旧字段拒绝、六类负面依据，以及类别解耦正例；共享条件及 ID 冲突等回归保留在上下文测试模块。

代码保证来源绑定、授权资格和已识别负面判断的执行，不能独立证明所选材料在语义上支持候选，或某种称呼确实中性。实际模型与成稿验收继续独立记录。

## 从核验问题生成修正要求

后续版本将内部审查的自由修正建议限制为空数组，代码校验原报告后，从失败项及来源审计生成对外修正要求，避免实际模型在自由修正建议内重复生成而耗尽长度。对外报告仍为 `checks/status/corrections`，不完整、漏项或相互矛盾的结果不能交付。

独立只读复核发现，同一检查 ID 下，逐片段审计的新问题曾覆盖原检查里另一条失败原因。修正后分别保存覆盖前和覆盖后的失败项，按 ID、原因、证据联合去重，同 ID 的不同问题均进入修正要求；超过 12 项时合并呈现而不丢弃。已有回归使用“例会由协调员主持”同时核对周期性质与角色职责均保留。该复核不证明模型执行了全部修正，真实未改正文的失败记录另行保留。

## 专用修正输入的兼容性复核

`delivery_repair` 使用与交付审查共用的 `delivery_source_materials`，将原请求、原文、用户对话、已保存简报及可用原始材料和失败候选分开。修正意见与候选不提供新增事实；实际输出模式、polisher 调用、原验收条件及两次修正额度保留。

独立只读复核发现并确认修复了两项兼容问题：

- 回答型操作的候选应为 `operation.response`，与实际审查对象一致；原始文档单独保留，不用旧正文代替待修回答。回归使用原文“周三”与错误回答“周五”区分二者。
- 保留 Skill 已归一化的 `title_design_style`、`writing_design`、`image_generation` 和 `voice_style`，覆盖旧 `writingGuidelines/writingDesign/titleDesignStyle/imageGeneration` 输入的实际约束值。示例全文与示例字段不升级为事实来源。

这两项修正由实现代理执行两个相关模块 211 项回归并确认通过，独立代理只读复核源码及用例后未发现新增阻断。该数字是阶段性结果，最终整组回归以主报告和日志为准；专用修正控制的实际正文仍未通过，不能用兼容性回归代替内容验收。

## 修正执行与历史问题闭环复核

完整生成的交付修正改为复用已有 `patch_writer`。独立只读复核确认，它在构造提示和外部模型等待状态前绑定当前失败候选，使用显式全文可修改范围；局部变换继续使用本轮原文与原选区，回答仍使用 `operation.response`。精确目标、重叠、范围及原子应用复用已有操作校验；该阶段空补丁和没有实际变化的补丁在写入前拒绝，后续问题处置协议增加了合法空补丁独立复核路径，见后文。JSON 模式实际使用结构化补丁协议及 8192 生成预算，修正次数仍为两次。

外部模型等待状态保存转换后的步骤、候选基线和范围信息，恢复时按该步骤处理返回的 JSON，不会交给旧的文本润色处理。已经发出的旧文本润色请求仍按其原协议完成，兼容此前保存的断点。

同一次修正链保留原失败检查、来源审计后的失败检查及修正意见，同 ID 多问题不覆盖。问题记录绑定原指令、原文和原验收条件；动态日期检查及候选改变不使其误判为新任务。历史引用单独标明是否仍逐字存在于当前候选，不拼入当前验收条件，也不自动决定通过或失败；当前材料可以纠正旧误报。整份交付通过后清除，新的修正链不继承。

持久化方向的独立只读复核确认：旧问题迁移只在会话、正文和简报恢复绑定成功后执行，已有新记录、新链计数为零或已通过报告不迁移。历史报告单独校验结构及原输入条件，允许旧证据因修正而过时；正式交付校验仍严格绑定当前正文。后处理发现新问题后，在发起修正之前保存当前正文、待核验问题和修正计数，异常时能从该状态恢复。

两个方向均确认本轮源码边界无新增阻断，未运行模型或测试。实现代理执行的相关两个模块为 229 项通过（17.04 秒）；这是专项快照，真实修正控制及最终完整路径的内容结论另记，不能用代码复核替代实际正文验收。

## 精确段落目标与外部返回校验

实际补丁控制发现模型抄错目标空白后，生成修正改用当前稿的实际目标目录；细片段删除又留下半句，因此最终生成修正按空行分隔的段落分组，相邻合并至最多 32 组，保留原文、空白、CRLF 和尾部。来源审计的细片段切分不变，不能把该目标目录描述为完整 Markdown 语法树。

独立只读复核曾发现目录只约束本地解码，外部返回可以绕过。修正后，在请求分流之前保存 `candidate_paragraphs.v1`、当前基线和目录；本地解码 schema 与提示使用同一目录，外部请求在提示中提供目录，完成入口按已保存协议重算并核对。每个 `target/destination` 必须是目录中的精确 text 对象，不能使用自由 ID、字符串或非目录子串；随后仍核验 occurrence、位置与原子补丁范围。外部通道没有新增本地解码 schema 字段，等效写入边界由执行校验保证，不能声称两者解码协议完全相同。

旧 `candidate_fragments.v1` 按原分片规则处理，无版本的旧等待请求按原协议兼容。独立复核读过四类绕过反例、完整段落恢复正例以及长文/CRLF 无损覆盖用例，确认该增量无新增阻断，未运行模型或测试；实现代理报告对应专项 238 项通过，最终完整回归以主报告为准。

## 问题目录、实际变更与作者自评边界

真实两轮修正中，一处日期修改曾使另一处同文替换被当作有效补丁。因此执行器逐项拒绝 no-op，新的生成修正响应必须完整覆盖固定问题目录，并与实际原子补丁一同校验。目录由当前失败及同链历史问题生成，历史长理由不再作为当前结论反复注入；完整原始报告保留在环境与断点。引用位置支持重复、重叠及跨行匹配，空引文不伪造定位。

持久化方向只读复核确认，作者处置、trace 和结果不进入来源目录或独立验收的事实视图；独立验收继续使用原条件及当前材料。合法空补丁保持正文但执行已有独立审查，单步标记消费后清除，不能影响后续步骤；不增加两次修正预算。没有问题协议的既有等待请求仍按旧补丁协议恢复。

前端方向复核提出，宽引文内修改日期不能证明其身份限定已纠正。据此将处置命名和含义收敛为 `edited_quote`，不再以来源审计引用或短于段落推断“语义精确锚点”。代码只证明引用相关位置有编辑，或来源 ID 有效、旧引文确已消失；不证明来源在语义上支持正文。所有处置都保留独立复核，不能清问题、自动通过或代替实际正文验收。该版本相关两个模块曾执行 256 项通过；后续处置组合校验和真实控制仍在进行，最终数量与内容结论另记。

v12 实测发现结构化解码允许运行时禁止的处置与来源组合。后续联合 schema 与执行校验共用定位状态规则：逐字存在时选择 `edited_quote`，已移除时选择 `not_present`，无法定位时可用 `unresolved`，这三种必须为空来源；来源目录非空时另允许 `source_backed` 配实际非空 ID。只读复核确认解码准备保留 `oneOf/const`，无来源目录不会产生不可能满足的来源分支，合法空补丁仍只进入独立审查。实现代理执行相关两模块 **262 项通过**。本轮 issue 协议仅用于内存与隔离脚本，尚未作为生产恢复请求部署，未为这些未发布实验变体保留额外运行时；实际旧文本、无 issue 协议补丁及旧候选目录兼容继续保留。真实控制结论另记。

## 固定检查 ID 的内部解码

v14 两次验收均重复同一个检查 ID。内部 `checks` 改为由实际 `required_check_ids` 生成的固定对象，每个值只有 `evidence/reason/passed`；严格核对全量键及字段后，按原条件顺序规范化回原公开数组。独立只读复核确认原 criterion 未改写，重复 JSON 键在解析阶段拒绝，规范化后继续执行原行证据校验、来源审计及公开报告校验，不填充通过、不合并失败项。

公开与持久化报告仍为 `checks/status/corrections`，旧数组报告继续由 `validate_review/validate_prior_review` 处理。内部验收是直接等待模型的调用，没有已发 `model.request` 断点；新调用若返回旧数组会按新结构拒绝并进入原有两次格式修复。两次内容修正预算不变。该复核覆盖直接输入原始坏 JSON 的十项失败和恢复测试，但未运行测试或模型；结构保证不能证明正文事实判断正确。

## 标题指令与实际输出形式

真实修正插入重复全文后，核对到共享 `_execute_step` 为有文档身份的补丁、回答和分析也追加了全文标题命令。新的局部 helper 先排除转换后的 patch、answer、query，再尊重 Skill 显式 `document` 角色，普通全文 writer/polisher 才附加全文命令，严格 Skill 单步 writer 保持局部输出。不能用 `operation=generate` 判定全文，因为其修正已转换为 patch。

独立只读复核确认，本地/外部模型分流前共用追加点，外部 pending 保存相同提示；身份元数据和已有 `apply_title` 治理保留。24 个参数化用例覆盖真实 `_execute_step` 请求，而非只测试内部提示工厂，包含显式 document 角色不能越过 patch/answer/query 以及生成修正转换后的反例。实现代理执行两个相关模块加既有标题治理共 **391 项通过**（296 + 95），这仍是专项快照。复核未运行模型或测试；实际重复标题及内容错误是否解决，以后续原始起点控制为准。
