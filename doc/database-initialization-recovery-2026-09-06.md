# 本地记忆库初始化失败优化

截图中的 `DATABASE_INITIALIZATION_FAILED` 仅能定位失败阶段，历史用户的具体根因仍需版本号及诊断包确认。本次改动补齐后续故障定位和恢复能力。

## 行为

- SQLite 锁竞争、只读、访问受限、空间不足、损坏、I/O 异常、缺失迁移与数据库位置不一致分别显示稳定错误码和恢复建议；未知异常保留旧错误码。
- 核心 `/health` 增量提供实际数据库位置与编译时完整迁移列表。位置仅用于本机匹配，不加入云端诊断。健康接口读取启动时缓存的位置，不与业务数据库争锁。旧版核心缺少元数据时保留基础表校验兼容路径。
- 核心在 HTTP 服务启动前原子记录数据库启动阶段、当前迁移和安全错误码；初始化器验证 PID 与进程创建时间，仍在初始化时有界等待 180 秒，超时不杀进程。确定性数据库错误不再自动重启；锁竞争最多重试两次。
- 正式主库专用表执行随机标记的提交、读取和删除，替换 TEMP 表探针。常规状态检查只读。失败及重试不删除、重建或自动覆盖已有数据库。
- 诊断汇总记录安全异常类型、可获取的 SQLite 数字错误码、迁移版本/缺失数量与失败耗时，不记录原始异常正文、SQL 或用户数据。Python 3.9 没有 SQLite 数字错误码时使用本地错误文本分类，但不上传该文本。
- 失败页同时显示具体原因及对应恢复建议。
