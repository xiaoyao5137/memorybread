# 创作细节选题与本地资料召回改造复盘

## 原因

原 GPU 成本优化周报会话的创作细节来自已安装 Skill 的 15 道静态题，题目只处理字段摆放、图表说明和证据排版。配置题库的生成路径不执行本地资料召回，阶段完成条件也只检查这些题是否答完。因此周期尚未明确、周会纪要和周期报表尚未核实，就能进入行文。此前正文虽然有草稿，但交付核查明确列出周期资料和指标缺口。

## 已落地的选题顺序

1. 从用户原指令和 Skill 执行步骤抽取资料需求；先在本地记忆查找文档、知识、数据与已保存的来源定位，再考虑向用户索取补充。标题词序不同的本地文档通过有界、只读的标题补召回纳入候选。
2. 若原指令没有确定报告起止日，先问周期。候选给出完整起止日并允许自定义，均不预选。相对词不能作为自定义周期的最终答案。
3. 周期得到用户确认后，用来源本身声明的统计期和完整度重新判定每项资料。采集或更新时间单独显示，不充当统计期。已匹配资料不再重问；候选、部分、缺失、检索失败和未检索分别解释。
4. 只对仍待核实的资料提确认题，允许确认具体候选、补充定位后重检，或明确要求带缺口成稿。候选确认不修改原始来源日期；带缺口成稿不将历史值写成目标期事实。
5. 原会话的已确认回答、原章节操作和草稿保留。旧会话可从行文返回补齐资料；已停在创作细节末尾的旧会话点击阶段确认时会启动预检，不会遇到只报错的死路。

具体状态和持久化约束见 [输入澄清契约](../shared/creation-brainstorm/input-clarification-v1.md)。
