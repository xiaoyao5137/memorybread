# 初始化权限步骤与系统授权引导

“开启采集权限”位于右侧初始化进度列表，在“检查运行环境”之后。环境检查通过后开始自动查询本机权限；全部必要权限已开启时直接标记通过，不显示弹窗。权限检查与后续组件准备并行，关闭引导不会停止后台初始化。

缺少权限时自动打开一次引导弹窗。关闭、Escape 或点击遮罩后不重复弹出，仍持续检查权限；可随时从右侧步骤按钮重新打开。实际权限齐全后自动通过，并关闭当时仍打开的引导。检测服务失败显示步骤状态，不误判缺少权限，也不主动弹窗打扰；用户可以打开引导重试。

弹窗只保留需要授权的项目的“去开启”操作，不提供手动标记已开启、截图验证或逐项验证按钮。屏幕录制、辅助功能、应用自动化会打开各自的 macOS 系统设置页，必要时发起系统授权注册。返回客户端、页面恢复可见及可见期间每 5 秒自动复查；按钮点击本身不是授权成功证据。可选项目默认折叠。

模拟初始化隔离组件准备，但系统权限属于本机，现与正式模式使用相同的真实权限查询。取消此前点击后直接置为已开启的模拟行为。自动检查不会申请权限；仅用户点击“去开启”后才打开系统设置或触发授权提示。

## 接口

- `GET /api/permissions`：在采集核心进程检查屏幕录制、辅助功能、输入监控；通过 `AEDeterminePermissionToAutomateTarget(..., false)` 无弹窗查询 System Events 自动化权限。未知错误不会被当作已授权。枚举支持的已安装浏览器，但不启动或读取网页。
- `POST /api/permissions/:id/request`：用户点击后打开对应设置及必要的系统授权提示。应用自动化先打开系统设置，再发起系统授权注册，状态仍由后续真实检查更新。
- 原有 `verify` 诊断接口不被初始化页面调用。

权限状态不跨启动缓存，避免旧授权遮蔽撤销后的真实状态。弹窗支持键盘焦点约束、Escape 关闭及关闭后的焦点恢复。设置页继续保留权限入口。

## 验证

前端回归覆盖：步骤顺序、尚未到达时不检查、已授权直接通过、缺少权限自动弹窗、关闭后不再次弹出、步骤按钮重新打开、授权后自动通过、接口错误不误通过、Escape、真实系统状态复查及模拟模式不伪造授权。后端测试覆盖 Apple Events 状态映射及原生 ABI、无弹窗查询、非法操作拒绝。

当前运行环境已确认屏幕录制、辅助功能、应用自动化均已授权；实际页面右侧显示“已自动检查通过”，从“已通过”按钮可重新打开显示真实授权状态的弹窗。未撤销或新增用户权限，未打包 DMG。

## 浏览器增强入口修复

删除弹窗顶部两段重复提示及“完成通知”设置；可稍后开启提示、诊断反馈收进“更多可选设置”。浏览器项目显示各自的菜单设置步骤。

浏览器“去开启”此前只执行后台文字检测，既不激活浏览器，下一次查询又恒定返回待设置。现请求通过受支持浏览器白名单打开并激活应用，检查启动退出状态；返回客户端时按真实授权状态自动检查 JavaScript 可执行性。查询不会启动未运行浏览器，也不会申请权限；只对原生授权预检已通过的目标执行常量脚本，不读取网页正文。

本次实测运行中的接口已正确识别 Chrome 网页增强为已开启；从弹窗点击 Safari“去开启”后，确认 Safari 已启动。浏览器内的安全开关仍由用户选择开启，应用不替用户确认授权。
