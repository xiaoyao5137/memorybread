# 创作输入残留与终止后恢复修复

## 真实问题与根因

截图对应 `creation_history.id = 152`，会话尾号 `582ff7e8`。只读接口确认该记录为脑暴模式，生命周期为 `cancelled`，对话已包含 `session_end`，尚未保存创作简报。

1. `beginBrainstorm` 已把指令加入用户消息，却要等待首题成功返回才清空输入框。用户在技能匹配、保存历史或首题生成期间终止，清空逻辑就不会执行。
2. 历史恢复仅检查脑暴模式和会话 ID，无条件发送 `action: start`。对于尚无首题的记录，这个动作会生成首题；顶部同时按已保存的 `session_end` 禁用终止按钮，造成“已终止但正在恢复，无法再次终止”的冲突。
3. 服务端原先没有根据历史的会话终止消息拒绝启动，也没有在异步模型返回后再次检查终态，迟到结果可能保存新的脑暴状态。

## 修复行为

- 提交脑暴指令时立即清空编辑器，原始指令保留在对话和根请求中。普通启动失败会恢复输入供用户重试；取消和会话切换不会回填。
- 终止时清空输入及当前附件，关闭添加入口。读取附件的迟到结果不能回填已终止或已切换的会话。
- 以明确的 `session_end` 或脑暴 `abandoned` 判定会话终止；普通单轮 `cancelled` / `user_abort` 仍可继续。
- 已终止历史只恢复展示，不再发送脑暴启动请求；旧草稿和热更新前错误启动的恢复请求也会收口，旧问题不再可编辑。
- 终态同步与正在运行的脑暴请求分开管理，取消旧请求不会误取消 `abandon` 同步。
- Core 在模型调用前、模型返回后保存状态前检查终止标记。后者与写入共用同一存储连接锁；被终止的请求返回 `409 BRAINSTORM_SESSION_TERMINATED`。重复 `abandon` 不再增加版本。
