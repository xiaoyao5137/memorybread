# 阶段 A 金标标注指南

## 1. 目标

金标用于同时衡量：历史事项误纳、本期真实事项保留、时间角色、状态/语态忠实、证据可回查和弃权。不能以全部判为未知获得通过。

## 2. 标注单位

每条记录只标注一个主要原子事项。并列句拆分；同一对象的目标、实际结果和当前状态分别标注。纯标题或目录项只有在正文提供谓词和状态时才形成事项。

## 3. 必填项

1. `source_type` 与原始文本；
2. 任务周期、时区和用途；
3. 最小逐字 `evidence_quote`；
4. `claim_kind/modality/status`；
5. `event_date/date_role/time_basis`；
6. `eligible/background_only/unresolved/conflict`；
7. 选择该结果的简短理由。

## 4. 标注步骤

1. 先忽略观察和刷新时间，只读来源正文。
2. 找出主要事项和最小支持片段。
3. 判定实际、计划、目标、预测或未知。
4. 判定工作状态，禁止用常识补全。
5. 列出局部日期并标注角色。
6. 仅在作用域明确时继承上下文日期。
7. 将事项时间与任务周期和用途对齐。
8. 有冲突且无法依据版本覆盖关系消解时标为 `conflict`。

## 5. 边界示例

| 来源 | 事项标注 | 周期进展用途 |
| --- | --- | --- |
| 本周打开，正文写 2 月完成 | 2 月实际完成 | `background_only` |
| 本周会议回顾此前完成，无历史日期 | 实际完成，时间未知 | `unresolved` |
| 本周会议“本周完成验收” | 实际完成，继承会议周 | `eligible` |
| 修订日期为本周，章节写建设中 | 当前进行中，变化时间未知 | `background_only` |
| 预计全年节省 100 万 | 预测/目标，不是实际 | `background_only` |
| 本期统计处理量 100 万次 | 实际指标及统计周期 | 指标用途 `eligible`，进展用途 `background_only` |
| 两个可靠来源给出不同完成日 | 时间冲突 | `conflict` |

## 6. 双人标注和裁决

冻结真实金标时，两名标注者应独立完成，不查看对方结果。计算事项用途和状态的 Cohen's kappa；建议门槛为 0.80。分歧由第三方或共同评审按契约裁决并记录原因。自动生成模板的一致性不能替代独立人工标注。

当前仓库中的 360 条语料是合成契约语料，用于门禁和模型回归，不声称具有人类双标结果。真实私人样本仅可在本机 QA 工作区保存，不写入仓库。

## 7. 冻结与防止过拟合

- 开发集用于调整 prompt 和规则，holdout 仅在版本候选冻结后运行。
- 每个问题修复增加同类正例和反向例。
- 不删除失败样本来提高分数。
- 语料、契约、提取器或规则变化均产生新版本和新报告。

## 8. 隐私处理

仓库语料使用虚构项目、日期和金额。私人文档只保留本机标注结果；报告仅写聚合指标和不可逆样本编号，不包含正文、私人 URL、人员或组织名称。
