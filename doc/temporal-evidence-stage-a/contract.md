# 时间证据与事项契约 v1

状态：阶段 A 冻结候选。适用范围：MemoryBread 本地采集、提炼、检索和创作。正式运行契约需在阶段 B 开始前再次审批。

## 1. 术语

### 来源版本

来源在一次可验证内容状态下的不可变表示。`version_hash` 由规范化正文和结构定位共同计算。相同来源、相同哈希重复观察不创建新版本。

### 事项

来源支持的最小可独立判断断言。事项必须能够独立回答“谁/什么、发生或处于什么状态、以何种语态、何时、依据在哪里”。目录名、孤立主题词和不含谓词的列表项不能自动成为“已完成”事项。

### 使用决定

事项针对某次任务的周期、时区和章节用途计算出的临时结果。可选值为：

- `eligible`：可以用于目标章节；
- `background_only`：只可作为背景或历史信息；
- `unresolved`：缺少必要依据；
- `conflict`：存在未消解的来源冲突。

## 2. 时间契约

### 观察时间 `observed_at`

由采集、刷新或导入系统写入，回答系统何时获得内容。它不得：

- 回填事项发生时间；
- 作为来源创建、发布或修改时间；
- 因再次观察而改变事项状态；
- 单独让历史事项进入本期进展。

### 来源时间

包括 `source_created_at`、`source_published_at`、`source_modified_at`。来源时间必须来自原生元数据、经身份校验的页面元数据或明确修订记录，并保存 `source_time_basis`。来源时间描述文档，不自动传播给其中所有事项。

### 事项时间

包括 `event_time_start/end`、`time_precision` 和 `time_basis`。事项时间只允许来自：

1. 事项本句或表格行中的明确事件/完成/状态变化/统计周期日期；
2. 未越过结构边界的章节、列表、表格或会议上下文；
3. 以可靠来源日期为锚点的相对时间；
4. 对具体来源版本和事项的用户确认。

未知时必须为 null。冲突时不得选择观察时间更近的一条。

## 3. 日期角色

| 角色 | 是否可直接形成事项时间 | 示例 |
| --- | --- | --- |
| `event` | 是 | 8 月 20 日决定采用新策略 |
| `completion` | 是 | 8 月 20 日完成验收 |
| `status_change` | 是 | 8 月 20 日进入阻塞 |
| `statistical_period` | 是，仅用于指标口径 | 统计周期为 8 月 20 日 |
| `revision` | 否 | 文档修订日期 |
| `publication` | 否 | 文档发布日期 |
| `deadline` | 否 | 计划截止日期 |
| `goal_horizon` | 否 | 年度目标期限 |
| `historical_reference` | 否，除非另有历史事件日期 | 本周会议回顾此前成果 |
| `observation` | 否 | 本周打开旧资料 |
| `unknown` | 否 | 日期作用不明 |

同一日期可在不同事项中承担不同角色，必须按局部作用域标注。整篇存在一个本期日期不能放行整篇事项。

## 4. 事项语义

### 断言类型 `claim_kind`

- `progress_event`：产生新结果的事件；
- `status_change`：进入阻塞、取消、恢复等变化；
- `decision`：已经作出的决策；
- `metric`：带统计口径的实际数值；
- `goal`：期望达到的目标；
- `forecast`：预测结果；
- `current_status`：当前状态，但变化时间可能未知；
- `background`：历史背景或一般事实。

### 语态 `modality`

`actual/observed` 表示来源声称已经发生或观察到；`planned/target/forecast` 分别表示计划、目标、预测；无法判断为 `unknown`。

### 工作状态 `status`

`unknown/planned/in_progress/blocked/cancelled/completed`。输出不得增强状态：

- 计划、目标、预计不得改写为完成或实现；
- 建设中、正在推进不得改写为完成；
- 当前已完成但完成日期未知，不得改写为本期完成；
- 累计或年化指标不得改写为本期增量。

## 5. 结构作用域

时间继承按照从强到弱的边界进行：同一表格行 → 同一列表项 → 最近章节 → 同一会议。遇到新的同级或更高标题、表头重置、明确转折“历史回顾/此前/后续计划”时停止继承。

相对时间必须有来源锚点：会议日期、明确发布日期或同一结构单元中的完整日期。观察时间不是默认锚点。没有锚点的“上周、此前、明年”保持未知。

## 6. 发布状态

模型输出首先为 `shadow`。只有同时满足以下条件才可 `published`：

1. 最小引用能在绑定来源版本中逐字回查；
2. 数字、单位、状态语义不强于引用；
3. 事项时间有允许的日期角色和合法作用域；
4. 来源版本完整性满足用途要求；
5. 没有未消解冲突；
6. 契约、提取器和规则版本完整。

验证失败使用稳定枚举原因，不由展示文案决定。`shadow` 事项可用于发现和补证，不进入本期进展。

## 7. 用途规则

### 周期进展

只有实际发生的 `progress_event/status_change/decision`，且事项时间与请求周期相交时为 `eligible`。目标、预测、当前状态、累计指标和历史事项为 `background_only` 或 `unresolved`。

### 指标章节

实际指标必须有明确统计周期并与请求周期相交。目标值和预测值不得伪装成实际值。

### 背景章节

已回证的历史事项可使用，但仍保持历史时间、状态和语态。冲突事项不能输出为确定结论。

## 8. 版本和纠正

- 事项绑定内容哈希、契约版本、提取器版本和规则版本。
- 来源正文变化创建新版本，不原地覆盖旧证据。
- 用户纠正绑定事项和来源版本，可撤销；新来源版本默认重新评估。
- 规则升级不自动全库调用模型，只在召回或维护预算内惰性重验。

## 9. 隐私

事项、引用、私人 URL 和纠正内容仅保存在本地。普通日志和遥测只允许记录枚举原因、数量、耗时和版本，不得记录原始正文、prompt 或引用。
