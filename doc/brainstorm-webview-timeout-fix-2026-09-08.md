# 脑暴启动失败：WebView 空闲超时修复

## 原始现场与根因

截图对应 `creation_history.id=153`、会话 `creation-1788839287733-8b87e3c942303`。2026-09-08 11:48:17 开始脑暴，Core 于 11:49:18 记录 `cancelled`，耗时 60,999ms；数据库尚无该会话的脑暴状态，正文为空。

同一次请求在 Creation Service 的 P0 队列等待 47,944ms，随后执行 58,876ms：检索 12,911ms、历史核对 20,603ms、首题生成 25,354ms，最终 HTTP 200。模型已经成功，但只返回最终 JSON 的 Core 长请求被客户端提前断开，Core future 被丢弃，无法继续保存结果。前端原生 `Load failed` 经安全错误过滤显示为“脑暴启动失败，请重试”。这次不是模型截断或生成质量校验失败。

独立 macOS 15.5 WKWebView 对照实测同时请求两条隔离接口：静默 65 秒后才返回 JSON 的接口在 **61,009ms** 报 `TypeError: Load failed`；立即发响应头、每 5 秒保活并于 65 秒结束的接口在 **65,046ms** 成功。测试未更改网络超时，每秒执行 `void 0` 避免隐藏 WebView 挂起。首次隐藏且未保活 WebView 的探针因执行挂起无效，不作为证据。

## 修复行为

- 同一脑暴接口新增 `Accept: text/event-stream` 协商。立即返回 `brainstorm.started`，等待期间每 10 秒发送注释保活，覆盖排队、检索、生成和保存；仅在状态机校验和持久化成功后发送 `brainstorm.completed`。旧 JSON 客户端保持兼容，`q=0` 不启用 SSE。
- 主脑暴和局部脑暴共用传输解析器，支持分块 UTF-8、CRLF、明确终态和旧 JSON；保活、started 或提前断流不冒充成功。错误事件保留安全错误码和原 HTTP 状态，网络断流显示固定中文原因。
- 保持现有 Sidecar 150 秒/Core 180 秒预算及用户取消语义。Core future 属于响应流，断连后不会有独立后台任务继续写入；前端取消、终止或切换会话后丢弃迟到结果。未修改 Python 生成逻辑或模型配置。
