# 脑暴多题延展与选项自主参考记忆

2026-09-10。

## 行为与实现

确认选项后，模型在同一次调用中先规划包含首题的完整同层主题，再生成第一个主题的问题，其余主题作为追加问题计划，默认每个方向本次展开上限 3 题，可配置为 1～8 题。单题足够时仍只生成一题。首题马上进入现有卡片，其余主题通过独立后台请求准备；同一个选项的多题保持相同父题与父选项，逐题由用户作答。先轮转同层已选方向的首题，再轮转同层互补题，最后才展开答案下的下一层。

后台请求默认最多 3 个并发，总候选数继续使用原有缓存上限。每个请求都进入 P2 全局队列，前台继续使用 P0；不会绕过本地模型的资源槽。候选准备好后，正常提交直接发布缓存题；未完成、被抢占或上下文失效时，以相同延展目标转前台生成。

内部 `pending_extensions` 保存未发布主题及父答案版本，不算用户决定，不进入简报、正文或回答计数。进程重启可恢复计划；后台完成不写数据库、不推进 revision。上游改答、人工编辑、自定义补充、可能改变资料权限的选项、结束与换方向会撤销未发布计划和旧缓存；已有用户输入保持在原状态与历史中。

问题生成请求携带专用 `sibling_question_context`，包含同方向首题和其他同层主题，仅用于避免重复，不把未回答题当作用户答案。完整计划的第一项对应首题，不把它再次放入后台。独立延展目标接入现有 `next_question_goal` 强目标约束和生成结构，祖先路径提供背景，探索阶段限定深度；题干和选项仍由模型生成，不靠事后修改标签伪装成新题。可选重复主题被过滤而保留合格首题；真正生成的延展题明显重复时，在原有预算内重写。

模型逐项自主决定是否参考召回资料，可以整题采用新思路或混合历史参考，不再优先推荐有引用的选项。新生成要求声明 `memory_mode`，旧响应省略仍兼容；实际使用历史事实必须有真实来源与原文核验。无引用的详情使用中性描述，不把“未附引用”误认成已证明完全原创。资料访问限制仍遵循有效用户输入，不由模型扩大权限。

## 验证

- Core：43 条相关单元回归、15 条预生成集成回归、24 条脑暴 API 回归、3 条 SSE 传输回归和 3 条模型边界回归通过；预生成套件另有 1 条需要显式启用真实服务的测试未运行。release 构建通过。
- Sidecar：16 个文件共 518 条相关回归通过、1 条跳过；使用真实 Python 3.9.25 对 10 个本轮变更文件执行编译、语法与禁用类型联合检查。宽泛维度标签不再吞掉具体互补目标，两个误过滤反例与原有重复题守卫均通过；此前成功的真实模型原始输出在这次最终修改后重放规范化仍通过，没有额外模型请求。
- 前端：4 个文件共 65 条相关回归及生产构建通过；真实浏览器操作验证逐题切换清空选择、历史回看不重复提交、同父同层树节点和 390 像素窄屏无横向溢出。页面使用隔离的模拟服务。
- 并发证据：Core 测试在放行响应前观察到 3 个独立后台请求同时在途；队列测试在总容量 3 时允许 2 个后台创作同时执行，为 P0 保留余量；总容量 1 时保持串行。发布顺序与完成先后解耦，缓存、重启恢复及撤销均有回归。
- 真实模型：使用合成需求和资料，首题一次输出 3 项完整计划，转换为 2 个后续目标；对其中“小组规模与表达规则设定”独立复验，一次生成通过，选项落实了小组人数与发言规则组合。题干措辞仍接近首题，但选项有实质延展；另一分享主题没有在强目标版本上再次实推，不将其计作已通过内容验收。独立请求队列执行约 19.28 秒，这是未缓存推理耗时，不是题目切换耗时。
- 记忆使用：真实模型曾在存在无关候选资料时整题独立构思，也生成过引用与原创混合的题目；最后的延展题为 1 项真实引用加 3 项独立建议。引用证明来源，不证明建议效果。历史不合格输出与一次未经支持的效果数字保留在评估记录中，不计作通过证据。

## 边界

并发准备利用用户阅读和作答时间隐藏等待；本地模型只有一个执行槽时，实际推理仍会排队。多题数量由任务需要决定，不以固定题数充当完整性证明。模型仍可能需要有界重写，首题或未准备好题目仍可能等待。

使用合成需求、合成资料和临时会话完成自动作答验证，原用户会话仅做只读一致性检查。未进行 DMG 打包、提交或推送。
