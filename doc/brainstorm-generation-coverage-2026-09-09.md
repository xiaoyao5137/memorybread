# 脑暴生成后的暂停与选择承接修复

会话 `4f640312`，历史记录 155。诊断和验收均保留原会话、原始需求、简报、答案、当前问题与原正文。

当前结论：生成后暂停、完整选择承接及相关回归已通过验证；真实长文已经包含全部 33 项选择，但独立内容审查仍有 12 项部分覆盖，不能宣称本次生成质量已全部解决，也没有将隔离试稿覆盖用户正文。

## 根因与实际证据

1. 旧“先生成一版”实现完成后主动重新显示探索阶段的原题，没有显式继续边界；截图中的问题是被重新开放的原问题，并非用户点击了继续脑暴。
2. 真实简报含 28 条决定，其中 27 条来自用户、1 条为假设；多选展开后为 33 个具体用户选择。生成输入只承接短标题摘要，未读取已选选项的说明。真实说明含样本量、分层样本数、布光角度和色温等参数，旧稿遗漏了这些参数，部分还标为待确认。
3. 直接决策区只取最近 24 条，前 4 条被剔除。本次 2,595 字的旧 Markdown 简报又回补了这些标题，因此不能称“27 项完全没有传入”；但有手改或较长简报时，回补并不可靠。
4. 原验收只设宽泛的结构、事实和参数检查，一项“结构完整”通过不能证明每个用户选择均被实质采用。旧稿 3,218 字，多个已选方向缺乏具体内容。
5. 同一探索位置曾跳过 Loop 问题，随后已明确确认，但旧通用占位仍与新确认共同进入提示。真实回放曾将已确认的流程与双指标重新写成假设。
6. 加强验收后的真实修正暴露出既有回退缺陷：明确未采用技能时仍将整个候选目录作为修正规则。本次 3 个未采用模板共 10,850 字符，包含与本轮无关的微服务、GPU 周报模板。
7. 完整选择进入提示后，本地模型的单次整篇写作及全文修正仍多次漏掉具体要求或仅列标题。运行时模型上下文为 32,768 token，日志未显示输入截断，不能简单归因于上下文窗口过小。分章写作进一步暴露出模型自行枚举归属的漏项和重复问题，因此完整性由结构化分配和程序校验保证。

## 修复

- 前端生成成功后暂停脑暴，明确点击“继续脑暴”才恢复原题。已有正文的历史恢复默认暂停，允许直接提交文档修改要求；失败继续保留原题和重试入口。
- 新 `creation/brief_context.py` 提供全部有效决定的统一视图。仅按有效历史题中已提交的选项 ID 读取标签与说明，保留多选、自定义输入、人工更正和清空；未选项、失效分支、当前问题和资料依据不作为已确认输入。禁用历史资料时沿用现有净化规则。
- 写作完整保留有效选择和参数，不再裁剪到最近 24 项或每项 320 字；整体超过既有安全容量明确返回错误，不带缺失上下文继续生成。其他冗长上下文不能把简报挤出提示。
- 整篇生成由程序为每个用户选择补上稳定的独立验收 ID，写作、修复、验收使用同一组条件。重复选择可合并落实，但不能仅以标题提及替代。假设、排除和未答项不升级为确认事实；局部修改和只读回答不增加全文重写要求。
- 策略选择须展开执行步骤、输入、产物与验证方法；纯参数选择不重复要求整套流程。参数保留适用对象与验证变量，经验与目标不能升级为实证。用户授权方案设计时允许提出具体新安排，并与已实现的事实区分。
- 超过 8 个具体选择时分组审核；来源审查也按每批最多 8 组直接原文分开执行，每组恰好覆盖一次，通用验收条件只在首批运行。各批均读取完整正文与输入；所有选择含尾组均须返回，任一失败保留到聚合结果。数值证据校验拒绝“理由声称正文含已选数值、正文实际未出现”的通过结论。该校验只核数值存在性，不证明单位、归属或全部语义；歧义表达保持未知。
- 同稳定维度、父问题及探索层级的通用跳过占位，若有后续用户明确确认，在有效视图中标记为被取代，并停止回灌旧渲染简报。具体假设、细分未决事项和原始数据均保留。
- 旧断点从已保存简报重建版本 3 的选择视图，并撤销过时的宽泛验收缓存。保持冻结的其他材料和原有两次修正上限。
- 修正只读取实际应用回执或路由/准入/显式选择，空选择不回退到候选目录；尚无选择记录的旧调用保留原兼容语义。
- 明确整篇生成（包括重新生成已有草稿）超过 8 项具体确认且未采用专用 Skill 时，将选择分配到章节，逐章承接完整标签与说明，同时保留其他全部确认选择的简洁原文作为跨章边界，按顺序汇集全文再验收。规划使用短别名、每个选择必填的归属对象，程序恢复稳定 ID 并拆分超量章节，不能靠丢弃条目满足每章容量。普通局部修改、变换和专用 Skill 保持原范围。
- 各章完成后保存预览和断点；临时失败保留失败章节供恢复，不能跳过。章节修正同时承接当前审核、作用域有效的多处独立问题及本轮正文质检意见；原因去重不能删掉不同的原文定位。当前仍判失败的选择继续进入其主归属章，即使先写的其他章已经删除旧引用，也不能据此视为该选择已通过；一般历史问题和已通过项继续过滤。每次重写独立递增轮次，禁止新旧章混合。外部模型续跑接受断点可精确重组的预览，仍拒绝人工修改基线。主循环后的修正同样实际执行新增章节并验收。
- 同一来源报告的审计与逐项判断相互矛盾时，先沿用原有两次格式校验；若两次均为已精确绑定的同类内部冲突，再进行一次独立的指定条件复核。复核保留原始来源和已确认选择，不能自动相信先前的通过或失败；未知、引用错误和不完整回复仍明确拒绝。Markdown 加粗和中英文间空格仅可在指定原文行内唯一恢复，不能跨行、改写含义或借用同文旧段。分组保留原始 diff 字符区间，避免多处相同文字时重新查找而错认改动位置；已用重复旧句与新增同句的反例独立复验。

## 真实模型验收边界

使用原操作冻结快照在内存隔离会话回放生产写作与审核入口，不写入用户数据库，不回答原问题，也不改用其他模型。回放从原写作步骤开始；新的输入评估和路由覆盖由自动回归验证，不能称整条新建会话链路真实重跑。

- 第一候选 2,519 字符：模型审核返回通过，但人工发现缺失“每类 100 条”、审核将正文的 1,000 条当作该项证据，已拒绝交付。新增数值校验只读回放旧报告，准确拒绝这一错误通过。
- 第二候选 4,252 字符：已带入主要数字，但人工仍发现策略展开不足、旧占位复活及事实强度失真。通用审核还出现逐字证据绑定错误，保留记录并停止该隔离回放，不能计为通过。
- 第三次回放确实逐组核对 33 项，识别只复述策略、缺失参数等问题并触发重新成文，但修正暴露出候选技能污染，候选仍不合格，已拒绝。
- 第四次回放严格比较前 7 次调用的 system/user 提示、schema 和输出预算与第三次实测记录完全一致后复用其结果，从已修复的重新成文入口开始调用真实模型。它验证修正与后续验收，不宣称整轮模型重新生成。
- 第四次重新成文已去除未采用技能，但仍只输出 2,356 字符，遗漏参数和方向展开，已拒绝交付。
- 第五次分章规划的两次真实回复分别出现重复归属及超量、遗漏归属，程序均拒绝，未将不完整计划用于写作。随后改为每个选择必填的归属对象，并由程序拆分超量主题。
