# 悬浮球图片咨询与多图历史修复

## 现场与复现

- 最近一条已有咨询是本机 `rag_sessions.id=140`，时间 2026-09-06 13:56:12。文字回答已保存，但 `user_query` 是意图改写后的查询，且记录没有上传图片引用。未改动该旧记录。
- 旧上传入口允许 8 MiB 文件，却把完整 Base64 填入 `/api/rag/stream`；现场向正在运行的接口发送 2,100,102 字节的合成附件请求，收到 HTTP 413 `length limit exceeded`。这复现了上传提问失败，但不等同于原生进程崩溃证据。
- Core 的 RAG 请求类型原先没有 `attachments`、`manual_instruction`，会丢弃前端这些字段；Sidecar 仅在存在 `screenshot_path` 时添加悬浮咨询上下文。云端记录构造同样没有附件字段。
- 原流程在生成成功后才保存记录，客户端云端保存还可能静默吞掉失败。
- 进一步检查 macOS Unified Log：13:55:49 和 13:56:18 两个 WebView 同时出现 MainFrameLoadStarted/Completed，前后桌面 PID 90013、WebContent PID 90406/90464 保持不变。Vite 日志在完全相同时间记录 `page reload src/__tests__/RagPanelHistory.test.tsx`。因此现场有明确的开发服务器整页刷新事件，导致悬浮球内存状态重置；不是已证实的原生进程退出。

## 已实现

- 异步桌面命令顺序保存附件原件并识别图片文字，避免在主线程执行文件/OCR 工作。图片咨询仅传文件引用与 OCR 文本，不通过咨询 HTTP 接口搬运 Base64。
- 悬浮球支持多选、粘贴、最多 6 个附件、单文件 8 MiB、明确数量错误、逐个移除；读取期间禁止提交，保留图片重试。
- 每张图片旁显示 28×28 缩略图，原图预览支持点击关闭、关闭按钮、Esc 和焦点恢复。Esc 仅关闭预览，不收起悬浮面板。
- 历史列表和打开后的咨询页统一展示图片；历史多图单独一行并换行。原件读取失败时显示明确提示。
- 先建立记录，再调用模型；云端、本地、失败路径更新同一个编号。原问题、图片与失败结果保留；Sidecar 可在客户端关闭后回写结果。
- 图片历史引用加入过期清理保护。创作页原有附件元数据传输保持兼容。
- Vite 开发服务器排除测试目录、测试文件及 Tauri 文件，避免测试修改刷新正在使用的咨询窗口；Vitest test 模式继续监听测试文件。
