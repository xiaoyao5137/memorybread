## 用户、场景与目标

受影响用户是在本机使用咨询、创作 Agent 与前置脑暴的用户。用户目前只能看加载状态、等待完整题目或重试，无法区分排队、资料处理、模型生成与保存。

典型场景包括：第一次提出较长方案需求；继续已有脑暴分支；修改简报后重新生成下一题；在咨询与创作之间比较等待；取消、刷新或切换会话后恢复任务。

目标：

- 缩短脑暴实际重复处理的输入，同时保持历史证据、当前用户意图与结构校验的正确性。
- 让三类交互的总耗时、首个有用结果、排队与模型处理指标具备一致定义。
- 在首题尚未完成时显示真实阶段，使用户知道请求仍在推进。
- 用配对基准证明优化收益，用已有安全与业务用例证明没有把旧资料错误当成当前决定。

## 范围、授权状态与非目标

| 工作项 | 本轮授权与状态 | 本文关系 |
| --- | --- | --- |

| 交互/定时创作的优先级入口区分 | 已授权实施；新增 `execution_origin` 区分交互与定时来源，定时走 P2 | 基准必须按来源分别记录，定时经同一 Agent API 不能自动获得交互优先级 |
| 脑暴输入压缩、稳定前缀、会话内可失效复用、联合生成试验 | 本轮仅形成待评审方案 | 本文主体；不修改运行代码 |
| 咨询/创作/脑暴耗时契约与阶段展示 | 本轮仅形成待评审方案 | 本文主体；不修改 UI |
| 约 61 秒静默连接断开修复 | 已有独立验收记录 | 作为可靠性基线保留 |

非目标：更换模型或硬件、提高输出长度上限、删除证据核对以换取低延迟、代用户回答脑暴问题、批量重写历史会话、跨会话共享私有上下文缓存、为本任务打包 DMG。本方案不改变供应商与密钥的客户端边界，不承诺任何绝对秒数 SLA。

依赖：Core/Sidecar/前端的版本兼容；运行时可用的模型计数器；权限与来源版本可验证；统一队列能够提供真实排队区间。依赖不可用时必须降级为明确的缺失值，不能推测结果。

入口边界：`execution_origin` 由真正的交互或调度入口确定，并由 Core 转发，不能仅凭使用 `/agent/run` 就认定为交互请求。历史/旧版本请求缺失该字段时的兼容默认值、调度入口显式赋值、非法取值拒绝和优先级映射，随已授权实现单独回归。本文的 `request_id`、计时与基准标签必须保留实际来源，不能把定时工作混入交互等待分布。

## 候选方案与推荐决策

| 方案 | 处理方式 | 收益来源 | 主要风险 | 建议 |
| --- | --- | --- | --- | --- |
| A：一次联合结构化生成 | 一次输入返回候选历史承接、覆盖判断与下一题；程序再次校验引用及状态 | 有机会只处理一份上下文并减少一次调用 | 同一个生成结果同时决定历史事实和提问方向，错误承接可能联动跳过应问维度；一处结构失败可能重做整个结果 | 先作为隔离评估方案，质量和重试成本过门槛后再决定是否进入用户路径 |
| B：保留核对，程序生成紧凑证据包 | 核对只看相关维度与必要证据；首题只看已验证事实及本轮问题需要的证据；共享原文索引留在程序内 | 减少重复正文、重复元数据、与当前目标无关的输入 | 压缩不当会丢失否定、时效或冲突上下文 | 第一阶段推荐；保留两步责任边界，以证据完整性约束压缩 |
| C：稳定前缀与会话内可失效复用 | 稳定规则/结构顺序；同会话、同版本与同权限下复用检索或核对结果 | 降低可避免的预填充或重复核对工作 | 运行时未必复用前缀；缓存失效遗漏会把旧决定带回当前会话 | 在 B 后分开启用并独立测量；缓存命中不作为正确性依赖 |

推荐渐进次序：统一观测契约 → B → C 的稳定前缀 → C 的会话复用 → 评估 A。每一切片都有独立开关、对照组与回滚路径，避免同时改动后无法归因。

### B：紧凑证据包

检索仍由当前需求与当前分支确定。程序先建立本轮唯一证据索引，包含来源标识、来源版本、原文定位、必要逐字摘录及冲突/时效信息；原始材料与权限由现有本地存储治理。模型引用短证据 ID，最终引用展示由程序映射回原文。

历史核对包按当前尚未确定的维度组织证据，只发送需要核对的材料。首题包发送当前意图、排除约束、已验证的承接事实、当前提问目标及支撑选项的必要证据，不再次附上完整来源正文和核对时重复的元数据。原文索引保留在程序侧，供证据校验和折叠依据展示。

压缩必须保留“未决定”“已取消”等否定关系、来源冲突、时间范围与量值单位，不能把未提供证据的维度视为已确认。确定性提取无法保留含义时，保留足够原文或明确未核对，不再调用额外摘要模型抵消收益。预算按模型上下文和证据角色配置，不按某一业务主题写死字段或场景分支。

### C：稳定前缀与复用

稳定前缀只包含版本化规则、结构契约和排序稳定的共享证据。日期、请求 ID、当前操作和可变状态放在适当的动态区段，当前用户意图仍保留其最高优先级语义。核对与首题承担不同职责，不为了前缀完全相同而混淆 system 指令。前缀复用是运行时机会优化，即使实际命中为零也必须返回相同合法结果。

会话复用采用分层键：检索快照以会话、检索输入、资料版本与权限范围为键；历史核对结果额外绑定用户输入修订号、简报、有效决策路径、撤销/排除约束、覆盖与 Skill 版本、模型与提示契约版本。任何一个依赖无法可靠校验时不复用。可见权限与来源是否仍存在，每次取用前重新检查；不能仅靠 TTL 证明有效。

修改当前简报、回溯/撤销答案、禁止读取本地记忆、来源更新/删除、切换会话、Skill 或契约变化均触发相关层失效。新分支允许复用不变的原始检索快照，但必须重新核对与当前意图相关的承接关系。刷新已有完成题目直接恢复持久化状态，不把“缓存命中”变成再次生成。

### A：联合生成的进入条件

联合输出中的历史承接只能是候选，程序仍必须检查本轮证据存在、逐字定位、权限、冲突/撤销、覆盖状态与当前简报优先级；模型不得任意决定哪些必问维度已经完成。无有效证据时不得跳过维度。若无法证明合并后的语义核对达到基线，不进入用户路径。

隔离评估需计入完整 JSON 失败后的重试成本，以及回退 B 时已经消耗的时间；不能只统计联合生成成功样本。不可通过放宽校验、删除历史误承接用例或提高不相关资料容忍度获得通过。

## 需求

下述要求描述待评审后的目标行为，文中的“必须”不表示本轮已实现。

- **FR-001** — 每轮脑暴必须由程序生成具备唯一证据 ID 的本轮证据包，模型输出的历史依据只能绑定该包内可验证原文。
- **FR-002** — 首题生成输入必须避免重复传入已由证据包表达的完整来源正文；缺失必要语义时必须保留原文或标记未核对。
- **FR-003** — 历史承接必须继续服从当前简报、撤销、排除、来源时效、冲突与权限检查。
- **FR-004** — 会话复用必须仅在全部依赖版本和权限均有效时返回结果；失效时按正常流程重新检索或核对。
- **FR-005** — 稳定前缀优化必须在缓存未命中或运行时不支持复用时保持相同业务结果契约。
- **FR-006** — 联合生成必须经过独立开关与质量门槛后才可进入用户路径，候选结果必须经过现有证据及状态校验。
- **FR-007** — 咨询、直接创作和脑暴必须按本文同一计时契约提供总耗时、首个有用结果、排队及模型处理信息。
- **FR-008** — 首个有用结果必须满足对应功能的可读/可操作交付条件，保活、状态文案、空 token 和内部 JSON 不得触发该指标。
- **FR-009** — 等待中的页面必须显示后端确认的当前阶段及已等待时间，不得凭计时器推测已完成阶段或虚构进度百分比。
- **FR-010** — 脑暴题目必须在完整结构校验和持久化成功后才可展示为可作答结果。
- **FR-011** — 失败、取消、连接中断、重试与恢复必须保留各自终态和时间范围，已有部分答案不得被标为完成结果。
- **FR-012** — 历史记录必须兼容缺失计时字段；无法确认范围的旧数字必须显示为范围未知的历史耗时。
- **FR-013** — 每次重试必须保留独立尝试标识，父级交互耗时必须覆盖其实际等待范围，不能只显示最后一次成功尝试。

- **NFR-001** — 优化必须通过现有脑暴证据、意图优先级、撤销/回溯、权限、结构、恢复及取消用例，不得删减失败断言以通过。
- **NFR-002** — 日志和普通遥测必须仅包含标识、阶段、计数、版本、耗时与安全错误码，不得包含用户需求、证据正文、模型输出或供应商密钥。
- **NFR-003** — 性能结论必须来自同输入、同模型配置、同机器条件的配对样本，并分别报告队列负载、冷热状态、输入处理量、输出长度和重试数。
- **NFR-004** — 发布门槛必须同时满足业务质量基线与可归因的性能收益；只有首个状态更早出现不能作为模型性能优化通过的依据。
- **NFR-005** — 新增运行时 Python 代码必须兼容 Python 3.9，UI 必须沿用桌面客户端当前设计系统。
- **NFR-006** — 计时必须使用各自进程的单调时钟计算区间；缺失与不支持值必须为 `null`，不得伪装成零毫秒。

## 接口与耗时契约

先制定版本化共享契约，再实现兼容的 Sidecar/Core，最后由前端消费。建议事件增加可选 `timing` 对象与阶段字段；本文字段为评审草案，命名最终在契约切片固定，旧字段在迁移期保留原语义。

| 指标 | 起止与含义 | 展示与持久化规则 |
| --- | --- | --- |
| `client_total_elapsed_ms` | 同一用户操作在客户端提交至成功终态展示；失败/取消则到对应终态可见 | 新 UI 的“总耗时”。包含客户端网络等待与渲染；由客户端单调时钟产生，可随完成确认保存。恢复历史时不把打开页面的耗时加进去。 |
| `server_total_elapsed_ms` | Core 接受请求至经过校验和保存的终态可发出 | 服务端权威处理计时。客户端计时缺失时显示“服务处理耗时”，不冒充点击到显示的总耗时。 |
| `first_useful_elapsed_ms` | 客户端提交至首次把合格有用结果展示给用户 | 咨询为非空可读答案片段；直接创作为实际文档片段/有效修改预览；脑暴为已保存、可作答题目或可操作的 ready 结果。 |
| `queue_wait_ms` | 请求及子模型工作处于实际等待队列的区间并集 | 展示“排队”；单任务嵌套上报不得重复计入。子任务若并行，应报告并集和受阻关键路径。 |
| `model_active_wall_ms` | 请求内模型实际处理区间在同一服务端时间基准上的并集 | 展示“模型处理”，表示墙钟占用；与检索或其他任务重叠时不得直接相加得到总耗时。 |
| `model_prefill_ms` / `model_decode_ms` | 每次模型调用从运行时计数器取得的输入处理/输出生成时间；请求级可给累计工作量 | 详情展示“读取输入”“生成输出”；多任务累计值标“累计”。这两个累计值不等于并发墙钟占用。 |
| `prompt_tokens` / `processed_prompt_tokens` / `output_tokens` | 逻辑输入长度、实际处理的输入量、输出量；按运行时明确语义记录 | 在诊断详情使用。未知实际处理量时不由输入总量推测，不用字符估计冒充真实 token 计数。 |
| `retrieval_ms` / `validation_ms` / `persist_ms` | 各对应阶段的实际区间 | 用于详情和定位；并发重叠时标识重叠，不默认相加。 |

`timing` 同时携带版本、业务交互 ID、请求/尝试 ID、阶段 ID、父阶段 ID、终态及是否完整采集。事件用序号去重。跨进程通过 trace 关联，各进程上报持续时长和阶段相对偏移；不能直接相减不同进程的单调时钟值。服务端落库与客户端“结果已显示”确认分开：确认消息只补充客户端计时，失败不得撤销已经保存的业务结果。

示例边界：两个并行模型任务各处理 10 秒，重叠 8 秒，则累计模型工作量为 20 秒，模型墙钟为 12 秒；界面不能显示成“模型占了 20 秒，因此总耗时至少 20 秒”。若无法可靠计算并集，墙钟值为缺失，仅展示已知累计工作量并标注。

首个有用结果只表示首次可读/可操作内容，不能代替最终完成。咨询/创作流式片段可能在后续校验中被替换或生成失败，仍保留首次有用结果时间，终态必须标失败或未完成。现有正文/引用校验不因该指标提前失效。

### 面向用户的文案

| 状态 | 建议主文案 | 详情或约束 |
| --- | --- | --- |
| 尚未获准执行 | 等待本地模型 · 已等待 12 秒 | 只展示真实排队；数字随本次操作等待增长 |
| 资料阶段 | 正在查找相关资料 | 用户禁止检索时显示“已按你的要求跳过资料检索” |
| 历史核对 | 正在核对历史信息与当前要求 | 此阶段真实存在时展示；联合路径不可伪装成独立核对已完成 |
| 问题生成 | 正在整理下一道问题 | 不显示不完整选项，不声称问题已保存 |
| 校验/保存 | 正在检查并保存本轮结果 | 原题和已有简报继续可见；只禁用会造成重复提交的动作 |
| 正常完成 | 总耗时 78 秒 · 首个可用结果 78 秒 | 示例仅说明格式；详情可展开排队、模型处理与其他阶段 |
| 流式进行中 | 正在生成答案 / 正在生成文档 | 有用片段到达后显示内容；状态事件本身不算“首字” |
| 取消 | 已取消，已保留此前完成的内容 | 有本轮片段时明确本轮未完成；不将取消显示为成功 |
| 可恢复失败 | 本轮未完成，已保留输入和此前进度 | 附现有安全错误原因与重试入口；失败不清空原始需求 |
| 恢复历史 | 已恢复上次结果 | 展示原请求耗时；本次读取缓存时间不替代历史生成耗时 |

不默认给预计剩余时间，不展示模型供应商名、底层协议字段或预填充术语。技术计数仅放诊断详情；普通用户详情将 prefill 称作“读取输入”。阶段变化沿用现有状态可访问性机制，不对每秒计时更新反复读屏播报。

## 状态、权限与失败恢复

状态流转为已提交 → 排队 → 执行阶段 → 校验 → 保存 → 完成；执行阶段可并行或跳过，由实际事件决定。失败与取消可以从任一非终态进入。连接断开只证明客户端没有得到终态，不能直接推断服务端失败或成功；恢复时查询持久化状态再决定是否可重试。

只允许当前会话和当前请求的事件更新 UI。旧请求迟到的阶段、部分结果或 completed 不得覆盖用户已切换的会话；revision 冲突沿用现有状态机处理。重复终态事件不能再次保存题目、增加 revision 或重置计时。

检索无命中、检索失败、核对不确定必须各自保留状态。无命中时可按用户需求提出新推演，但不得伪造历史支撑；核对不确定时不跳过相应维度。资料中的指令仍是数据。用户撤销资料权限时，在复用入口和生成前都应阻断旧证据再次使用；保留已由用户确认的当前输入要与已撤销的历史证据明确区分。

重试建立新 attempt；自动重试与自动回退继续留在同一交互追踪中，保留此前取消、失败与耗时。用户在终态后手动点击重试建立关联原交互的新交互，不把两次点击之间的用户思考时间算入新交互的服务等待。成功恢复已有结果不得发起新模型工作。取消期间若服务端已持久化成功但客户端未知，恢复应显示该真实结果及其终态，不能产生第二道题。

## 观测、基准与性能决策

- **OBS-001** — 为每个用户交互建立请求、尝试与阶段追踪，记录排队区间、阶段耗时、终态和完整采集标志，用于分辨排队改善与模型改善；不记录正文。
- **OBS-002** — 每次模型调用记录输入总量、实际处理量、输出量、prefill/decode、调用次数、重试数和缓存状态，用于证明重复处理是否下降；运行时不支持的字段保持缺失。
- **OBS-003** — 客户端记录总耗时、首个有用结果与终态显示时点，关联后端 trace，用于解释用户体感；结果已保存但未收到客户端确认单独标注，不伪造显示成功。
- **OBS-004** — 记录引用校验拒绝、历史错误承接、撤销/权限失效、结构失败、缓存失效和回退结果，用于阻止以质量损失换取时间下降；普通日志只有安全分类与计数。
- **OBS-005** — 报告排队、模型并集墙钟、模型累计工作量及并发重叠标识，用于避免重复计时；不能跨不兼容计时版本直接计算趋势。

基准先冻结当前可靠版本、模型与生成设置、机器/内存状态、资料快照及原始输入。覆盖长资料首题、短资料首题、无命中、当前输入否定历史、来源冲突、连续分支、简报修订、撤销权限、旧会话恢复及截断/结构重试。

先用每类至少三次配对运行筛查错误与方差；用于对外报告优化收益时，每个关键负载分组至少收集 30 对完整尝试，并保留全部失败/重试。真实用户样本在隔离评估会话运行，不能替用户作答或推进原会话。咨询和直接创作使用各自固定任务衡量改变前后，不把不同工作负载混作模型速度排行榜。

区分空闲队列、后台负载、冷模型/冷前缀、暖模型/暖前缀，报告样本量、p50、p95 及配对差值区间；小样本 p95 只作描述，不能据此宣称稳定分位 SLA。核对与首题的语义质量按同一固定断言及人工标注样例评估。联合方案额外检查未通过校验后整个回退链路的总时间。

建议发布决策门槛：安全与业务正确性用例无退步；不含外部队列影响的配对执行耗时中位数改善且 95% 配对置信区间不跨零；端到端与首个有用结果的尾部等待没有可信的退化迹象。无足够数据判定时继续隔离评估，不把状态展示改善称作模型加速。绝对秒数目标和允许的统计容差属于下一次评审决策，不从这一条历史样本外推。

## 风险与缓解

| 风险 | 后果 | 缓解与剩余不确定性 |
| --- | --- | --- |
| 紧凑证据遗漏限定语 | 把旧计划误当当前事实 | 原文定位、否定/时效/冲突样例、无法确定时保留原文；仍需真实语义评估 |
| 会话复用失效漏项 | 用户撤销后仍引用旧资料 | 分层依赖键、每次权限复核、未知版本不命中；缺少稳定来源版本前不开放该层 |

| 阶段耗时重叠或旧字段误读 | 误判模型慢、错误宣传提速 | 明确钟域、并集/累计、旧记录未知范围与采集完整性 |
| 增加观测或缓存造成开销 | 优化抵消、私有信息扩大暴露面 | 观测切片独立测量，允许字段限制，缓存只限本会话且可清除 |
