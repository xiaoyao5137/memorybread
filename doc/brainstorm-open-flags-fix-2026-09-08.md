# 脑暴已确认决定与开放事项提示修复

2026-09-08。最新创作记录 154 的脑暴状态为 ready、revision=2。两题均保存为 source=user，选择分别是“分步拆解”和“必须包含合规审查”，没有未答的 current_question。

## 原因

模型在 open_flags 中写入了一条可选深化建议：“后续可细化具体执行步骤或技术选型，但不影响当前方案主体方向”。原模型示例鼓励 ready 状态在该字段保存后续细化事项，而页面直接将 open_flags 的长度拼成“其余 N 项将作为开放假设保留”，使补充建议看起来像未确认的答案。

另一个同源统计问题是 answered_count 实际统计已处理的回答轮数，其中包括跳过后形成的 agent_assumption 和主动排除的 user_excluded，不能全部称为用户已确认决定。

## 修复

- 主卡与简报编辑器共享统计规则，按有效 decisions.source 分别显示用户决定、合理假设和排除约束；人工清空的摘要不计入已确认数。
- 主卡单独展示已确认数量，并在“待决定与补充”下逐条展示 open_flags 原文，用户能够看到具体是哪项内容，不再推断为漏答或自动采用的假设。
- 新模型提示要求 open_flags 只列具体尚未确定的事项；泛泛的继续深化建议放在 continuation_directions；没有具体未定事项时返回空数组。
- 旧会话保留原始答案、补充内容及用户修订，不按中文关键词过滤或迁移存档。共享契约已同步。
