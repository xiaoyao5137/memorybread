# 咨询附件契约

咨询支持最多 6 个附件，单个最多 8 MiB。图片原件保存在本机；咨询请求与新咨询历史不携带 Base64 原图。

`attachments` 为有序数组，每项为 `{ id, name, type, size, path }`。路径由桌面命令 `save_consultation_attachment` 生成，不能使用浏览器临时 URL 作为持久引用。旧记录的 `data_url` 仍可预览。

`POST /api/rag/history` 接受可选 `id`：省略时创建，指定时更新同一条记录的回答、上下文、模型、耗时。不存在的记录不静默新建。客户端先保存已提交记录，再调用模型；失败时更新同一编号。`POST /api/rag/stream` 的 `history_id`、`manual_instruction`、`attachments` 由 Core 转交 Sidecar，Sidecar 生成结束时更新该记录，以防客户端关闭后丢失结果。

附件存放在 `floating-screenshots`；历史上下文的 `attachments[].path` 与既有 `screenshot_path` 都受引用保护，不能作为过期缓存清理。移除待发送附件不删除已被历史引用的原件。

图像咨询目前使用图片 OCR 文字辅助本地/云端文本模型。未识别到文字时明确说明上下文不足，不声称已经理解图形、颜色等视觉细节。原图预览始终使用完整原件。

前台咨询 OCR 按文字框纵向位置恢复行顺序，同一行按横向位置排列并用 ` | ` 分隔文字框，避免识别器按列输出导致对象与数值错配。坐标缺失时保留原顺序；不补造未识别的单元格、曲线数值或表头。多张图片的 OCR 必须保留各自图片名称及边界；数字结论须同时匹配材料对象、指标、单位和基线。

材料分析对复合指标表头（如 avg/P95）添加逐项字段对照，保留图号、层级、对象、指标、单位和原读数。仅在表头与读数有唯一顺序对应时展开；缺列、歧义或粘连部分不得猜值，也不得把曲线轴刻度转成统计数据。材料明确声明基线且对象、图号、层级及指标一致时，可按原值补充升降方向；不重新计算或覆盖原表百分比。原始 OCR 保留供核对。

图片在加入咨询时分配“图片1、图片2……”名称，写入现有 `name` 字段，附件 ID 与原图路径保持不变。当前会话内移除图片不重排编号，追加图片继续递增；清空会话重置编号。非图片附件保留原文件名。旧历史中的文件名仅在展示时转换。

主咨询与悬浮球咨询输入 `@` 可选择当前附件中的图片，支持鼠标、上下方向键、Enter/Tab 确认和 Escape 关闭；中文输入法确认不选择候选或发送。输入中的 `@图片N` 和发送的附件名称、对应 OCR 文本使用相同编号。
