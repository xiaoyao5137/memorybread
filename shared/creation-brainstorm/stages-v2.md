# 三阶段脑暴契约（v2）

## 内容决定准备契约 17（新会话）

没有已选 Skill 的新建三阶段会话，每个阶段先准备本次文档的内容决定题。已有已选 Skill 的新会话保留 v16 可信目录路径，直到 Skill 政策能以新内容题契约严格绑定。旧会话保留原准备版本、问题树、已答选择、人工修订、关联操作及正文；不会因新契约自动重选、清空或覆盖。固定属性值目录、可信 Skill 方法目录及默认行文编译器继续用于其原来受保护的路径，不能把旧原子根节点当成新内容题解析。

内容题由一个有界批次生成完整平面题池（0 至 4 题），保存后才开始作答；0 题仅在全部本次内容决定已有可靠依据、独立审查确认无新增决定时允许。内容题仍是候选，推荐不等于确认，用户多选、自定义、跳过、排除与人工修订沿用原状态语义。每题仅处理一个本次任务对象和一个尚未决定、会改变正文的内容问题。方向问主体问题、对象或可选路线；细节承接已确认方向及周期，问具体机制、数值口径、执行约束、证据缺口和验证办法；行文问真实内容的论点与证据对应或缺口表述。表达属性和段落润色可由用户另行要求，但不得替代内容决定。

用户选择内容题的某个方案后，其完整说明以“用户选择的条件做法”进入有效决定、简报和章节写作输入；方案说明不是资料核验结果。人工修订的简报优先于原选项说明，清空或失效的决定不得重新进入写作输入。内容题的证明绑定题干、选项及正文作用；准备契约 17 不接受 `repair_candidate_copy` 改写候选文案。

Sidecar 批次 `kind=content_questions` 返回 `{questions,content_proofs,no_new_decision_reason}`。每个非空题有同 ID 的内部证明 `{question_id,anchor_source,anchor_quote,document_effect,option_effects}`：`anchor_source` 只能是 `root_request`、`user_decision` 或 `manual_edit`；`anchor_quote` 必须是本次原指令、有效用户答案／补充输入或当前人工修订的逐字片段。它定位提问对象，不把未选候选、历史资料、自动发现但未选 Skill 或模型建议变成用户事实。`document_effect` 说明答案会改变的正文位置或内容决定，`option_effects` 与全部选项按原序一一对应并且各有不同结果。Sidecar 先让模型输出紧凑候选，再由程序编译完整题包；程序核对完整引用、长度、题目与选项数量、唯一 ID、平面结构、推荐项、输入身份和保存状态。独立审查逐题核对本次性、可答性、选项作用、已确认取舍及事实边界。任一未知或拒绝都不能发布，不得用泛化风格题填空。内部证明随阶段持久化并从公开响应移除；公开阶段可显示 `content_no_new_decision_reason`，说明经核查没有新内容题的原因。

资料预检在细节阶段优先运行：已确认的周期、已选 Skill 的来源要求与实际收据进入内容题上下文。`matched` 只表示预检匹配，候选、部分、缺失、失败、跳过以及旧资料都不能独立证明本期数值或成果。无有效本期依据时，问题应具体询问可核对的对象、原始值、统计周期、来源定位或用户希望的缺口处理；候选选项可提出补证方式，但不得提供虚构的结果供确认。行文阶段即使没有新的表达选择，也不得将资料缺口等同于成品已可交付。交付检查继续独立核实正文与来源。

章节运行时，Core 从同一持久会话构造给 Sidecar 的私有 `creation_brief.content_source_gap`：仅对三阶段均为准备契约 17、没有已选 Skill、报告周期有保存的用户答案时提供。该字段包含契约版本、已确认周期，以及细节阶段预检的来源需求 ID、名称和状态；公开脑暴响应仍不携带预检原始收据。Sidecar 必须逐个对照同一简报中的保存题目和用户答案，确认每项来源需求都选择了与该周期完全一致的“标明缺口先成稿”，才能进入全缺口草稿模式。此模式的检索候选只作定位线索，不进入写作事实视图；流式原始正文不得向页面发布，新章节只能输出目标周期、逐项资料缺口与待核数据。若已生成的候选含未经核实的事实，交付核验前须撤回新增正文并保留此前已完成正文，最终交付再次核对同一安全正文。旧 v16 和 Skill 章节沿用各自既有证据契约。

版本 17 对明确的计算资源成本优化报告增加账单费用、资源用量、利用率／措施记录三个独立资料目标，沿用原预检收据和来源确认题；任一来源命中不能替代其余目标，也不能证明记录里的数值或节省结论。没有已选 Skill 的其他题材仍由任务专属内容题和原交付门禁约束，不凭通用关键词强加这三个目标。旧版本的资料需求不受影响。

用户修订或清空已经确认的报告周期、来源决定时，当前细节阶段的全部内容题及其已答选择、未答候选和证明都进入归档，预检和后续阶段重新准备。不能把建立在旧周期或旧来源上的内容选择保留在有效简报中；已完成的旧正文与历史记录保留为历史，不把它们当作新周期的事实。

Core 以每阶段独立的 `content_mode` 标志区分新路径；旧阶段缺此标志时按其已保存版本处理。新题批次按 `session_id`、阶段、完整有效决定、人工修订、所选 Skill、周期和预检状态形成稳定输入身份，并由原 CAS／generation ID 拒绝迟到批次。方向和细节只发布本阶段完整题池；行文另创建一个真实正文容器，题目归属该容器并按现有章节确认与交付流程运行。保护中的旧原子检查点仍用原目录字节及原 value ledger 验证，不能因新路径回落为自由问题或重算用户答案。

本契约适用于主创作流程新建的 `workflow_version: 2` 会话。既有会话和局部选区脑暴继续读取原有状态，不迁移或改写历史答案。v2 与旧契约冲突时，以本文件为准。

## 用户流程

1. **创作方向脑暴**（`direction`）：围绕本次创作的主体方向，先批量准备完整候选思路树，再由用户逐题确认。
2. **创作细节脑暴**（`detail`）：以上一阶段已确认决定和人工修订为输入，批量准备各细分方向的完整候选树，再由用户确认。
3. **创作行文脑暴**（`writing`）：依据前两阶段的结果规划章节，预先生成全部章节的设计题与下钻选项。逐章回答、确认、执行通用 Agent Loop 创作和交付检查，完成一章后进入下一章。

每阶段的候选树在进入作答前必须完整生成、校验并持久化。作答仅在已保存树上导航，不执行即时模型推理。候选、未选分支和未来章节均不是用户决定。自定义答案保存为用户输入，不伪造与某个候选分支的匹配；后续阶段生成时承接该输入。

## Core API

沿用 `POST /api/creation/brainstorm/turn`。新流程启动请求附 `workflow_version: 2`，旧请求保持兼容。新增动作：

| action | 行为 |
| --- | --- |
| `status` | 返回持久进度；工作进程重启后可恢复尚未完成的批次 |
| `retry_stage` | 重试失败阶段尚未保存的批次 |
| `repair_candidate_copy` | 以版本锁与预期旧值原子修订尚未确认候选的选项标签或提问说明，保留原文修订记录，不生成新题或作答 |
| `confirm_stage` | 当前阶段问题确认完毕后，启动下一阶段 |
| `confirm_chapter` | 携带 `chapter_id`，确认当前章设计并取得稳定的 `instruction_id` |
| `chapter_completed` | 携带 `chapter_id`，由服务端验证对应 Agent 操作及正文后进入下一章 |

现有 `answer`、`skip`、`exclude` 等动作仍受乐观版本锁和当前问题身份约束。思考阶段立即返回状态，不依赖浏览器保持长连接。离开页面只停止前端查询，后台继续生成；终止会话使迟到结果失效。

候选文案维护请求附 `candidate_copy_patches: [{question_id, option_id?, field: "label" | "why_now", expected_text, text}]`，每次 1 至 16 项。`label` 必须提供选项 ID，最多 24 字；`why_now` 不提供选项 ID，最多 80 字。同一目标不得重复，预期旧值必须与当前存储相同，且仅可修订当前待回答阶段尚未确认、没有已回答后代的候选。文本必须简短完整，标签不与同题其他标签重复；有下钻题时新标签仍须满足原条件锚点校验。问题与选项 ID、父子关系、来源、选项说明、推荐状态、用户答案、阶段进度、生成身份与正文均不变。全部验证成功后才提交，失败不得部分写入。`stage_workflow.copy_repair_history` 追加版本、目标、字段及新旧文本，保留修订前证据；该记录不是用户决定。

响应保留 `current_question`、`history`、`decisions`、`brief_markdown` 等现有字段，新增可选字段：

```text
stage_workflow: {
  version: 2,
  active_stage: "direction" | "detail" | "writing",
  stages: [{
    id, title,
    status: "pending" | "thinking" | "answering" | "ready" | "completed" | "failed",
    generation_id,
    questions: BrainstormQuestion[],
    progress: {
      completed_batches, total_batches, percent,
      started_at_ms, updated_at_ms,
      estimated_remaining_seconds: number | null
    },
    error?: {code, message, retryable},
    preparation_progress?: {topic_title, saved_nodes, pending_nodes},
    recovery_progress?: {attempt, max_attempts, retry_at_ms}
  }],
  chapters: [{
    id, title, goal,
    status: "pending" | "answering" | "ready" | "writing" | "completed",
    question_ids: string[], instruction_id?, operation_id?
  }],
  active_chapter_id?
}
```

顶层 `phase` 可为 `preparing`、`exploring`、`ready`、`chapter_writing`、`completed` 或 `abandoned`。阶段状态是阶段导航和思考提示的依据；顶层阶段不能替代逐章交付状态。

历史列表与单条历史接口另返回可选的轻量字段，不加载完整候选树：

```text
brainstorm_stage_summary: {
  version: 2, phase, active_stage, stage_status,
  completed_chapters, total_chapters, active_chapter_title?
}
```

摘要从持久化脑暴会话读取，供历史列表显示思考中、待确认、章节创作中及完成进度。章节操作的 `lifecycle_status`、`goal` 和正文仍保留真实操作终态；第一章交付完成不等于整个三阶段会话完成。旧历史或旧服务没有摘要时，客户端继续兼容既有字段。

## 模型批次

### 技能包可信方法目录（准备契约 7）

安装的规范技能可在 `references/brainstorm-catalog.json` 配置目录。Core 按已选技能的稳定 key 重载本地规范记录，要求技能仍安装、未删除，并以规范 `references/memorybread-creation.json` 原始解码字节的 SHA256 绑定写作 profile；profile 中的描述与执行步骤须与记录一致。前端或模型提交的任意目录不是可信入口。目录身份、版本、原始内容 SHA256 与完整权威输入共同进入准备指纹。Sidecar 另从只读规范记录验证同一身份，失配或无效目录明确拒绝；不能回落为自由生成并继承旧检查点。

目录 schema 1：`{schema_version, kind: "memorybread.brainstorm-catalog", catalog_id, catalog_version, skill_key, skill_profile_sha256, stages}`。每个配置阶段含 `topics` 与 `slots`；主题含 `{id,title,goal,root_slot_ids}`，槽含 `{id,topic_id,object_id,choice_axis,required_fields,prompt_body,why_now,methods}`，方法含 `{id,object_id,required_fields,label,description,tradeoff,child_slot_ids}`。同槽全部方法必须绑定同一对象和相同必需字段，仅提出不同实施方法；方法不是用户答案。字段严格校验，未知字段、ID、跨主题子槽、循环、共享子槽、重复题干、超出完整树预算或不完整分支均拒绝。第一版没有可写政策参数；新增能力须明确扩展 schema。

有目录的阶段由程序编译主题、根槽、问题、选项和后续槽，真实祖先前提继续由既有程序绑定，问题 ID 与树仍按原协议校验和原子发布。静态题目为可自定义的单选题；`single_choice_reason` 固定为“各方法服务同一对象，请选择一种实施方式”，`answer_template` 固定为“补充你的具体实施方法。”。方法顺序决定默认推荐顺序，推荐不是用户确认；标签与说明直接取目录，选项 `details` 保留完整取舍，`context_details` 与 `memory_brief` 为空。节点内部目标以 `catalog_slot:<id>` 精确绑定目录槽，不能按自然语言标题猜测；实际题干仍显示完整方法问题和真实祖先条件。目录不用候选或用户未选分支授权资料读取，不将模板示例当历史事实；当前静态目录不调用模型或检索。所有已确认决定、人工修订、清空与排除原样只读继承。静态目录继续执行有效确认题与完整复用已选规则的既有程序排重检查；命中时明确拒绝，不让模型改写目录规避约束。规则、周期、必需内容、计算公式和缺失动作没有生成写入口；候选问题仍由用户真实作答。未配置目录时，默认行文采用下述表达能力编译器，其他阶段采用逐节点模型准备与独立检查；所有路径共用阶段截止、取消和 CAS。

当前准备契约版本为 16（可信目录始于版本 7）。未回答且未受保护的阶段切换到目录时，完整旧规划、题池与进度进入内部准备归档，再从目录创建新的 manifest；不按旧主题标题、序号或模型语义推断槽绑定。旧节点检查点完整追加为 `contract_changed` 归档，不覆盖此前归档链。目录同版本内容变化也使旧输入指纹失效并归档。已回答、已人工修订或有关联操作的阶段仍受原保护，不自动改写。目录与内部绑定、快照、归档不暴露给公开响应。完成状态依然要求整个真实候选树全部保存，不产生确认或正文。

版本 11 将候选事实权威绑定当前需求。准备契约 7 至当前版本之前的自由生成阶段，在未回答、没有候选人工修订或受保护章节/操作时，完整旧 manifest、题池、进度、错误与恢复快照进入 `generator_contract_changed` 准备归档，当前检查点完整进入 `contract_changed` 归档，再清空活动规划从 `plan` 重建。仅归档检查点不能复用旧主题或历史事实目标。此前归档链、恢复审计、其他阶段、原需求、技能、确认和人工输入逐字段保持；升级幂等，不能重做用户已确认的阶段或覆盖正文。

版本 12 将完整所选 Skill 的政策检查覆盖到所有自由生成阶段，方向和细节候选也不得缩小 Skill 必需内容或范围；不得只在行文阶段检查后再继承早期无效规划。版本 11 已保存但未确认的自由生成规划和检查点按上述相同保护与完整归档契约重建，不作为已验收前缀复用。完整 Skill 检查和可信局部目标范围判断是独立门禁，任何模型通过都不代替实际候选内容验收。

### 逐节点准备与检查点

版本 13 将自由方向／细节的根规划绑定到程序持有的属性能力注册表 `shared/creation-brainstorm/root-axes-v1.json`。方向阶段适用受众对象、表达目的、内容重点、叙事视角和语气；细节阶段可在完整已确认方向内选择局部信息粒度、概念解释深度、论据呈现、结构次序、节奏、行动实施方式等已实现属性。既定字段、周期、事实、材料权限、必需内容及固定方法不成为可投票属性；受众目标不预设单一阅读对象。能力是有限的明确声明，不承诺任意自然语言属性的语义独立或全部创作场景覆盖。自定义完整可信目录仍使用原独立接口。

注册表 schema 1 包含 `kind/registry_id/registry_version/axes`；当前 registry 版本 4，顶层另含 `value_capabilities_sha256`，每轴包含 `id/property/title/definition/goal/stages/decision_mode/value_ids`，已实现属性的模式精确为 `atomic`。标题和模式也是已实现能力的精确声明，不能由配置改写。配置只允许选择、排序既有精确能力及缩小其支持阶段，不能自由新增 ID、别名、属性定义或目标文字。扩展新能力需要实现、契约和回归同步更新。默认构建使用共享 JSON 原字节；可通过服务端配置 `MEMORYBREAD_BRAINSTORM_ROOT_AXES_PATH` 选择经过相同严格校验的文件。Core 和 Sidecar 以实际原字节 SHA-256 核验独立内部 `root_axes_binding: {config_sha256, config}`，不借用完整目录绑定。该绑定进入未答自由阶段全部准备请求、输入指纹和保存快照；变更只能以 CAS 提交，迟到旧配置产物不得保存。

版本 14 将自由方向／细节的 `plan` 与 `topic_plan` 绑定到同一完整属性选择。供应商 `plan` 只输出有序 `axis_ids`，ID 解码限定为当前阶段真实适用能力；未知、同属性重复、额外字段、空集合或预算越界整批拒绝，不补造、合并或裁掉属性。程序采用 `min(max_topics, 属性数)` 个主题，保持原属性顺序均匀分组：前 `余数` 组为 `整商+1` 个，其余为 `整商` 个。每组不超过真实 `root_limit`，标题以能力中文标题用“与”连接且最多 60 字，目标以完整 canonical goal 用“；”连接且最多 240 字；超限整批拒绝，不截断标题、目标或分支。

编译主题内部为 `{id: topic_axis_1..., title, goal, root_axis_ids}`，主题 ordinal 从 1 开始；全阶段每个属性只属于一个主题，根目标的对象不能脱离主题职责。自由计划章节为空，待决定事项保留当前 `brief_edits.open_flags` 的原始非空行，模型不能新增、重写或恢复已清空的事项。Core 对真实计划回复精确重编译整个清单及每条完整目标后才持久化，并将编译 manifest 绑定检查点输入身份。

自由 `topic_plan` 不再调用第二次模型选择根；程序从当前已编译主题的 `root_axis_ids` 完整绑定原序 canonical goal，继续返回既有 `root_goals: string[]`。缺少／伪造主题证明、标题或目标改变、跨主题扩展到其它合法属性、重复或删减原组均拒绝；Core 精确核验根 ID 只能是该主题自己的完整选择。新主题和根仍是未确认候选，不升级为用户权威。计划与程序生成根继续进入全部原权威、固定规则、Skill 政策及范围语义门禁，不能使用完整可信目录的免模型旁路来规避检查。后续自由节点、资料检索和全部节点门禁保持。

版本 13 已使属性身份程序化，但其自由主题与二次根选择仍可能产生范围漂移；未答版本 13 清单、题池、检查点、错误及恢复额度完整进入原归档链后，再从版本 14 `plan` 重建。不会从旧主题文字抽取、改写或合并属性，也不把旧模型审查通过当作主题职责有效证明。旧本地 direct apply_batch 完整 questions 适配保留；版本 14 自由方向／细节的真实准备入口拒绝完整 questions 回包，防止旧协议绕过当前主题和根证明。受保护版本 12／13／14 及目录、行文原路径保持。旧本地适配不能作为新供应商选择 ID 与主题编译协议的验收证据。

未受保护的版本 12 自由规划首次进入版本 13 时，按完整 manifest／题池／进度／错误／恢复和检查点归档契约重新规划，不能复用任意旧自由根。随后即使版本号不变，注册表原字节身份变化也完整归档该阶段全部未答池和检查点，并从 `plan` 重建。已答、已编辑、已修候选文案、已有正文或操作的阶段保留原快照与全部历史；实际兼容的受保护版本 12／13／14 已保存节点可在原可信根与原输入身份下继续，不强塞新配置或重新编译根，节点／只读审查请求可省略新绑定，仍执行全部原节点门禁。无法安全新规划的保护记录保留并明确失败，不自动覆盖。完整可信目录及默认行文编译器继续原旁路。`root_axes_binding`、选择 ID、配置哈希及全部内部归档只用于恢复，公开阶段响应与简报不呈现执行元数据，主题中的 `root_axis_ids` 同样移除。

版本 15 将注册属性视为一个原子决定：每个所选属性只生成一道终端题，根题的多个选项不会凭默认两层深度再创造子目标。自由方向／细节计划的 `root_limit` 等于 `max_questions_per_topic`；每个完整主题仍保存全部原序属性，不删根、不硬限制为一根。节点选项预算沿用原上限，原子节点 `max_next_goals=0`。目录、默认行文及受保护旧树仍采用各自完整子树预算和分支门禁。

新检查点冻结 `atomic_root_questions=true`，但布尔值本身不能授权终端模式。Core 从契约版本 15、完整属性绑定、当前主题的原序 ID、逐字 canonical goal、根 ID ordinal、深度 1、无父关系及全部已存根／待存根覆盖重新证明模式；Sidecar 从本地同字节注册表和完整 manifest 独立重算。内部节点请求携带 `node_mode: {kind: "root_axis_atomic", axis_id, node_id}`，精确绑定当前真实根，不把证明包交给生成模型。`node_mode` 在全局为可选以兼容旧节点，但携带当前自由属性新绑定的 node 必须同时提供完整模式证明；遗漏模式或给正后续预算企图回落旧树，在任何检索、生成或审查调用前拒绝。旧受保护节点省略新绑定和模式，不能把新配置错包当作旧入口。模型任务与独立审查接收真实属性、定义、目标和模式，只提出该原子属性自己的选项值，全部原事实、资料引用、Skill、范围、确认和决定空间门禁继续执行。未知或伪造证明、错误深度、父条件或非空后续目标均拒绝，不部分保存。原子主题全部根题通过后才原子发布，不能把空后续目标当作任意旧树免检条件。

版本 14 的原子属性曾被强制展开成自由子树，真实候选越出所属属性且含无依据的当前事实前提，即使模型审查通过也不能验收。未答版本 14 的完整 manifest、问题、检查点、错误与恢复额度先按原完整归档契约保存，再从版本 15 重规划；旧检查点默认 false 字段不序列化，原始历史归档不凭新增字段改写。受保护版本 14 续跑保留原编译 manifest 输入键，版本 12／13 保留其真实旧输入结构，不伪造不存在的历史键。受保护版本 15 发生当前配置身份变化时明确失败并保留进度，不省略模式或新绑定悄悄回落为旧树；未答版本 15 仍先完整归档再编译新配置。

版本 16 将原子问题的表达文本也绑定到有限属性值能力。不可配置路径的共享 `attribute-values-v1.json` 定义已实现的 `atomic_values_v1` renderer、11 个属性的完整固定题面与 47 个有限值；Core 嵌入实际原字节，Sidecar 读取已安装资源，配置不能提供另一份能力快照或任意替换文本。注册表的 `value_capabilities_sha256` 必须等于实际能力文件 SHA，`value_ids` 只能按原能力顺序选择该轴至少两个真实值，不能给别轴值、别名、重复值或自由说明。扩展能力需受治理资源及两端构建、契约、测试同步更新；有限值不是任意创作场景的覆盖保证。

供应商在该模式只输出 `{options:[{value_id,recommended,memory_choice}]}`，每项精确三个字段，2 至真实选项上限且恰一布尔推荐。题型、题干正文、提问目的、补充提示、单选理由、选项标签和说明由程序从实际能力完整渲染，不接收自由文案、字段用途或后续目标。当前注册值均可组合，能力题型明确为多选；类型仍由可信能力定义，不能由供应商判断或切换。选项 ID 按供应商原序绑定，推荐排序移动整项并保留 ID、值与来源选择；推荐仍不是用户确认。

内部 node 回复保留 `question/next_goals/memory_brief` 并附 `root_value_selection:{options:[...]}` 原始完整选择，公开 API 不呈现该字段。Core 根据当前模式证明、真实属性和完整闭包重渲染，逐字段核对全部固定文字、题型、topic 维度、required／allow_custom、每个选项 ID 与推荐绑定；缺证明、改字、错轴、未知或重复值、类型伪造、额外自由字段及任何子目标整题拒绝，不通过删除或改写字段修复。固定能力文案不走自由 copy repair。来源提示、完整引文和检索结果仍由原 Sidecar 权限、引用、事实与全部 Skill／范围／决定空间门禁校验；Core 的固定文案证明不冒充检索来源真实性证明。

新检查点保存按真实 node_id 顺序的 `root_value_selections`，重启和下一节点派发前重新渲染全部已存根的实际问题；不能只信布尔值或从标签猜 ID。空 ledger 不序列化，版本 15 原始 `atomic_root_questions=true` 及不存在 ledger 的结构原样归档。未答版本 15 完整题池、manifest、检查点、错误、恢复和旧绑定先保存到原链，再从版本 16 规划。已受保护的版本 15 是原子路径，不能以低于当前版本为由退回通用树；当前能力闭包无法验证其旧快照时明确失败保留进度。版本 12–14 的原树与真实输入身份保持原有兼容边界。模式、能力哈希、值 ID 和 ledger 均不暴露给用户 API 或简报，全部有效用户输入和正文保持。

三阶段使用同一准备协议。阶段 `plan` 一次准备主题，默认行文由程序保留完整正文内容单元；尚未完成的主题先调用 `topic_plan` 得到有界的独立 `root_goals`，再调用 `node` 逐题准备。默认行文节点的题型、题干正文、说明、完整选项及每个后续目标由表达能力编译器生成，不调用模型自由拟题。自然语言的单选说明和补充提示由程序根据题型提供；程序将每个实际非叶选项完整绑定到组织能力的下一深度，叶节点不展开。自由原子根每个选项的 `next_goals` 必须为空，其它模型树阶段保持原契约，继续输出各选项必要的 `next_goals`；问题 ID、父题／父选项绑定与执行元数据由程序确定。非行文规划的 `chapter_id` 解码限定为空串。

内部请求增加 `context_id` 与 `node`（稳定题 ID、目标、深度、可信父题／选项条件及当前剩余预算）；`topic_plan` 返回 `root_goals: string[]`，`node` 返回 `{question, next_goals: [{option_id, goals: string[]}], memory_brief?, root_value_selection?}`。每项目标最多 80 字。程序证明的原子根也是终端节点，与配置的旧树最大深度无关，后续目标必须为空；其它叶节点的后续目标必须为空，其它非叶节点每个选项都必须有后续目标。根数量、每个条件的独立问题数量与选项数量由真实主题和配置预算决定，不固定为一根或两个选项。当前节点和剩余 frontier 在最小完整展开后也须满足问题数／深度限制，不能删除有效节点或分支来适配预算。

`topic_plan` 与 `node` 共用当前任务边界：最终 `generation_task` 携带完整 `selected_topic`、当前目标和所有可信父条件，其他主题仅携带 `id/title` 排除摘要。全部已确认决定继续作为约束，不作为重新讨论需求、受众、周期或其他主题的任务。根目标可以少于预算上限，不为填满数量重复已确认需求。

节点模型内部输出 `prompt_body`；程序根据所有祖先的真实选项标签添加固定条件前缀，API 仍输出完整 `question.prompt`。正文预算为题干上限减去实际前缀长度。正文须有效且非空，预算不足明确拒绝；不得截断、修改父条件或删除分支。原始正文在添加前缀前先与已有题干排重，完整题干继续接受长度、重复、引用和可读性校验。定点改写只修正文，条件前缀保持原样。

其它自由树节点的供应商内部输出只有 `question`；当前有限原子值节点按版本 16 只输出上述 primitive。其它自由树节点中，每个 `question.options[i]` 携带该选项自己的 `next_goals: string[]`；不输出顶层后续目标数组或选项序号。非叶选项的目标数组至少一项，叶选项的数组必须为空；嵌套解码保留这些界限。程序按模型原始选项顺序派生 `option_index`，将组内目标规范化为内部扁平 `{option_index, goal}`，校验每个实际选项覆盖、组内重复及全部分支目标总数，再转换成既有 API 的 `next_goals: [{option_id, goals}]`；推荐排序不改变绑定。每组解码上限可使用当前总预算，实际全部分支之和仍严格受 `max_next_goals` 约束，允许不均衡分配，不按组均分预算。后续目标不得完整重复当前可信 `node.goal`；调用方提供明确的祖先目标 `parent_goal` 时也检查该目标，不从显示题干猜测执行目标。未知字段、无效组或预算越界整题拒绝并有界重新生成，不补造目标、截断内容或删除分支。目录与程序绑定行文的目标编译契约保持。此供应商解码表示变化不改变公共 API、检查点的已绑定问题／frontier 或版本 12 的输入身份，保留当前有效规划并从尚未通过的节点继续。

Core 在当前 `Stage` 的可选 `topic_checkpoint` 保存主题身份、固定构建身份、输入指纹、准备契约版本、已验收问题和待准备 frontier。当前 `preparation_contract_version=16`、根属性配置快照与已编译主题清单纳入输入指纹；节点检查点同时保存经程序核验的原子模式。每次仅提交一个已校验节点；超时或修订失败保留当前契约的检查点，下次继续尚未通过的节点。当前契约的已发布题目、用户答案与已完成批次保持不变。旧题池按下述升级核验恢复。检查点缺失的旧 v2 会话从当前未完成主题开始；准备契约、输入、确认决定、人工修订或资料权限变化不得继承旧检查点。失效检查点完整保存在内部 `topic_checkpoint_archives`，含原因、归档时间与原检查点，随后重新规划未发布主题。载入思考中的旧检查点也先通过 CAS 保存归档并更新工作身份，再调度当前主题，防止旧工作迟到覆盖。工作进程仍受会话 revision 与 generation 约束。

检查点节点不参与用户回答、阶段确认或章节绑定。整个主题全部准备并通过原有完整树、父引用、循环、深度及全阶段排重校验后，才原子并入 `stage.questions`、增加主题完成批次并清除该检查点。阶段完整准备之后才显示 100%。响应移除当前检查点与归档，只呈现 `preparation_progress: {topic_title, saved_nodes, pending_nodes}` 的安全进度摘要，不向页面重复发送内部 frontier 或源材料。`pending_nodes` 是当前待准备目标数，展开中间节点后可能增长；它不冒充最终问题总数或阶段完成率。

准备契约 11 的 `plan` 与 `topic_plan` 只读取当前根需求、人工修订、全部有效用户确认和所选 Skill，不执行历史召回。规划只安排尚未决定的对象与方法，不能从旧报告、历史候选或示例预填本次受众、周期、参数和成果。实际问题节点仍按原权限执行来源召回和引用检查。规划审查使用独立的短规则，保留完整当前权威与 Skill 政策，不把候选规划当作事实来源。

自由后续目标的固定规则比较只在存在有效 `answer_source=user` 决定时启用；空确认集合由程序绑定为 `future_fixed=not_applicable`，不能解释成资料缺失。真实排除、父路径、清空约束、根需求与事实仍独立检查；已有有效用户确认时继续严格比较并保留未知阻断。未知反馈只携带实际程序单元 ID 与有限事实字段，不能补造确认或事实来消除未知。

同一可信输入上下文可复用有界、短期的召回快照，键同时绑定确认输入、修订、资料权限与 `context_id`；不以候选题目或用户尚未选择的分支授权检索。缓存失效或进程重启可以重新检索，但不能重做已保存节点。生成模型保留唯一完整 `confirmed_context` 与 `brief_edits`，任务中的固定决定、清空约束和根需求以程序决定 ID、上下文索引／字段路径及当前来源状态引用，避免再次复制全部确认正文；人工修订仍指向当前实际文字。独立检查请求另行保留完整权威一份。权限与缓存键继续读取完整原始输入，不采用最近若干条替代所有约束。日志只记录阶段、步骤、耗时、数量及缓存命中，不记录用户答案、材料或模型输出。

默认行文的新节点由通用表达能力编译器生成。有限策略只安排当前章节新增的解释与转承文字；数据、计算、来源、图表、证据清单及其内部次序和位置、交付载体均不属于可写范围。题干、完整选项和每条子路径由同一能力及实际祖先条件编译，模型不能输出行为文案或新增数据操作。编译证明绑定完整当前权威、所选Skill、章职责、实际节点和能力配置，并精确重编译核对实际候选；它证明来源及结构，不冒充任意自然语言政策的兼容性证明。实际候选仍接受原有全部权威、Skill、范围与新颖性语义门禁。既有自由文案和用户输入不凭编译标识免检。

默认编译的子方案必须明确细化真实父方案内部的新增文字槽，不能仅声明“沿用父方案”再独立替换整段布局。选项说明和题干按完整真实祖先与对应槽位生成；表达IR将子操作嵌入父操作的空文字槽，重复的组或依据连接分别按实际位置处理。逐层移除后代细化后，每个祖先的完整节点及次序必须与原产物精确一致；外部原文档保持原样。未识别、缺层、错绑定或已占用的槽位拒绝执行。该IR只证明拟议新增文字的组合，不证明自然语言政策兼容、实际正文写作或交付完成；当前题干与全部选项继续接受原自然语言父条件和全量权威检查。

仅修改未接受子节点的细化实现、完整已接受根产物与权威输入不变时，保留当前契约、计划、根节点检查点和真实待完成分支。针对已耗尽的历史会话，明确授权的`retry_stage`开启一次新的有界运行，会重置本轮自动恢复计数；修复验收必须保留重试前完整状态、旧额度与恢复记录、源码及运行时指纹、实际请求和响应，不得将显式重试说成旧额度从未重置。新运行内自动续跑仍使用持久化共享额度和CAS，不能通过反复显式重试无限延长。

章节的正文职责与组织能力是不同类型，`chapter.goal` 不得直接复用程序组织能力的执行任务。默认行文计划直接由程序将完整当前需求和有效确认内容绑定到一个正文创作容器，不调用模型自由拆章。容器保留需求及所选Skill规定的原有分节、必需内容、方法和证据位置，不重新拆分内容所有权，不把图下、表后或条目证据迁移到新章节，也不代用户确认组织方案；页面可呈现一个写作单元，正文内部已有章、节及内容安排保持。它仍通过原计划验证、完整权威与Skill一致性门禁，然后准备完整组织题树。可信已安装Skill目录继续使用其独立配置契约。鉴权、本地输入错误、取消和未恢复的模型服务错误不通过此方式伪装成功。全部调用共用原步骤截止，不重置时间；未通过的容器不能发布。

正文指令及交付核验按真实单元数量区分范围。只有一个单元时，完整有效用户决定属于本轮成文与核验范围，原始标题及内部分节由有效需求和Skill决定，不强制将页面单元名写成正文标题；人工修订、清空与排除仍从当前简报重新绑定。多单元沿用本章已确认设计与各章责任边界，不能要求每章重复全篇。

新节点的运行时选项上限 `MEMORYBREAD_BRAINSTORM_WRITING_MAX_OPTIONS` 合法范围2至5，默认2，并与Core当前实际节点预算取较小值；能力目录可提供少于上限的完整方法集合，上限不是填满要求。超限整题拒绝，不能切片。上限仅作用于尚未生成的新题，已保存问题和分支、只读审查、静态目录和其它阶段不降。默认编译节点没有模型生成或文案改写调用；语义门禁仍使用原有共享截止。

单步沿用当前阶段的共享截止（默认 210 秒及 Core 的 30 秒传输余量），含排队、检索、生成及小修。保留的自由模型节点工具最多两次生成；常规节点使用 2400 输出 token 包络，包含大量独立子目标时按结构预算计算、最多 4000，两次尝试保持同一包络，不在失败后翻倍。默认行文节点不执行该自由生成重试，仅编译完整候选并通过全部独立门禁。每次只恢复当前未通过节点，不以提高整树 token 上限或重做已保存兄弟节点恢复。

准备契约 6 在每个 `topic_plan`／`node` 候选返回前增加独立、有界的一致性检查。依据有效用户决定、人工修订、排除约束和原始需求，检查当前主题、真实祖先条件、全部根目标，或修复后实际问题的全部选项与后续目标；不能只检查推荐项。已确认取舍必须作为固定前提，允许在其约束下细化尚未确认的实现，不得重开选择、改变主题或否定路径条件。候选、假设与引用不构成新的用户决定或检索权限。检查只读取给定内容，不另行检索或使用工具。

程序为全部根目标、题干、每个选项及每个后续目标枚举稳定审查单元。独立范围检查按最多 8 个单元与实际UTF8证据输出包络分组，每组最多 4000 token，必须按程序单元 ID 逐项返回证据绑定的有限事实；结果缺项、重复、额外单元、矛盾或无效均拒绝，不能以整池一个总判定替代覆盖。每项保留所属主题、真实祖先和该题其他选项的语境。当前有效用户确认的完整问题指纹与候选题干重复时，由程序直接拒绝重新提问；不把已清空、排除或假设当作确认题。候选全部选项完整标签都连续包含于同一有效用户已选标签，且说明与该已选说明存在任一方向的完整字段包含关系时，直接拒绝重新提问；规范化只处理空白和字母大小写，保留标点、否定与数值，不跨不同选项拼接匹配。这包括旧说明外加用途包装。新增机制需以清晰新标签或未整段复用旧规则的实质说明辨识。不把人工修订前选项当权威，不因仅标签相同而拒绝实质不同的新实现。每个选项保留真实匹配决定的证据引用。每道题另有有限的决定空间证书，按真实选项身份完整核验其关系，区分新实现与复用既定方案、把共同固定规则拆成竞争选择、重开既定取舍或没有真实新自由度；不能把两个须共同遵守的确认决定包装为互斥方案。证据逐字绑定当前完整选项标签与有效行为字段，角色与实际固定决定引用采用有限role_binding，程序解析为内部role/fixed_id。所有实际选项都必须是同一尚未确认选择轴的新方法；整体关系不能覆盖坏单项，未知、无效或矛盾结果均阻断。

每条完整真实固定规则与每个实际选项都进入兼容矩阵，分批最多12条规则，并按完整最坏输出包络缩小批次至最多4000 token；输入完整实际题干、选项标签、说明与取舍，并绑定完整权威快照和本批规则。四个有限事实检查增量是否新增原动作前提、换掉原动作、排除原必需内容或范围、替换已确认方法或优先级。比较的是候选方法合并到仍保留的原写作政策后有无变化，不把资料是否已取得或执行结果是否发生混入政策比较。上级载体内尚未固定的局部说明不自动等于更换该载体，局部新增细节也不能免除真实已确认的内部方法。少复述旧动作不等于取消，候选自称保留不掩盖实际替换；unknown仍阻断。实际yes单元进入独立证据绑定复核，只复核该真实规则与该实际选项，原规则证据及候选全部label、description、有效tradeoff按换行拼接的单一证据分别枚举绑定，不能选择短标题代替完整行为。误判被清除后仍继续全部剩余规则，真实变化仍拒绝并返回实际决定ID。全无变化路径不新增复核调用。

复核不检索或生成新候选，缺项、额外字段、无效值或空行为描述均阻断；与全部首轮审查、生成及文案修订共用原步骤截止。程序检查结构并拒绝模型报告出的改写；模型分类和行为判断仍可能出错，必须以真实内容验收独立核验，不以结构通过或分类字段冒充全域语义保证。

计划、节点和只读审查的内部权威完整继承全部所选Skill profile，不以有界摘要替代规则。默认行文实际问题的范围审查在完整单元证据上另判断是否提出当前组织目标之外的数据处理、计算政策或工具实现；解释已有公式或过程不等于重新执行。存在所选Skill时，完整profile列表按真实路径、严格整数数量与完整SHA绑定，调用前后校验实际源与冻结快照；每单元独立判断是否违反该写作政策。输入作为待审政策，不执行其内指令。实际yes为范围违规，unknown阻断，伪造或缺漏证据拒绝；无Skill不制造此类未知。全部新增事实继续使用原有有界批次与共享截止，整题新取舍和全部固定规则兼容不能替代Skill检查。

独立事实与关系审查使用温度0，创意候选生成保持原采样参数；稳定采样不能代替证据绑定或真实内容验收。每组仅检查一次，所有组与生成、文案修复、检索、排队共用 210 秒截止，不在换组后重置时间。任何组失败均不能保存；受控反馈进入 Sidecar 原有最多两次当前步骤生成，不增加按组重试层。Core 的额外步骤派发单独受下述持久化步骤和阶段总量限制。日志仅记录阶段、步骤、耗时、数量和受控原因，不记录用户答案或模型自由文本。

### 旧题池升级核验

旧准备契约的未回答题池在继续准备或接受首个答案前核验。已有该阶段答案、人工修订或关联创作操作的阶段保持保护，不自动替换题池。Core 根据自身稳定题 ID 的批次绑定定位主题，并从完整题池派生真实祖先条件；不依据模型维度文本猜测主题。无法可靠绑定的未回答旧池完整归档后重建。

`kind=review` API 一次最多接受 12 道旧题。Core 默认按最多 8 个审查单元切块，每题成本为题干、决定空间加实际选项数，至少包含一题，并按真实块长推进持久游标；环境变量 `MEMORYBREAD_BRAINSTORM_STAGE_REVIEW_UNIT_BUDGET` 接受 8 至 96 的整数，默认 8；预算保存在私有审查游标中，重启或配置变化不跳过题目、不重置步骤截止。使用上述有效用户约束、完整问题与选项，剥离长引用正文；不检索、不改写、不生成新题。每块的全部题干与选项按上述单元协议进行有界检查，共用 210 秒截止。通过块以内部 `review_checkpoint` 保存契约版本、输入指纹、题池指纹与下一索引；连接异常、超时或无效结果保留原池和已通过索引，重试只继续尚未通过的块。输入或题池改变必须重新核验。

全部通过后标记当前契约版本并保留原池。语义拒绝则将完整原 `questions/topics/progress`、原工作身份、拒绝代码及决定引用写入 `preparation_archives`，清空当前未回答题池并按原主题规划重建；不裁剪冲突根题及其子树，也不冒充已完成进度。资料权限撤回时 Sidecar 直接返回程序代码 `source_permission_revoked`，不调用模型或检索；Core 同时归档并清空旧主题规划，在仅用户输入上下文中重新规划，不能复用撤权前的目标文字。

`review_checkpoint`、`preparation_archives` 和节点检查点归档仅用于内部恢复与审计，公开响应全部移除。通过 CAS 更新 revision/generation 后才调度新任务，迟到的旧审查或生成结果不得覆盖当前状态。

Core 调用 `POST /creation/brainstorm/stage/batch`，每批沿用现有推理队列、取消机制和有界错误恢复：

```text
request: {
  stage: "direction" | "detail" | "writing",
  kind: "plan" | "questions" | "topic_plan" | "node" | "review",
  root_request, decisions, brief_markdown, selected_skills,
  brief_edits, user_input_revisions,
  topic?: {id, title, goal, chapter_id?},
  plan?: {topics, prepared_question_count, prepared_question_prompts, prepared_question_bodies},
  context_id?, node?,
  root_axes_binding?, node_mode?: {kind: "root_axis_atomic", axis_id, node_id},
  review_questions?: [{question, topic, ancestor_conditions}],
  limits: {max_topics, max_questions_per_topic, max_depth}
}

plan result: {
  topics: [{id, title, goal, chapter_id?}],
  chapters: [{id, title, goal}],
  memory_brief?, open_flags?
}

questions result: {questions: BrainstormQuestion[]}
review result: {review: "pass" | "reject", codes: string[], decision_ids: string[]}
```

模型先规划本阶段讨论主题（行文阶段包含章节），再逐节点保存、按主题发布完整子树。旧 `questions` 内部接口保留用于兼容旧调用方，不替换已有节点检查点。注册原子属性每根一题终止；其它自由树默认每主题两层，根题每个选项都包含下钻题，叶题的选项为本阶段的明确终点；树深、主题数量和单批大小由 Core 配置限制。阶段内容必须满足实际创作需求，不能通过静默截断题目、删除未完成分支或伪造已完成来满足限制。

每批校验父子关系、选项引用、唯一 ID、环路、树深、可读性和完整性。Core 为本阶段分配稳定唯一标识。已保存的有效批次不因后续失败而重做；重试保留用户输入和已完成批次。候选路径只表示条件假设，不进入已确认决定或资料访问授权。

后续题目批次携带本阶段规划与已准备题干的有界摘要，用于跨主题排重；这些内容单独标记为候选，不混入用户决定或事实来源。

`prepared_question_bodies` 由 Core 从已发布题目与当前检查点的可信父链派生：仅在题干以完整真实祖先前缀开头时精确移除该前缀，旧格式保留完整题干。不按正则猜测用户文字，也不把失效归档纳入当前题目排重。Sidecar 保留全量题干与正文校验，模型接收的摘要不替代该边界。

完整规划及旧题干留在 Core/Sidecar 的校验边界内，整树模型只接收当前主题完整目标和其他主题的 `id/title` 排除摘要；不将完整旧题作为可模仿示例。每次首次生成及重试的 JSON 均将当前 `generation_task` 放在最后，校验反馈不能覆盖批次主题。旧题仍由全量排重守卫拦截，仅在小文案修复需要防碰撞时进入其候选上下文。

模型内部引用字段使用 `memory_choice` 的有限枚举：`original`，或本轮真实来源的一项／两项组合（如 `reference:m1`、`reference:m1+m2`）。采纳模式与来源一起选择，避免本地紧凑 grammar 移除数组上限后生成空引用或超过两条来源。程序映射回既有引用字段并继续核验来源、原文、采纳模式与用户资料权限；未知组合、矛盾的旧字段及伪造引文均拒绝，不截断或改作原创。对旧模型合法的引用格式仍保持兼容，客户端响应格式不变。

完整候选树先展开并核验原始引用，将真实映射证据保留在候选中，避免改写抹掉矛盾声明或旧协议内联来源。超长题干、提问说明及选项文案再进入有界的定点改写：一次只返回待修字段，最多两次，全部字段通过格式、长度和明显残句校验后原子写回。未超长但带未闭合日期片段或尾部悬空连接词的当前候选也须修订；长度合规不能掩盖截断。扁平修复 schema 保留文本解码上限，全部字段上限字符合计不超过 1200；超过预算的候选须重新生成完整紧凑树。正常字段、问题和选项 ID、父子关系、引用及用户状态保持原样；不得截断文本或删分支。随后仍核验整树、来源、重复问题与最终可读性。小修复与树生成共用批次截止，不能重新取得完整预算。

同树题干因遗漏不同父选项条件而重复时，只可明确原有条件；修订题干必须保留对应父选项的完整标签。同一路径重复和重复根题仍拒绝。选项标签重复时，仅当原说明已具有不同方法或取舍才可消歧，完全相同选项不能只改名称继续发布。原候选重复既存批次题干也不能仅换措辞通过。小修写回前再次检查题干、标签与父选项条件；压缩造成的新碰撞在剩余小修次数内修订，不重做有效候选树。最后仍执行全量校验，Core 在任何状态变更前再次拒绝全阶段重复题干。

阶段批次的排队、检索、生成和有界修复共用一个截止，默认 210 秒，通过 `MEMORYBREAD_BRAINSTORM_STAGE_BATCH_TIMEOUT_SECONDS` 配置 30 至 600 的十进制整数，无效值回退默认。Core 传输上限比该截止多 30 秒；入队等待消耗的时间不能在准入后重新获得。超时必须取消模型流并释放槽位，保留已经落库的批次。旧单题流程仍使用 150 秒总预算及 180 秒传输上限。

## 真实进度与恢复

准备契约 10 的模型路径重建未确认的旧契约 7/8/9 候选与规划：仅当前阶段无答案、人工编辑或章节创作操作时，把完整旧题池、主题规划、章节计划、进度、错误及节点检查点追加归档，再重建当前阶段；此前归档链与内部恢复审计保持完整，已确认阶段与已有正文不改写。可信目录路径继续按其完整绑定恢复，受保护状态不自动替换。

内部准备归档同时保存原 `automatic_recovery` 快照，包括冻结的步骤与阶段额度、已派发次数、待完成派发标记及上次失败状态；旧归档缺少该可选字段时继续兼容读取。归档快照仅用于审计，不替换新输入的恢复策略，也不出现在公开响应。

行文规划与主题准备由程序绑定尚未确认的组织、表达或执行取舍，章节内容范围与已确认决定只作为固定约束。多章规划另需逐章验证独立主任务，不将全篇要求复制为每章正文目标；共享背景与格式继续继承。内部默认行文节点请求提供完整安全章节 `{id,title,goal}`，按真实 `topic.chapter_id` 绑定 `selected_chapter`，生成和独立范围审查均读取同一本章目标，范围证据以该完整对象的程序SHA256引用精确绑定；不能以全文背景或相似标题猜测章节身份。不能把章节内容目标直接当作待决定主题，不能重新确认已确定的时间周期、来源、指标口径或优先顺序。模型返回语义通过字符串不能代替程序绑定核验；规划、主题根目标和后续节点必须遵循同一决策范围。

默认模型门禁使用三个独立检查：每个实际选项的新取舍与整题关系、当前单元的范围与陈述事实、全部固定规则与全部实际选项的兼容矩阵。题干证据逐字绑定当前实际问题，题干角色有限区分新选择、重新确认某条真实固定决定、越出当前范围与未知；不允许先虚构一个题干不存在的自由轴再据此放行选项。每项action_span只能绑定其完整实际标签、说明及有效取舍的换行拼接；仅最坏输出确实超限时使用完整选项SHA引用，输入仍保留全部原文，索引与SHA调用前后精确校验，内部证据解回完整原文。选项角色与真实固定决定ID由一个有限 `role_binding` 枚举绑定，再由程序解析，不能输出“新方法”却同时引用已固定方法的矛盾组合。完整实际单元的 `claim_evidence` 绑定题干或选项标签、说明及有效取舍；分别判断是否声称用户已选择当前候选、条件假设已获确认、或未有当前权威依据的实际结果已发生。合法待选方案和条件路径不需要实际执行证明；用户已提供的事实仍是权威。任一违规事实为yes均拒绝，unknown、伪造或缺漏证据仍阻断，不由一个笼统claim结论覆盖其它审查。

默认行文的程序后续路径另有精确关系证明：实际组织轴、当前目标及深度上限、章节ID、完整祖先、实际选项ID和每项唯一的下一深度目标必须全部匹配，叶节点后续为空。程序标志本身不能豁免核验；缺项、重复、自由目标或错误绑定均拒绝。这些已证明的机器路径不再由模型重复猜父关系，当前问题和全部选项仍接受新取舍、具体章范围与完整固定规则检查，后续真实子问题也完整审查其父条件。其它自由后续目标继续执行原有全部语义门禁。

实际子问题的父条件审查按当前完整单元和真实有序祖先绑定独立证据；自由后续目标还绑定其真实分支选项。`preserves`只表示候选提议与全部父路径假设能够同时成立；`violates`表示候选实际替换、删除或改变父要求，或使路径条件不能成立；语义仍不充分时返回`unknown`并阻断。父条件是待选假设，不要求用户已选择、方案已执行或已有成品正文。整题范围读取全部实际选项，单选项读取完整标签、说明和取舍，不能以推荐项代替其它项。有限编译的槽位及祖先投影可作为额外结构证据，但不代替该语义判断；自由与既有祖先没有此证据时仍接受同一严格检查。

完整固定规则矩阵对每条真实规则与每个实际选项独立检查四项变化，并检查完整实际选项是否仅复述该规则的已定取舍。规则身份由程序按完整当前规则、索引与SHA绑定；模型先绑定一段当前有效原规则证据，再按固定事实顺序给每个实际选项五个整数：0表示no、1表示yes、2表示unknown，程序拒绝布尔、浮点、缺漏和额外项。事实仍逐项独立，不是一个合并通过位；证据不代替读取完整权威。被判有变化的每项具体事实另由独立、证据绑定的复核确认；不把一项误判扩大成无关事实的重新猜测。第五项重复取舍的复核及未知在所有规则的兼容检查完成后处理，避免掩盖后续真实方法冲突；仅保留原要求但新增真实组织方法不等于重复选择。独立整题新取舍门禁继续检查真实题干和全部选项，五项全0不能充当新颖性证明。误判复核只清除对应规则、选项与事实，其后所有规则仍须完整检查；真实变化、重新选择固定内容、未知或无效证据继续阻断，全部复核共享原截止。合法新方法的全无变化路径不新增复核调用。

Core 对受控的无效候选、生成超时和限流执行持久化、有界的内部恢复。默认每个准备步骤额外最多 2 次、整个阶段累计最多 8 次；`MEMORYBREAD_BRAINSTORM_STAGE_STEP_RECOVERY_LIMIT` 接受 0 至 5 的整数，`MEMORYBREAD_BRAINSTORM_STAGE_RECOVERY_LIMIT` 接受 0 至 32 的整数，无效值回退默认，0 关闭自动恢复。预算在首次调度时冻结，每次派发前通过 CAS 保存次数，重启、查询和 generation 变化不重置额度；中断后重派发同样消耗剩余额度。步骤身份由真实 plan/topic_plan/node/review 身份、可信输入和当前稳定节点计算，不含请求凭据或可变化的 generation。

模型服务暂不可用（`BRAINSTORM_MODEL_UNAVAILABLE`）单独按持久化的退避时间自动等待、重新派发，不消耗候选内容的步骤／阶段额度；退避由 2 秒增长并封顶 5 分钟，旧会话若恰在不可用错误后进入额度耗尽状态，首次 `status` 依据原恢复审计还原不可用次数和旧额度后继续同一检查点。连续不可用的私有审计记录聚合次数及最近失败时间，避免长期等待使会话状态无限增长；旧审计条目保持原样。鉴权、输入、配置、取消等终态仍不自动重试，服务恢复后若候选内容继续不合格，原内容额度照常耗尽并显示真实失败。Core 运行时持续调度；重启后访问会话的 `status` 会重新认领持久状态，无需用户点击“继续本阶段思考”。

阶段预算另绑定完整可信 `input_fingerprint`：用户有效答案、人工修订、根需求、技能或权限实际变化开启新的有界输入预算，保留旧审计；成功节点、revision、generation、状态查询和工作进程重启不刷新阶段额度。供应商路由变化或失败本身不属于新权威输入。

内部恢复只执行未通过的当前步骤，已验收节点、完整批次和用户确认保持。每次候选继续通过全部结构、引用和语义门禁，不发布被拒内容，不截断分支；鉴权、配置、输入、权限、取消和阶段冲突不自动重试。派发前本地树结构、预算或输入校验失败直接终止为 `BRAINSTORM_PREPARATION_INPUT_INVALID`，不进入模型恢复也不发出模型请求。Sidecar 每步骤原有两次候选生成及单步骤共享截止不改变，Core 的额外派发有上述独立总量上限。

内部等待或执行保持 `status=thinking`、`error` 缺省；可选 `recovery_progress` 仅返回当前额外尝试序号、最大额外尝试数和重试时间，预计剩余时间置空。页面继续展示正常准备过程，不要求用户处理可恢复失败。私有恢复状态和追加审计只保存受控错误码、状态码、时间和步骤哈希，公开响应全部移除。内容／超时／限流额度耗尽必须真实进入 `failed`，返回 `BRAINSTORM_PREPARATION_EXHAUSTED`；安全文案按实际最后失败码区分候选内容未通过检查、思考超时、服务暂不可用、请求受限或中断，不把内容检查失败归因于模型服务状态。未知错误码只返回通用的已保存进度和继续说明，不回显上游文字；不能伪造成功。用户显式 `retry_stage` 可开启新一轮有界恢复，保留此前审计、当前契约已验收检查点与全部确认内容。

百分比基于已保存并校验的批次，阶段规划未完成时不得假造完成率。只有整树校验和持久化结束才显示 100%。预计剩余时间依据已完成批次耗时估算，初期没有样本时显示“正在估算”；估计值不代表承诺时限。界面展示“创作方向／创作细节／创作行文阶段模型思考中”，动画、完成批次和等待说明可在返回会话时恢复。

持久化进度绑定会话、阶段和 `generation_id`；新任务不能被旧批次覆盖。任务去重防止查询、刷新或多个窗口重复启动模型。错误只返回安全错误码与中文信息，不保存密钥或供应商配置。

## 章节创作与交付

确认章节后，前端使用返回的稳定 `instruction_id` 调用现有 `POST /api/creation/agent/run`，附 `brainstorm_chapter_id`。Core 从持久化会话组装可信 `creation_brief`，注入：

```text
chapter_context: {
  id, title, goal, index, total,
  confirmed_decisions,
  outline: [{id, title, goal}]
}
```

脑暴开始时，`selected_skills[]` 是本会话已选写作政策的冻结快照，逐项保存完整可执行 profile、`workflowRole: primary | support` 和 `selectionSource: user | automatic | dependency`；内部 `skill_binding_version=1` 连空选择也冻结。`user` 只表示本轮原始请求中的明确 `@Skill` 匹配；模型匹配的主 Skill 是 `automatic`，随主 Skill 引入的辅助 Skill 是 `dependency`。不能把自动选择或辅助依赖改记为用户显式选择。旧会话缺少来源时，Core 只能从该会话保存的原始根请求中的字面 `@Skill标题` 与已保存主 Skill 求交推断 `user`；其余主 Skill 为 `automatic`，辅助 Skill 为 `dependency`。仅未标记冻结版本的旧动态脑暴空会话沿原兼容路径补存一次选择；新空会话不得被后续请求补选。后续页面或章节请求提交的目录只是可执行 profile 的可用性证明，不能取代会话中已保存的选择和约束。

Core 绑定章节时校验当前完整可执行 profile 与冻结快照中已有字段一致；缺失或改动返回 `BRAINSTORM_SKILL_BINDING_UNAVAILABLE`，保留会话、操作、已完成正文和冻结政策，不能静默改用别的 Skill 或普通创作。验证后，仅绑定的 Skill profile 进入本章 Agent 候选。Core 给 Sidecar 的内部 `brainstorm_skill_binding` 包含 `version: 1`、覆盖冻结 ID／角色／来源／已存 profile 与核验后完整可执行 profile 的 SHA256 `fingerprint`，以及 `skills: [{id, role, selection_source}]`。旧会话的稀疏 profile 缺少的可执行字段只能由当前安装记录补足，补足后的完整 profile 同样进入指纹，后续变动触发重路由；不能声称已追溯验证旧快照未保存的字段。Sidecar 将其中的主 Skill 作为本章固定工作流候选独立审查；审查通过后执行其声明步骤，辅助 Skill 只提供约束／依赖。审查不适用、冲突或必需资料缺失应明确呈现原因并保留可恢复状态，不得默默退为普通 `generate`。本章交付核验必须核对已采用 Skill 的步骤结果和最终正文，不以检索或工具完成收据代替内容验收。

已有章节 operation 的 checkpoint 若缺少该绑定，或指纹与当前持久化冻结绑定不一致，Core 在同一 operation 开启新的输入尝试，从路由重新执行未完成后缀；旧泛化检索、计划和正文候选不再作为本次结果。原 operation 历史、已完成章节正文、确认决定和旧 checkpoint 审计保留，不重复追加已完成章节。Sidecar 恢复时使用 Core 当前绑定，不能复用旧 checkpoint 中的候选目录、显式来源或路由结论。

本章执行现有通用 Agent Loop、正文持久化与交付检查。输入包含前两阶段有效确认、当前章设计和章节目录；未确认的未来章节题目不作为已选事实。本轮验收范围为当前章，已完成正文保留，后续章节不因本轮范围被判缺失或提前生成。

前端收到完成事件后请求 `chapter_completed`。服务端验证稳定指令对应的持久化操作、交付审核通过和保存正文；客户端声称成功不能解锁下一章。失败保留现有正文和当前章节，恢复复用原操作，不能重复追加已完成章节。单章通过不代表整篇完成，全部章节交付后流程才完成。

## 思路图与回归要求

左侧创作简报按三个阶段展示整树，包括尚未作答和未选择的完整候选分支；明显区分候选、已确认、跳过和排除。章节状态与正文预览同步。沿用可编辑简报与无障碍焦点、折叠和窄屏换行规则。

必须回归：旧会话恢复、零模型作答、所有候选分支覆盖、多选和自定义、阶段确认、按章顺序与失败恢复、后台切出返回、重复启动/过期结果/终止守卫、进度真实性、候选与已确认输入隔离、真实通用 Agent 交付和先前正文保留。
