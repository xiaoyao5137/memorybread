# 脑暴与可编辑简报契约

## 基于已回答内容先生成一版

探索中的脑暴卡片提供“先生成一版”动作，复用 `POST /api/creation/agent/run`，传入 `creation_mode=brainstorm`、当前已保存的 `creation_brief` 快照及原始 `root_request`。快照的 `phase` 可以为 `exploring`，无需先完成所有问题或调用脑暴 `finish`。已有正文时，将当前正文作为 `current_document`，基于本轮指令更新一版。

本轮创作指令明确要求基于原始需求和已提交回答先生成文档；未回答的问题、未确认选项与待补充事项不得写成用户决定，必要缺口标注待确认，不编造事实。当前卡片尚未提交的选项和输入不合并为回答，也不自动执行 `answer`、`skip` 或接受假设。Sidecar 继续使用已有简报来源规则，区分有效用户决定、明确排除、已保存假设和开放事项，并保留人工修订及资料权限。

该动作只读取脑暴快照，不推进其 `phase`、`revision`、问题或回答历史；生成成功、失败和重试都不代表脑暴收敛，原问题仍可继续回答。生成中的卡片按现有运行状态只读，成功后暂停问答，用户明确点击“继续脑暴”才恢复原题。实际成文仍遵循正常 Agent 路由、正文保存与错误恢复链路。

## 长请求传输与保活

`POST /api/creation/brainstorm/turn` 支持通过 `Accept: text/event-stream` 选择 SSE；未请求 SSE 的旧客户端继续接收原 JSON 与 HTTP 错误码。SSE 立即返回响应头及 `event: brainstorm.started`（`data: {}`），等待期间每 10 秒发送注释保活，覆盖入队、检索、生成及持久化，避免桌面 WebView 在约 60 秒无响应时关闭连接。保活只证明连接仍在等待，不表示模型已有结果。

成功仅在原状态机完成校验和持久化后发送 `event: brainstorm.completed`，数据为 `{ "state": <原 BrainstormTurnResponse> }`；失败发送 `event: brainstorm.failed`，数据保留原安全 `code` / `message` 并附原 HTTP `status`。SSE 响应头已经发送时不能再依赖 HTTP 状态区分业务失败。客户端必须消费明确的终态事件，注释、started 或提前断流均不得当作成功。主脑暴与局部脑暴共享解析器，并继续兼容旧 JSON 响应。

前台传输保持现有整轮预算与取消语义，不派生脱离请求的后台会话写入任务。取消、切换或终止会话后，旧事件不能覆盖界面；失败保留输入、已有问题与已确认版本。连接中断使用固定中文原因提示重试，不显示底层地址或原始异常。

正式生成的 `model_mode=local` 使用 Sidecar 当前注册的本地模型，不读取旧 `creation.models` 中的外部模型、凭据或地址；`external` 通过 `model.request` 交由品牌网关执行。两种模式均不向 Agent 注入历史供应商配置。生成完成必须存在非空正文，全部正文节点失败时不得返回成功。模型权限错误返回 `MODEL_ACCESS_DENIED`，不可自动重试，提示切换可用模型或检查模型权限；错误事件不得包含供应商原始响应。

问题默认 `multi_choice`；只有方向确实互斥且模型提供 `single_choice_reason` 时生成 `single_choice`。旧题型保持兼容。

## 已确认决定、假设与补充事项

`answered_count` 记录已处理的回答轮数，不是用户确认数。展示决定状态时应使用 `decisions.source`：`user` 是用户确认，`agent_assumption` 是用户跳过后保留的待核验假设，`user_excluded` 是排除约束；空白的有效摘要不计为已确认。用户人工修订后的有效来源与摘要由 Core 返回，展示层不得根据原始答案覆盖它们。

新生成的 `open_flags: string[]` 仅列出当前仍缺少答案的具体事实、条件、冲突或取舍；必须能说明什么尚未确定。已经由用户回答、人工修订或明确排除的事项不得重复列入。仅有“后续可细化执行步骤、技术选型”等可选深化建议时，使用已有 `continuation_directions`，不得为了保留继续脑暴入口而填充 `open_flags`；没有具体未定事项时返回 `[]`。`ready` 允许存在不妨碍当前成文的具体未定事项，但不能存在会推翻主方向的高影响歧义。

`open_flags` 不表示用户漏答的题目数量，也不自动授权 Agent 代为决定或把这些内容算成假设。前端按原文展示为“待决定与补充”，与已确认决定、待核验假设分别表达，不使用“其余 N 项将作为开放假设”推断二者关系。旧会话可能混有可选细化建议，保留原文供查看和编辑，不按语言关键词清除、重新归类或迁移存档，以免丢失真实风险及用户修订。

## 提问可读性与依据分层

新生成问题的 `prompt` 最多 60 字符，选项和继续方向的 `label` 最多 24 字符；`why_now` 与 `description` 最多 80 字符，仅说明本轮要确认什么、候选方向的主要取舍，不重复题干、罗列全部选项或粘贴资料。Sidecar 对超长文案执行原有预算内的有界模型重写；不能通过硬截断改变答案含义，也不能无限重试。

`BrainstormQuestion.context_details: string` 保存检索状态、承接的历史结论与来源说明；`BrainstormOption.details: string` 和 `BrainstormContinuationDirection.details: string` 保存已校验的引用、原文摘录与待验证说明。这些字段均可省略，Core 默认为空字符串，并随当前题、回答历史、归档题与继续方向保存和恢复；继续方向转成合成问题时保留 `details`。无需新增数据库列，旧会话的原始文案不被截断或重写。

前端优先展示简短题干、候选标签和取舍，长文案与资料依据默认折叠且可以展开查看。旧会话的长题干和选项也须可完整回看；长链接、连续字符和结构化原文必须在容器内换行。资料原文按层显示，不参与选项选择、不修改已选答案。`memory_brief` 继续保留已校验历史证据供简报及正文创作使用，展示层收起依据不改变创作上下文。

问题新增可选 `parent_question_id`、`parent_option_id`，由 Core 赋值，标识选项下钻关系。回答历史和当前题共同组成思路树。修改上游答案后，原有后续题失效，按新答案重建下钻关系。

## 从问题到方案与落地

`BrainstormQuestion.exploration_stage` 为可选字符串：`explore`（明确问题或方向）、`solutions`（探索解决思路与取舍）、`implementation`（细化所选方案如何执行）、`validation`（确认效果验证与失败应对）。旧题缺省按 `explore` 调度，不改写存档、答案或原会话版本。新生成问题须保存实际阶段；根题按内容选择阶段，选中分支则由 Core 指定下一阶段，Sidecar 不得靠修改阶段标签跳过实际讨论。

Core 对用户确认的单选、多选及自定义答案进行广度优先调度：先按选项展示顺序轮转同层已选方向，再进入下一层的执行安排和验证讨论。用户明确选择继续方向时，新根优先；根内仍严格按层遍历。子题存在仅说明开始展开；必须继续处理其有效选择。`validation` 的有效回答是该叶的讨论终点，不再机械分叉所有验收选项；这只表示已讨论验证方式，不表示实际执行或验证通过。跳过形成的假设与明确排除项不自动扩展。人工简报修订替代旧选项，以当前有效文本继续；清空的答案不生成分支。

Core 在会话 JSON 的内部 `branch_parent_revisions` 中记录子题生成所依据的父答案版本。人工修改父答案后，旧后代（包括修改后才收到的旧题回答）不再进入有效决定、简报或模型上下文；下一轮成功生成时移入既有 `archived_questions` 供回看。旧状态缺少版本基线且父答案已经人工修改时保守视作被覆盖。新状态不新增数据库列，失败仍不提交中间清理或推进版本。

Core→Sidecar 请求增加可选 `exploration_stage: string`，空值表示没有强制阶段；非空时必须返回该阶段的具体问题。`focus_hint` 包含当前有效的已选路径，使深层追问继续承接原问题；`decisions` 保留阶段及父节点关联。阶段约束独立于横向维度覆盖：有待展开分支时，即使背景维度已覆盖，也不能返回 `ready`，不能把继续方向列表包装成问题冒充深挖；须在原有重试与超时预算内生成合格问题。无待展开分支时再补全仍缺失的高影响背景或返回 `ready`。换方向仍可主动离开当前分支，用户随时显式结束脑暴的能力保持有效。

方案题必须由模型主动提供 2～5 个任务相关的候选解法，说明作用机制及关键收益或代价，不能只列问题、问用户还有什么问题或要求用户自己想方案。落地题承接已选解法，按任务需要比较第一步、流程、依赖、协作或资源安排；验证题比较能直接观察当前问题是否改善的试验/验收方法及必要的调整方式，间接业务指标不能代替该问题的质量验收，不虚构精确指标、排期或承诺。阶段是通用讨论语义，不把写作、活动等任务强制转换成工程实施流程，也不设置会话总题数门槛。

指定阶段时仍按权限检索资料并校验候选依据，但不重复执行全局背景维度的历史继承核对；背景覆盖不会代替这条分支的方案讨论，也不将其他子项目的背景数据附作本分支已确认结论。回到背景覆盖时再核对尚缺维度。用户仅选候选项即可推进，`answer_template` 只能邀请可选偏好或限制，不把想方案、解释机制的工作交还用户。

`POST /api/creation/brainstorm/turn` 新增 `edit_brief` 动作和 `brief_edits: Record<string,string>`。键为 `root_request`、`open_flags` 或历史题 ID；空字符串表示用户清空内容。使用现有 revision 乐观锁，失败不覆盖本地输入。返回状态新增 `brief_edits` 和 `root_request`。人工修改优先于自动摘要，后续脑暴保留修改；简报 Markdown 为最终创作消费的合成内容。原始回答历史保持可回看。

继续脑暴支持 `continuation_direction_ids: string[]`，多个方向作为多选题写入历史并逐项下钻。保留旧 `continuation_direction_id` 单值及 `__custom__` 自定义方向协议。

`archived_questions: Array<{question, answer: BrainstormAnswer | null}>` 保存回改或换方向后失效的题目和原回答。它们仍可在思路树中查看，但不参加当前分支调度或最终创作。`decisions.summary` 与 `open_flags` 返回人工修订后的有效内容；原始回答只保留在 `history` / `archived_questions` 中用于回溯。

`exclude` 动作与 `skip` 使用相同的 revision / question_id 校验，表示“该方向不重要”。Core 保存 `answer.source = user_excluded`，不记录选中项；该方向只作为排除约束传给后续脑暴与生成，不作为确认事实、合理假设或检索辅助词。不得展开、补写，也不得在文档中列出“未展开方向”。历史保留，重新回答可恢复。

## 每轮记忆依据

Sidecar 在每次 next（包括首题、分支下钻和换方向）生成前，先读取原始需求与有效用户答案中的资料范围限制。明确禁止本地/个人/历史资料或限定仅使用当前输入时，在查询分析和资料访问前跳过检索，返回 `skipped`；旧简报中的历史引用不继续作为本轮输入。模型假设与引用示例不能改变检索权限，禁止联网也不等同于禁止本地记忆。允许检索时才以原始需求及当前简报/分支召回本地记忆，限制来源数和正文预算。检索状态区分跳过、命中、未命中和失败；失败不阻断脑暴，也不得伪称命中。召回资料属于不可信参考内容，不能覆盖本轮用户修订、排除项或执行指令。

状态 JSON、脑暴返回值和 Core→Sidecar 请求新增 `user_input_revisions: Record<string,number>`，键与 `brief_edits` 相同。它记录根需求、人工简报字段和有效回答最后一次用户操作的会话 revision；新根需求为 0，回答、修订和所有继续方向（包含单选、自定义）以当前 revision + 1 与状态原子保存。重新打开或回改上游决定时，失效答案的修订记录同步删除。旧状态在下一次正常写入时一次性补齐：未编辑根需求为 0，旧回答按已有顺序，无法证明顺序的人工编辑保守使用迁移时 revision；已存在的记录以后不刷新，故后续真实用户许可可覆盖更早禁令。

权限只接受有效用户字段，按上述版本判定；同版本限制优先，无版本的旧限制不会被无法证明更新的许可覆盖。许可必须是完整、明确的直接指令，疑问、转述、条件句或模型假设不会扩大资料范围。引用内容默认是数据，只有对该具体引用明确发出的执行/遵守指令才参与资料限制。权限计算是唯一纯函数，后续成文从保存快照消费时复用同一规则。

`decisions.user_inputs: string[]` 保留同一次操作中各条直接用户输入（自定义文本及明确选中标签），避免将合并后的 summary 误当作完整授权语句。人工修改时只保留当前修改值，旧选项和旧自由文本不再授权；模型假设与排除动作不产生资料授权。继续脑暴可同时选择多个推荐方向和自定义方向，全部保存并逐项讨论，同次操作使用相同 revision，资料限制优先于同时出现的许可。

禁用时从当前根需求、用户确认答案和人工修改重建有效上下文，不从旧 Markdown 提取所谓已确认段落，不传历史题干、选项 tradeoff、模型假设或未知来源的 focus。用户明确排除的主题只作为排除范围保留，不作为事实。Core 的分支提示只带用户已选标签，`focus_hint_source` 区分 `user` / `confirmed_selection` 与旧请求的 `legacy`；自定义继续方向同时写入回答历史，使资料限制在以后轮次仍有效。原始历史仍可回看，但禁止资料时立即成文也不得重新使用旧简报引文或旧开放问题。

同一创作指令重试时，Core 将当前明确提供的 `creation_brief` 与断点中保存的简报比较；不同则使用当前文档基线和当前输入重新执行，丢弃旧断点及迟到模型结果，不复用旧资料和计划。相同简报继续断点恢复；省略简报的旧调用保留兼容。Sidecar 在任何断点缓存使用前复核该边界，防止旧恢复数据绕过当前资料限制。

历史核对器内部输出 `inherited_facts: [{dimension_id, evidence_id}]`。Sidecar 将本轮来源按顺序分成最长 240 字、重叠 40 字的连续原文片段，约束模型仅选择本轮存在的片段 ID，再映射成 `{dimension_id, memory_id, quote}` 并校验原文；兼容旧格式，混合字段矛盾时拒绝。只能承接明确、仍适用且无冲突的历史决定；片段存在不代表维度已决定，待确认、过时或相互冲突的内容不能跳过提问。问题选项及继续方向可带 `memory_evidence: [{memory_id, quote}]`，由 Sidecar 校验 ID 和原文后转为 `details` 中的来源标题、时间和摘录。无依据的候选在 `details` 标明推演，不冒充历史结论。

Sidecar 返回新增可选 `memory_brief: string`，Core 在会话 JSON 内保存（旧会话默认空），并合入简报供恢复和正文创作使用。该段是历史参考，不是用户确认答案；每轮刷新，人工修订始终优先。前端将问题说明、选项说明与资料依据分层展示，不新增必填字段或数据库列。

历史决定承接分为独立核对和问题生成两步：仅对用户尚未决定的维度核对历史事实，校验来源与原文后再计算下一待问维度。问题生成不能自行修改覆盖状态。核对不可靠时不跳过该维度。查询剔除既有历史引用段落与用户排除项，防止自我强化召回；长文按关键词选择命中窗口。

为降低本地模型抄录原文的负担，选项也支持 `memory_ids: string[]`（最多两项），由 Sidecar 从对应来源生成真实摘录。说明中明确写出的有效 `mN` 引用可兼容恢复；未知 ID、伪造的显式引文一律拒绝并重试。前端和 Core 通过 `details` 消费已校验并附有标题、日期、定位编号与原文的依据文本，不依赖模型私有字段。

## 脑暴模型错误

Core 将 Sidecar 的 `detail.code`（兼容顶层 `code`）转换成白名单内的 `{code, message, retryable}`，HTTP 状态与错误类别一致。`message` 由 Core 固定生成，不能透传模型原文、供应商响应或任意 Sidecar `message`；日志只记录状态码和已映射错误码。前端继续使用通用敏感信息过滤，无需放宽过滤规则。

| Sidecar 错误码 | Core 错误码 | HTTP | 可重试 | 用户提示 |
| --- | --- | --- | --- | --- |
| `BRAINSTORM_MODEL_OUTPUT_TRUNCATED`、旧 `CREATION_DOCUMENT_TRUNCATED` | `BRAINSTORM_MODEL_OUTPUT_TRUNCATED` | 502 | 否 | 脑暴问题生成达到长度上限，已保留当前输入，请缩小本轮讨论范围后重试 |
| `BRAINSTORM_MODEL_OUTPUT_INVALID` | 同左 | 502 | 否 | 脑暴问题未生成有效结果，已保留当前输入，请重试 |
| `MODEL_ACCESS_DENIED` | 同左 | 403 | 否 | 当前模型访问未获授权，请切换可用模型或检查模型权限后重试 |
| `MODEL_RATE_LIMITED` | 同左 | 429 | 是 | 模型服务当前繁忙，已保留当前输入，请稍后重试 |
| `MODEL_REQUEST_FAILED` | 同左 | 502 | 否 | 模型未能接受脑暴请求，请检查模型配置后重试 |
| `MODEL_TRANSPORT_UNAVAILABLE`、`MODEL_SERVICE_UNAVAILABLE`、`CREATION_UNAVAILABLE`、`BRAINSTORM_MODEL_UNAVAILABLE` | `BRAINSTORM_MODEL_UNAVAILABLE` | 503 | 是 | 脑暴问题生成服务暂时不可用，已保留当前输入，请稍后重试 |
| `BRAINSTORM_MODEL_TIMEOUT` 或 Core 请求超时 | `BRAINSTORM_MODEL_TIMEOUT` | 504 | 是 | 脑暴问题生成超时，已保留当前输入，请稍后重试 |

未知错误不显示原始内容；按 HTTP 429 / 503 / 504 分别归为繁忙 / 不可用 / 超时，其余统一归为输出无效。生成失败不得推进持久化版本或丢弃已保存的答案，重试使用原输入和原版本。输出无效或截断表示本轮自动恢复已耗尽，`retryable=false`，客户端不得继续自动重发；用户仍可保留原输入手动再试。超时和暂时不可用标为可重试，也不要求客户端自动重发或无限重试。

Sidecar 根据本轮任务生成结构化输出约束：待完成分支只能返回 question、换方向只能返回 ready，指定阶段与覆盖目标使用本轮枚举。内容长度、选项数、重复问题和来源有效性仍由后置校验负责，不能只改阶段标签或伪造选项绕过校验。历史参考之后重新明确当前分支和已答问题；质量恢复携带不合格候选的最小问题字段和累计校验原因，纠正后重新生成完整候选，不重复检索，不写入无效结果。短暂断流、模型超时、限流和暂时不可用在同一生成请求内退避重试，丢弃半截输出；鉴权、配置错误和取消不重试。质量与瞬时故障共用最多 3 次模型尝试，中间失败不会成为前端错误事件；只有恢复耗尽才返回稳定错误，禁止客户端叠加无限重发。

记忆核对共享 40 秒预算，API 自入队起（包含排队、核对、退避和有界重试）共享 150 秒截止；未获准运行的任务超时撤销，运行任务仅使用剩余预算并在截止时取消模型流，返回 `BRAINSTORM_MODEL_TIMEOUT`。Core 保留 180 秒请求上限，为本地传输和错误响应留出余量。记忆核对失败按未核对处理，不得将未知历史事实视为已确认；必要的提问生成失败仍须返回错误。

## 首题等待与诊断

创作历史中明确的 `conversation[].kind = session_end` 表示会话已永久终止；普通运行的 `lifecycle_status = cancelled` 或 `user_abort` 不表示会话终止，仍允许重试。已终止会话的脑暴启动与继续动作返回 `409 BRAINSTORM_SESSION_TERMINATED`，提示“当前会话已终止，请开启新会话”，不可重试。Core 在模型调用前检查终态，并在模型返回后与状态写入使用同一存储连接锁再次检查，防止迟到结果恢复或新建已终止会话。已保存 `phase = abandoned` 的会话只允许 `start` 读取已有快照或幂等 `abandon`；重复放弃不推进版本，其他动作不得重新打开会话。

Core 初始简报完全等于原始需求镜像时只做一次检索；任何人工增补、分支、答案或修订继续参与本轮召回。前端按已知请求状态展示匹配技能、保存会话、生成问题或恢复进度，并显示累计等待时长；不推测后台细分进度。启动与恢复使用可取消的请求，终止或切换会话后迟到响应不能覆盖新会话。

Sidecar 仅记录阶段、耗时、数量与异常类型；Core 记录经过校验的会话标识、动作、阶段及耗时，区分模型成功、输出校验、持久化完成与请求取消，不记录需求、来源正文或模型输出。

新生成问题尚未发布时，内容不同的选项若仅内部 ID 冲突，由 Sidecar 分配不与任何现有候选冲突的唯一 ID，不触发整题重生成。重复选项内容、无效证据或不完整输出仍走原有拒绝与有界重试，不改变已发布问题的 ID。

人工清空历史题摘要后，该决定不再算已覆盖，可重新询问；旧原始需求与历史记忆不能自动恢复被删除的决定。明确 `user_excluded` 的排除约束仍有效。人工修订摘要后不再依据该题原选中项调度分支，模型使用当前有效摘要继续讨论。通过 `reopen` 或 `revise_answer` 重新回答上游题时，该题及失效下游题的 `brief_edits` 一并清理，以新答案重新形成简报；原始需求和其他未失效字段的人工修订保留。

默认覆盖以目标产物为中心，使用目标与期望结果、面向对象与使用情境、内容结构与呈现方式、范围与现实约束、完成与成功标准五个中性决策面。沿用既有维度 ID 兼容历史会话，ID 中的业务或架构名称不代表当前任务领域；原始需求中的“设计/方案/功能/验收”等词不再触发技术门禁。专业维度只由用户已选且适用于当前目标的 Skill 实际决策步骤补充，写作、检索等执行步骤不机械变成问题；新的专业步骤 ID 绑定 Skill/步骤身份，可随回答保存和恢复。无 Skill 时仍需确认会改变成品主体的创作路线，不能只确认目标和受众就提前收敛。

换方向请求只接受 `ready` 与候选方向；模型返回问题时由 Sidecar 在原有有界重试内修正，不能将无效状态直接交给 Core。问题 `required` 与推荐元数据使用统一布尔值归一化，字符串 `"false"` 不得变成必答题。

## 生成正文的决策承接与暂停

“先生成一版”使用已保存的简报快照，不提交当前未确认选项，不推进问题或版本。生成正文后默认暂停问答，只在用户明确选择“继续脑暴”时恢复原题；恢复有正文的历史会话同样默认暂停。

正文输入、写作和验收共用有效决策：保留全部已确认回答，多选按已提交选项 ID 逐项承接标签及选项说明，不用最近 N 题替代全量决定。只从有效历史题恢复已选项，不采纳未选项、当前待答题、失效分支或选项资料依据。人工修改和清空优先于旧选择；禁止历史资料时沿用用户输入净化规则。完整的有效决定超过上下文容量时明确报错并保留输入，不静默裁掉决定后继续生成。

整篇生成时，每个有效用户选择由程序加入独立覆盖条件，写作及交付验收使用相同 ID 和内容。重复决定可在同段落实，但不能用标题提及或笼统“结构完整”替代实质覆盖；参数不能丢失或改写成待确认。假设、排除和未答项不变成必须写入的已确认事实。局部修改与只读回答继续遵守本轮范围，不强制重写全部脑暴内容。

方向和策略要展开执行步骤、输入、产物与验证方法；参数须保留适用对象和验证变量，经验与目标不能升级为实证。大量选择按每组最多 8 项审核；来源片段也按每批最多 8 组分开审核，每组恰好覆盖一次，通用验收条件只在首批执行。各批均读取完整正文与输入，汇总全部结果，不省略尾组，任何失败保留到聚合结果。数值证据校验检查审核理由声称采用的已选数值是否真的出现在正文中；它不能证明数值单位、归属或全部语义覆盖，歧义表达保持未知。

同一稳定维度、父题及探索层的早期通用跳过占位，若已有后续用户明确确认，在生成有效视图中标记为已被取代，不回灌带该旧占位的渲染简报；原始答案和具体未决假设保留。断点使用版本 3 有效视图重建并清除旧验收缓存，不修改冻结的用户输入。

明确整篇生成（包括基于已有草稿重新生成）有超过 8 项具体确认选择、且未采用专用 Skill 时，先规划章节归属，再逐章撰写。模型使用短别名分配章节，程序映射回稳定选择 ID；每项只有一个主归属，跨章引用不能替代主归属。每章最多 8 项，超量主题按原顺序拆章，总数最多 12 章；不能通过裁剪选择满足限额。每章携带完整的本章选择、其他全部确认选择的原文边界及章节目录；仅本章选择要求本章展开，其他章的已确认安排不得被推翻或改为未知。已完成章节随操作断点保存，完整正文按计划顺序确定性汇集后再做交付审核。

章节修正同时承接当前审核、作用域有效的独立问题记录和本轮正文质检意见，保留具体原文证据。不同位置的相同问题不能因原因相似而丢掉定位；当前仍失败的选择必须进入主归属章，即使其他章已改掉其旧引文，也要保留失败原因并标明旧定位已经变化，不能推定该选择已通过。一般历史问题和已通过项继续过滤，已删除的旧引用不广播到其他章。原稿、已选输入和检索权限保持原有边界。

章节失败不能跳过后宣称完成；恢复从失败章节重试。每次重写使用独立递增轮次，旧轮章节不能补齐新轮缺章。外部模型续跑只接受断点中已完成章节重组出的精确预览，任意正文改动仍触发基线变更检查。逐章预览不等于完整正文已通过验收。

## 横向调度与后台预生成

当前题成功持久化并返回后，Core 按同一广度优先队列准备其他已确认分支；当前题尚未回答时不猜测它的选择。后台候选仅存在有界、短期的进程内缓存，不推进 revision、历史、简报或当前题。下一次正常回答命中后才按原乐观锁提交问题。未命中或未完成时转前台生成；首题及用户作答快于生成时仍可能等待。

同层候选以准备时共同已确认上下文独立生成，兄弟方向普通选项回答不强制重生成候选；全部已保存回答继续进入后续轮次。Core 只复用 Sidecar 确认可复用的普通选项回答（`prefetch_safe_option_ids`，模型结果之后由程序按现有资料权限解析器计算，模型不得自行声明），旧 Sidecar 缺省不启用。任何自定义文本、资料范围指令、跳过/排除、人工修订、回改、换方向、结束或放弃均撤销缓存及在途工作。缓存键包含会话、模型配置、根需求、Skill、人工编辑、分支父子身份及祖先答案版本；模型配置变化或迟到结果不能串会话或复活旧分支。缓存命中只发布分支问题，不用旧全局摘要覆盖当前决定；同许可引用去重保留，人工编辑立即清理旧派生资料。与已答题题干明确相同的待决定项可移除，其他具体未知事实保守保留到后续完整上下文核对。

Core→Sidecar 请求新增可选 `prefetch: bool = false`。true 进入 P2 / p2_creation 可抢占通道，false 保持 P0 / p0_creation。预生成遭前台抢占返回 HTTP 503 与 `detail.code=INFERENCE_PREEMPTED`、`retryable=true`，Core 仅丢弃该候选，不把后台失败显示为用户当前题错误。断开请求必须取消排队及实际模型协程，保持原有 150 秒总预算。Core 每会话默认最多准备 4 个候选，可由 `MEMORYBREAD_BRAINSTORM_PREFETCH_LIMIT` 配置为 0～16；最多保留 8 个会话，缓存 10 分钟到期。按实际提问的遍历顺序选择预生成候选；独立请求并发启动，进入 Sidecar 队列及完成的先后顺序可以不同，最终发布仍由同一广度优先队列决定，并遵守本地推理槽限制。


## 同一已选方向的多题延展

Core→Sidecar 的 `question_batch_limit` 缺省 1；Core 对已确认分支的首题默认传 3，可通过 `MEMORYBREAD_BRAINSTORM_QUESTION_BATCH_LIMIT=1..8` 配置。这是本次方向展开的数量上限，不是固定题数。Sidecar 在生成首题的同一次模型调用中自主返回 `sibling_question_goals: string[]`（0 到上限减 1 项，每项最多 80 字符），规划同父选项、同阶段的互补问题。目标必须只依赖当前已确认路径，不能假设当前题或其他未回答题的答案；不需要额外延展时返回空数组。

后续独立出题请求通过 `extension_goal: string` 指定其中一个目标，`question_batch_limit=1`，响应不得继续产生目标。`sibling_question_context: string[]` 提供同父选项的已发布问题及其他未发布主题，仅用于排重和互补设计，绝不能当作用户答案；首题仍未回答时，后台也必须避开首题与其他并行主题。所有问题继续走现有规范化、原文引用校验、质量恢复和阶段校验。批量首题的内部模型结构使用 `question_plan: string[]`，在同一次推理中先规划包含当前题的 1～N 个同层主题，再生成第 1 个主题的问题；Sidecar 仅将第 2 项起的计划映射为公开 `sibling_question_goals`。这不是额外规划调用，旧模型直接返回兄弟目标的形式仍兼容。原始计划数组的结构和数量越界仍触发有界修复；可选目标与首题、历史题或同批主题明显重复时，只过滤未发布目标，保留合格首题。真正生成的延展题与同层题精确重复或仅轻微改写时须在原预算内重写；缓存发布也复查最新同分支题干。该文字守卫不声称能证明任意语义的完全独立性。旧 Sidecar 不返回目标时自然退化为单题。

Core 将目标保存在会话 JSON 的内部 `pending_extensions`，与父题、父选项、父答案版本关联；模型目标不是用户决定，不加入回答计数、简报、正文或历史答案。只有正常前台事务发布问题、消费目标。进程重启可按目标重新准备，后台完成不写入会话、不推进 revision。父决定修改、无效祖先、自定义补充、资料权限可能变化的选择、人工编辑、明确结束或方向切换使未发布目标失效；这些操作不删除已保存用户决定。

仍按广度优先遍历：先轮转同层已选方向的首题，再轮转各方向的后续互补题，完成该层后才讨论答案下的下一层。多个问题逐一呈现，每题单独由用户回答；同一选项可有多个直接子题，题目 ID 和父关联由 Core 管理。

后台按独立请求有界并发准备（`MEMORYBREAD_BRAINSTORM_PREFETCH_CONCURRENCY=1..8`，默认 3），总候选数仍由 `MEMORYBREAD_BRAINSTORM_PREFETCH_LIMIT` 控制。每个请求均进入 Sidecar 的 P2 调度；后台创作通道按实际后台容量允许并行，供电变化同步更新，显式通道限额保留。前台仍为 P0；模型容量大于 1 时为交互保留一个执行槽，单槽时遵守现有抢占规则，不绕过模型资源槽。本地模型只有一个执行槽时，实际推理仍会排队；并发准备利用用户作答时间减少题间等待，不承诺无条件同时推理或零等待。

独立延展请求将 `extension_goal` 接入已有 `next_question_goal` 生成目标，使用稳定的目标 ID 和本题主题约束输出结构，但不把它加入背景覆盖维度或用户决定。具体目标决定本题讨论什么，探索阶段只限制深度，祖先路径只提供背景；题干与选项仍须真实落实目标，不能事后改标签代替生成。

## 选项自主使用历史参考

召回资料只是可选候选，模型逐项自主选择 `memory_mode=original|reference`：可以整题原创、整题参考或混合，不按是否引用决定推荐权重，不要求为了引用而收窄思路。原创候选可以采用常识、新组合、反向思路或跨领域启发，`memory_ids` / `memory_evidence` 留空；它们是当前任务的建议，不代表历史事实。`reference` 必须附有效的真实来源，原有 ID 和原文核验保持不变。新生成 schema 先要求 `memory_mode` 再生成选项内容，省略字段的旧输出继续兼容。未附引用的详情使用中性说明，不从空引用推断已证明完全原创。资料访问权限仍由用户有效输入决定，模型不得扩大访问范围。
