# 创作细节输入澄清契约 v1

## 目的与顺序

创作细节阶段先核对影响交付事实的输入，再讨论版式或表达细节。已安装 Skill 的执行步骤是待获取资料的声明，不是资料已经取得的证明。准备题池时按步骤目标优先检索本机记忆，包括已采集的文档、知识、时间线和数据来源身份；不得先要求用户重新提供链接或截图。检索失败、权限跳过、没有命中、命中但时期或内容不完整，是不同状态。

当用户需求与已确认回答没有确定报告起止日，而选中 Skill 要求某一周期的事实时，先问报告周期。候选周期按设备本地日期生成，写明起止日，允许用户自定义；候选只供选择，绝不是默认答案。周期题须在普通细节题之前展示，且不能通过 `skip`/`exclude` 代答。回答后只使用用户选择的范围重新判定来源时期；采集日不能证明统计期。若用户自定义的时期仍不明确，继续澄清，不进入行文。

确定周期后，对每个仍未证实或只有部分证据的必需来源提出明确的资料确认题，附本地检索状态、来源身份与实际时期。资料已完整匹配时不再询问。用户明确确认候选来源、提供新定位或同意带缺口草稿，应作为不同答案保存；确认候选不能篡改原来源日期或把残缺正文当作完整资料。未提交的答案和推荐选项均不能成为事实、决策或交付授权。资料请求应限于确实缺少的部分，不能重新索取已从本机记忆取得的完整内容。

## 持久化与展现

- 在创作细节 `Stage` 保存 `input_preflight`：版本、冻结的设备本地日期、权限/检索状态、周期状态、逐项需求及有界来源收据。收据只包含可安全展示的来源身份、定位、采集时间、统计期和完整度；不写入原始页面正文、凭据或密钥。
- 澄清题使用现有 `BrainstormQuestion`，以 `input_clarification.kind` 和 `need_ids` 绑定输入需求；周期候选的 `BrainstormOption.input_value` 存 ISO 起止日和时区。页面不解析题干来推断字段或状态。
- 周期与资料答案仍保存在原会话的 `turns` 和用户决定中。状态恢复、改答和候选失效应只重算受影响的预检与未提交题，不清除其他已确认回答、已有正文、来源收据或历史草稿。
- 对用户展示 `matched`、`candidate`、`partial`、`missing`、`failed`、`skipped`；只有来源实际统计期覆盖目标期、所需正文/指标完整且身份可核对时才为 `matched`。`failed` 与 `skipped` 不得说成“无资料”。
- 必答澄清题未得到有效用户回答时，创作细节不能确认完成，后续行文和正式交付不得使用假定周期或把历史值写成目标期事实。
- 选择“标明缺口先成稿”后，行文交付只对该题绑定的资料需求放宽目标周期来源齐全要求；必须核对保存的用户答案、需求 ID 与确认周期完全一致。同一步骤若有多个独立资料需求，须逐项作出该选择。执行步骤、正文、确定性查询和其它未授权需求仍按原门禁验收。
- 带缺口成稿须在对应章节说明目标周期资料或指标待核实，将历史资料与本周事实分开，并保留确认的报告周期。交付收据以 `completed_with_gap` 标示授权缺口；不得把此状态报告为来源已匹配或完整周报事实。错误周期、未标注的本周断言仍进入修订，不以用户的缺口选择豁免。

## 验收

以原 GPU 成本优化周报会话回归：保留既有 17 项已确认回答及操作历史；在创作细节先出现未代选的周期题；本地记忆预检保留 9 月 22 日 AIGC 片段及实际时期、区分周会缺失、GPU/Token 单日数值与未知统计期；选定范围后仅对仍不明确的资料提问。确认前不得把旧资料判作本周完整来源，也不得标记交付完成。普通无周期任务、已有明确周期任务、权限失败、空召回、改答与恢复均须有回归。
