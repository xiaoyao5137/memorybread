# 本轮创作的输入与交付条件

本轮操作决定执行范围；资料是否足够决定检索依赖；交付检查决定是否需要修正。三者不由文档题材、历史根需求或工具是否启用互相替代。

## 操作边界

| 操作 | 输入检查 | 执行 | 交付检查 |
|---|---|---|---|
| patch | 不调用模型判断资料 | 定位、验证、原子补丁 | 精确范围与内容验证 |
| respond / resume / undo | 不重新研究 | 回应或指定历史操作 | 沿用对应操作契约 |
| transform / answer | 只检查本轮新增需求 | 必要检索后局部改写或回答 | 只检查本轮范围 |
| generate / execute_skill | 检查完整交付物的资料缺口 | 必要检索后写作或所选工作流 | 核对全部本轮交付条件 |

完整创作不等于必选全部工具。虚构写作、通用方法和资料齐备的整理可以不检索。局部追加涉及新事实时也可以检索，但不因此重走初稿工作流。

## 输入数据

`assess_creation_inputs` 使用结构化模型输出。按已注册来源分别判断 work_context（项目背景和过去决策）、business_data（经营指标与基线）、public_facts（公开事实与技术能力）。每类必须明确选择 provided（已提供）、missing（需获取）或 not_needed（不依赖），并给出依据；类别划分不代表强制执行。检查输入同时包含完整当前正文与材料行 ID，已有事实通过行 ID 绑定原文；状态字段先于需求理由生成，减少先虚构需求再解释检索的偏差。模型输出转换为运行时统一的输入数组，not_needed 不生成检索依赖。

运行时统一保存为 `input_contract`：交付物 `deliverable`、输入 `inputs`、资料自足原因 `self_contained_reason`、逐项验收条件 `acceptance`。资料判断成功后，`deliverable` 由本轮原指令绑定；模型提前拟出的草稿不能替代真实交付目标。写作只消费原请求、验收要求、用户显式设置及实际来源和回执，不把预检时的缺资料理由当作最新事实。输入包含唯一 ID、需求、来源、missing/provided 状态、逐字证据、查询与必要性理由。provided 必须匹配当前材料原文；missing 必须有可执行查询。无输入依赖时必须说明为何自足。最多 12 项输入和 12 项验收条件。

原模型选择保存在 `candidate_routing_decision`。`routing_decision.tools` 的标准检索能力根据缺失输入重算；其他能力保留原选择。每种来源只安排一次检索，查询由本轮缺口生成。工作流已有来源节点复用；缺少的必要来源节点安排在写作前。当前产品将基础检索工具定义为必备能力，未选择可选工具的校验仍然有效。

## 反馈、恢复与失败

`inputs.assessed` 记录输入条件和必要工具。执行节点携带 `input_requirement_ids`、`input_query` 和必要性理由。`input_receipts` 保存实际执行状态；工具报错必须停止，不能跳过后声称“没有资料”。空结果只表示没有命中，不能自动证明目标已满足。

`delivery.checked` 保存逐项检查，要求覆盖全部验收 ID，判为通过时必须选中最终正文的证据行 ID，由代码还原逐字片段，禁止使用自行改写的引用。provided_materials 保存可用输入，candidate_document_lines 保存待审正文，两者分开核验；正文漏写已有事实属于可修正问题。还会核对来源结果，不能把成功执行等同于证据充分。仅能用现有资料纠正的问题进入 revise；有待获取的关键证据不足进入 blocked。输入契约已确认自足时，未通过的产物须先提供具体修正，修正次数受 `MAX_DELIVERY_REPAIR_CYCLES` 限制。通过后不自动润色。修正未改变正文时停止无效重复；完整生成的重新成文可保留因旧误报被质疑的正确内容，并交原独立验收复核。达到预算仍不合格则停止。

完整生成的交付修正从原可信材料和原交付目标重新成文，沿用完整 Markdown 写作入口。失败问题单独提供，旧稿只提取标题和章节结构作为参考，不把整份失败稿作为必须保留的写作基线，也不将其升级为事实。请求冻结材料、原条件、失败问题和结构参考；Skill 已归一化的设计与语气约束继续保留。新稿经过原有空文、内容和标题治理，并由原独立验收核对实际写入的正文；不因旧润色保留规则回退正确的新稿。页面使用整稿替换预览，旧局部修改意图或 Skill 最终组装不能再覆盖已重新验收的完整稿。外部等待状态保存实际步骤及冻结输入，原有已发请求继续按其保存的协议处理。

修正所用 Skill 仅限本轮实际采用的规则：`applied_skills` 字段存在时包括空列表都按应用回执执行，否则依已有路由、准入、操作或显式选择记录收窄。不得因已采用列表为空而回退到整个候选目录；没有这些选择记录的旧调用继续兼容原显式 `selected_skills`。已采用规则沿用统一规范化和字段白名单，示例正文不成为事实材料。

局部变换仍绑定本轮原文和原选区，使用原有原子补丁；回答型修正只更新实际回答，不改用户文档。修正和审查共用可信材料，不把失败候选、作者解释或审查推理当作新事实。完整生成无需同时选择长段落目标和填写额外处置协议；这些未发布的实验路径已撤除。

本轮待核验问题随现有环境保存，绑定原指令、原文及原验收条件，保留同 ID 的不同失败原因。重新成文将其明确标为上次尝试的问题，不作为事实或取代原要求；独立验收的历史视图只含检查 ID、旧引文、当前是否仍存在及对应行号，不重复灌入旧判定和修正推理。完整原始记录仍保存在环境中。原材料可以推翻旧误报，历史引用是否仍逐字存在不自动决定通过或失败。整份交付通过后清除，新链不继承；动态日期检查或候选变化不重置当前链。旧断点仅在既有恢复绑定成功后迁移历史问题，允许旧引用因修正过时，正式交付仍严格核验当前正文。后处理新增问题时，发起模型修正前保存当前正文、问题及已用修正次数，失败或中止后可恢复。

共享模型入口按转换后的实际输出形式附加标题要求，先区分补丁、只读回答和查询输出，再处理 Skill 的显式全文角色、普通全文写作、完整重新成文和润色。文档身份元数据可以保留；“完整文档沿用标题”的指令仅用于确实输出完整正文的调用，不追加到补丁 JSON、回答、分析或 Skill 单章节。该判断在本地与外部模型分流前执行，已有标题治理仍保留。

局部修正的第二次补丁仍绑定本轮原始文档和原授权范围，最终只提交完整操作结果，避免节点 ID 在第一次修改后失效或范围扩张。最终格式、引用等守卫如改变已验收正文，必须重新核验实际落盘内容。检查与修正节点异常不得被普通节点容错吞掉。

合同、工具回执、审查报告和修正计数都随现有 `operation.checkpoint` 序列化，不新增另一个恢复通道。`run.completed` 附带最终审查与工具回执；失败沿用现有错误与断点通道，未通过验收不标记完成。

## 多轮材料与时间依据

输入检查、撰写和交付检查共用 `creation.input-context.v1` 快照，包含根需求、带角色和顺序的对话、已保存脑暴简报及 `user_options` 中的显式创作设置。对话超出 40 条时，入口与下游复用同一角色预算：最多保留 4 条近期助手消息，其余优先用户消息；用户消息也超限时保留根请求锚点及最近的用户消息。不能让大量助手解释提前挤掉中段用户更正，也不宣称无限保存所有旧约束。助手的建议不进入可选事实行，不能自证为真实资料。根需求只提供未被本轮取代的背景，不扩大局部修改范围。

验收保留与输入检查一致的 `supplied_lines` ID，避免验收条件引用 `brief-*` 时丢失原文。`candidate_document` 提供完整 Markdown，行 ID 仅负责证据定位；正常标签和值分行不构成内容缺失。人工清空的脑暴决定携带字段 ID 和维度，旧断点从结构化简报重建缓存，不能恢复被清空的旧值。

`candidate_metrics` 提供去除首个一级标题后的实测汉字数、非空白字符数和拉丁单词数，验收按用户要求的计数口径判断，不能凭行数估算字数或擅自加严“约”的范围。用户显式提供的受众属于可用来源；未指定时不从主题关键词或默认业务群体推断受众身份。任务画像、模型生成的交付描述、验收措辞和判断理由都不是独立事实来源。称谓暗示的身份、人员关系、组织归属和适用范围也需依据；普通邀请可以使用中性表达，明确提供的身份与允许虚构的设定仍可使用。

写作、内容修复和交付验收通过同一构造器加入三个独立条件：`source_scope_grounding` 检查身份及关系，`source_attributes_grounding` 检查属性和存在预设，`source_obligations_grounding` 检查额外流程及读者义务。验收仍在原调用中完成，兼容只有宽泛事实条件的旧契约，保留原有用户验收项；遇到 ID 冲突追加下划线生成唯一系统 ID。系统检查先选候选证据，再说明与原材料或授权的对应关系，最后分别判断通过；代码要求全部通过，一个维度通过不能抵消另一个维度失败，也不能被时间、数字或格式项通过所替代。“请、谢谢”等礼貌语气不指定身份，角色或关系称谓本身则包含事实，不能从会议等场景推断共同工作关系。泛指角色仍可能预设其存在和职责，事件性质、周期、额外流程及读者义务也需要来源或授权。中性邀请可以自然措辞；不能仅因要求成文就增加另一项办理流程。用户明确要求设计方案、拟定安排或虚构时，允许在该授权范围内构造内容；虚构故事无需对人物类型、地点、情节或拟人逐一取得许可，也不自行增加用户未要求的现实物理限制。漏报系统项与漏报用户项一样触发有界格式修复，仍不完整则停止验收，不自动补成通过。局部操作仍只审查本次变更内容。

正文应直接呈现用户所需作品；困难、解决办法和结尾等结构要求通过情节实现，不夹带验收标签和自评。

同一次验收调用先返回逐片段 `source_audit`，再返回 `checks`、`status` 和 `corrections`。内部 `checks` 以本轮实际验收 ID 为固定必填对象键，值仅含 `evidence/reason/passed`，不能自行生成另一份 ID 或重复同一检查。代码严格核对后，按原验收顺序还原公开的检查数组，原验收条件和公开三字段报告不变。重复 JSON 键、漏项和额外字段仍拒绝；旧已保存报告继续按公开数组格式校验。代码按标点和实际修改范围生成来源审计片段，超过 32 组时合并保留全部改动；不把未修改的间隔正文重新纳入审查。每组使用实际片段 ID 作为必填对象键，避免有界数组在本地解码约束中失去长度限制。每组须优先报告其中缺乏依据的含义，只有全部含义有依据或属于中性表达才可判通过。候选引用必须来自该组的一个连续原文片段。

内部解码同时绑定 `passed` 与证据行：通过只能选择实际非空正文行 ID，失败可以没有正文证据，空正文不提供通过分支。如果逐片段审计全部为正面，三个独立来源检查却有失败，则使用独立于格式修复的矛盾重审额度核对实际材料、补齐问题或纠正误报，不自动清除独立失败。如果已有真实负面片段，保留独立失败并进入内容修正，不为某一项非决定性的分类或引用定位再次生成整份报告，避免撤销已正确检出的错误。这只是审查结论的整体一致性检查，不证明每条语义或定位都准确。公开和历史报告的校验仍沿用原格式。

内部模型响应的 `corrections` 固定为空数组，由代码在验证审计与逐项检查后，从覆盖前及覆盖后的全部失败问题生成修正要求，避免模型重复生成建议时循环，或将一种无依据流程换成另一种。来源问题要求移除或中性改写未获依据的限定；其他失败项保留原验收条件、问题及正文定位。超过 12 条时合并保留全部条件，不截断遗漏。内部形状校验只允许暂未派生修正要求，不放宽覆盖、状态一致性或证据校验；对外仍使用严格的三字段报告，`revise` 必须带具体修正，`pass` 仍需全部检查通过。

来源目录仅包含用户输入、有效简报、原文及可用资料事实。模型从实际目录枚举中选择 `source_id`，由代码读取对应原文，避免将改写后的字符串冒充逐字引用；旧自由引用字段不接受。常规检查的 `evidence` 继续使用正文行 ID。模型先选候选及来源，再用简短 `meaning` 保留其中的实质限定，最后分别判断含义类别和来源支持；该解释不进入事实目录。`can_use=false`、过期或不可用资料、查询参数、采集元信息和工具回执不能作为正文事实依据。用户指令可以授权构造新方案或虚构故事，授权引用指向该用户要求，不要求虚构情节预先存在于材料中；原文及模型整理的简报不能独立提供新增创作授权。模型标为合理推断或没有依据的内容由代码强制对应检查失败，不能被后续总评通过覆盖。漏片段、重复 JSON 键、未知来源或有依据声明缺少来源进入既有两次格式校验上限；失败不能自动补成通过。来源存在不等于代码证明语义蕴含，仍需模型逐项判断并结合真实输出验收。

检索时间范围只用于选取材料，不能作为用户资料绝对日期的证明。资料已齐备的写作不注入执行时钟；占位符守卫仅处理未填写的周次且保持本周/上周标签对应，不改写已有数字。输出出现输入未提供的日期、周次或相对时间限定时，额外加入独立时间依据检查；允许等价日期表达、用户要求且有依据的换算、明确待确认的建议，以及用户允许的虚构情境，不允许擅自把“周三”收窄成“本周三”。

时间来源的代码核对使用实际候选 `text` 和所选目录原文，不使用可能漏掉限定的 `meaning`。常用日期格式仅按同值、同精度归一；代码守卫覆盖所选源无可识别日期依据，以及仅有裸星期却增加本/上/下周锚点的情况。未解析日期线索采取保守处理，复杂换算继续由原独立条件核验，不将词法匹配视为完整日期推导或语义支持证明。正确日期若选错来源，而别的真实来源含同值标签，准备通过时要求在原格式额度内重新核对引用；候选来源 ID 只是核对线索，不自动重绑定或证明属于同一事件。已有定位一致的真实失败可直接退回内容修正，不额外把非决定性的错源引用记作正确日期的正文错误。

恢复时同时核对会话、正文基线及本次提供的简报。可以接受原底稿或断点已保存结果，以兼容未提交的分步输出；不能把其他会话的断点或过期正文覆盖到当前文档。Core 发现根请求或简报变化时开启新的执行尝试，清除旧模型结果和检查点并重置事件序号；侧车对两类恢复也独立拒绝不一致的简报。缺省简报与显式空对象兼容，清空非空简报则视为变更。

错误码：

- `CREATION_INPUT_CONTRACT_INVALID`：资料条件不完整或证据声明无效；结构化解释最多重试一次。
- `CREATION_CAPABILITY_UNAVAILABLE`：必要能力不可用。
- `CREATION_EVIDENCE_UNAVAILABLE`：必要来源执行失败或没有成功回执。
- `CREATION_DELIVERY_UNVERIFIED`：验收输出不完整，或格式、覆盖、正文证据绑定无效；不代表正文被截断，不得标记验收通过。
- `CREATION_DELIVERY_INCOMPLETE`：关键资料不足或修正后仍不满足条件。

## 测试入口

验收与写作共用有界证据视图，保留来源、事实、时间、可用性及限制，不序列化原始 DOM/HTML 和完整历史快照。验收复用写作的数据和参考资料预算，保证同一来源覆盖，明确标注摘录与可用/展示条数；未展示片段不得被推断为不存在，完整证据仍留在原环境与断点中。

输入检查和交付验收共用完整候选缓冲与本地长度恢复机制：长度耗尽时丢弃整个候选，逐步增加预算，最高 16384 token，不拼接残缺 JSON。完整响应的格式校验最多重试一次；长度恢复耗尽后直接报告对应检查阶段的错误。恢复验收使用已保存的正文、条件和工具回执，不重复已完成的写作或检索。前端保存产物后仍展示具体失败原因。

- `ai-sidecar/tests/fixtures/creation_instruction_cases.json`：完整创作、简单操作、追加和混合指令的预期。
- `ai-sidecar/scripts/evaluate_creation_instructions.py`：真实本地模型路由与资料判断，不把计划视为执行证明。
- `ai-sidecar/scripts/evaluate_creation_delivery.py`：真实模型写作、局部追加与事实验收。
- `ai-sidecar/scripts/evaluate_creation_user_paths.py`：多轮更正、脑暴成文、表格、虚构、只读问答和局部改写。
- `ai-sidecar/scripts/evaluate_creation_memory_path.py`：隔离 SQLite 的生产检索与真实本地模型成文，记录来源回执并阻止访问用户数据库或其他网络端点。
- `ai-sidecar/tests/test_creation_context_contract.py`、`test_creation_resume_boundaries.py`：共享事实上下文、时间检查与 HTTP 恢复边界。
- `ai-sidecar/tests/test_creation_delivery_contract.py`：契约、执行顺序、失败、有限修正与保留范围。
- `ai-sidecar/tests/fixtures/creation_calendar_review_v21.json`、`creation_review_consistency_v22.json`：保留真实审查的原候选、材料、契约和回复，用 CPU 回放验证日期与审计一致性边界，不替代实际模型复测。
- 原有 operation、Core 原子提交/恢复/撤销与桌面事件测试继续覆盖既有行为。

外部资料测试使用受控测试材料，不覆盖私有资料召回质量和当前网页可用性；模型通过用例集也不是对任意自然语言的绝对正确性保证。

## 长文审核输入

较大的审核请求以保留空行和换行的逐行映射承载完整候选正文，不再额外重复整篇 Markdown。来源审查按每批最多 8 组直接展示待审核原文；每组恰好覆盖一次，不要求模型解读字符指针。保留原始行编号和完整来源，不用摘要代替长文或删除文末以适配模型窗口。无旧文的大篇幅初稿优先按完整行合并到有界审核组，局部修改继续只审查实际变动片段，不跨过未修改的旧文拼接引用。一般验收条件只在首个来源批次执行；后续逐项选择审核也读取完整正文。聚合时失败优先，保留各批失败理由与独立事实引用。

来源检查的失败证据在解码 schema 中仅枚举本批实际改动相交的非空行，排除其他批次及未改旧文；一般验收条件仍可引用全文。来源检查的失败引用须绑定模型所选行的准确字符范围，并与本批实际改动片段相交；分组保留原始 diff 区间，不从相同文字重新查找位置，其他位置出现相同文字不能替代所选位置。每批格式错误最多允许一次修复；合法的语义矛盾另允许一次完整重审，格式错误不消耗该额度。最多三次完整审核，两次完整、合法的审核若仍存在“片段审计全部正面、来源检查失败”的矛盾，只增加一次有界冲突复核。该复核保留全文、来源及明确的用户确认列表，逐条件输出单一结论；只有独立复核明确确认原判误报才可通过，确认无据则保留各处问题，无法判断仍拒绝交付。它不保证模型的全部语义判断正确。

冲突复核的来源证据使用 `source_ref`：代码按来源字段、原始行及最长 480 字符生成带位置的引用目录，模型只能选择目录 ID 或空值，不再自由输出来源 ID 与引文。代码从所选引用恢复原文和来源权限；重复文本靠原始位置区分，不跨字段或换行拼接。未知引用、有依据但无引用、非用户来源授权、时间限定不支持仍拒绝；uncertain 不允许直接通过交付；目录定位不替代语义支持判断。

冲突复核的自然语言理由及来源审计解释使用与公开验收检查一致的非空字符串契约，不因超过任意 240 字阈值而拒绝已绑定的证据；模型输出总量仍受既有调用预算限制。合法 `uncertain` 作为未通过的复核意见进入 `revise` 与既有修订流程，保留未核验状态，不将用户已确认事实当作错误，也不直接通过交付。真正的 JSON/字段/绑定错误最多单独修复一次，第二次仍无效则报告 `CREATION_DELIVERY_UNVERIFIED`；取消和传输错误不进入格式重试。

逐片段候选引用优先逐字绑定；失败后仅允许移除引文首尾呈现空白，再唯一恢复到同组一个连续原文片段。内部换行与事实字符仍须一致，不能借空白恢复跨过未修改的旧文或消除重复文本歧义。


来源审计的候选正文引用也由程序生成按片段归属的 `candidate-ref` 目录，实时模型仅选择该片段允许的 ID；程序恢复原始文字，拒绝跨片段 ID。旧记录的自由引文仍须逐字绑定，仅允许唯一定位时消除首尾空白，内部字符不能改写。

脑暴验收条件只从当前结构化简报、用户指令及有效修订建立，渲染简报里的历史参考不会因包含“已确认”字样变成本轮必选要求。旧断点恢复时重建这部分验收条件，保留原资料工作、用户正文和修订计数。小规模选择覆盖失败可进入逐项章节修订；方案按输入、执行、产物和验证结构生成建议，用户确认依据原样保留，叙事和事实报告保持连续正文。


实时整体状态使用 `checked` 标记，再由程序从逐项 `passed` 计算公开 `pass/revise`，必要资料缺口仍可返回 `blocked`；不得因冗余状态与逐项结果矛盾丢弃合法检查。旧公开报告的状态一致性校验保留。实时来源检查的通过、失败证据均限于本批改动原文，不能因选择批外行而被解码约束强制为通过。冲突复核结论采用主语明确的中文选项，解码为既有内部结论；引用、授权与时间依据校验不变。


对方案的来源义务审查区分用户已授权提出的执行建议与声称现实已存在的强制规则。覆盖核验可使用当前修订轮次、唯一绑定实际正文的选择所属章节行；只定位确认标签不能替代检查落实内容，章节映射不自动授予通过。


结构化方案的选择覆盖按与写作共享的输入、执行、产物、验证字段分别评估，并从各维度结果汇总；不能要求单个输入字段重复提供其他三个字段。任一维度不足仍不通过。未采用该结构的文档沿用完整正文覆盖核验。

有结构化脑暴状态时，审计完整使用当前决定的 `value/description/source` 与开放事项；旧渲染摘要保留为参考，不得覆盖当前确认状态。方案段落明确区分待核实资源、条件满足后的建议动作、预期产物及尚待验证的效果。常见带单位的新量化限定在章节保存前作有界检查，用户已给参数和可识别等值写法保留；不能以新设金额或数量门槛补定义未知业务等级。
