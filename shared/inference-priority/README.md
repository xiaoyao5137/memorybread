# 交互推理优先级与提炼抢占契约

2026-09-08：用户在线咨询与创作的模型工作必须统一为 P0，包括查询准备/改写、回答、技能匹配、脑暴历史核对和问题生成、正文/Agent 子步骤、修改/审阅/续写及局部创作。技能分析/审阅、创作聊天等用户触发的辅助调用同样遵循交互优先级。P1 时间线提炼、P2 批量提炼/合并/后台日记保持后台任务身份。

P0 到达时必须阻止新的后台推理占用共享模型槽，并通知正在运行的 P1/P2 让出资源。抢占应覆盖请求连接、等待响应头、输入预填充、流式输出和重试边界，不能等下一枚 token 或完整模型输出才检查。取消应终止实际模型传输，调用退出后才释放持有的槽，不能只取消外层 Future。不得通过重启/卸载整台模型服务、提高后台优先级或超配并行度实现抢占。

P0 相互不抢占，同级按现有 FIFO 与资源容量调度；排队、取消和超时必须释放交互需求标记，异常/进程退出不能留下永久阻塞后台的资源。嵌套模型调用保持同一交互任务身份，不重复申请自身持有的槽而死锁。不同进程使用相同的机器级仲裁和抢占通知。

复用创作 Agent 的调用通过 `execution_origin` 显式携带任务来源：省略时为 `interactive`，在线用户操作为 P0；定时调度器必须传 `scheduled_task`，使用 P2 后台创作通道。Core 校验并透传该字段，sidecar 决定优先级；不能根据会话名、提示词内容或所选模型推断。其他取值拒绝执行，避免错误来源悄悄提升优先级。该字段是本机调度契约，不是权限凭证。

被抢占的后台任务使用现有 `INFERENCE_PREEMPTED` 可恢复语义：候选生成结果不视为完整结果、不落入业务成功数据、不占用永久失败重试预算；让位期间可以等待，交互需求消失后按照后台调度策略恢复。用户取消、权限失败和输出截断继续使用各自错误类别。

诊断仅记录任务类别、阶段、优先级、队列等待/取消/释放耗时与安全调用标识，不记录提示词、回答、资料内容、凭据或供应商原始异常。性能验收必须区分本地模拟传输、跨进程资源让出和真实模型资源释放，不把“标记为 P0”当作已经抢占成功。


2026-09-10：脑暴未发布的同层问题使用现有 P2 后台创作通道。`p2_creation` 的缺省通道限额与实际后台容量一致：模型并行数为 1 时仍为 1；更高容量时最多使用总槽数减 1，保留最后一个槽供 P0 使用。供电变化时同步更新缺省通道限额，调用方显式设置的 `lane_limits` 保持有效。该调整不会修改模型实际并行配置，也不会越过跨进程模型槽或 P0 抢占门禁。多个独立后台问题在容量允许时可实际并行执行，容量不足时正常排队。
